# 4.4 — Factory Classes: Creación de Objetos No-Singleton

> **Objetivo**: Entender por qué Magento usa Factories para instanciar Models, cómo se generan automáticamente, cómo crearlas manualmente cuando necesitas lógica custom, y cuándo usarlas.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [4.3 — Argument Types Parte 2](4.3-argument-types-2.md)

---

## El problema que resuelven las Factories

En el DI de Magento, todo es singleton por defecto. Si inyectas `Post` en el constructor, siempre obtienes la misma instancia. Pero un Model como `Post` representa **un registro específico** — necesitas crear muchas instancias diferentes.

```php
// ❌ INCORRECTO — siempre la misma instancia, datos del post anterior
public function __construct(private readonly Post $post) {}

public function create(array $data): Post
{
    $this->post->setTitle($data['title']); // contamina la instancia compartida
    return $this->post;
}
```

```php
// ✅ CORRECTO — nueva instancia cada vez
public function __construct(private readonly PostFactory $postFactory) {}

public function create(array $data): Post
{
    $post = $this->postFactory->create();  // instancia nueva y limpia
    $post->setTitle($data['title']);
    return $post;
}
```

🔄 **Laravel**: En Laravel puedes hacer `new Post()` o `Post::create()`. En Magento **nunca uses `new`** — rompe el DI container (no se resuelven las dependencias del constructor). Siempre usa la Factory.

## Factories auto-generadas

Magento genera automáticamente una Factory para cada clase cuando corres `setup:di:compile`. Solo necesitas agregar `Factory` al nombre de la clase al inyectarla:

```php
// Clase: MiVendor\Blog\Model\Post
// Factory auto-generada: MiVendor\Blog\Model\PostFactory
// Ubicación generada: generated/code/MiVendor/Blog/Model/PostFactory.php

public function __construct(
    private readonly \MiVendor\Blog\Model\PostFactory $postFactory
) {}
```

Magento genera la Factory si:
1. La clase termina en `Factory` en el type hint
2. La clase base (`Post`) existe
3. Has corrido `setup:di:compile` (o estás en developer mode)

### El código generado

```php
// generated/code/MiVendor/Blog/Model/PostFactory.php
// (generado automáticamente — no lo edites)
namespace MiVendor\Blog\Model;

class PostFactory
{
    public function __construct(
        private readonly \Magento\Framework\ObjectManagerInterface $objectManager,
        private readonly string $instanceName = '\\MiVendor\\Blog\\Model\\Post'
    ) {}

    public function create(array $data = []): \MiVendor\Blog\Model\Post
    {
        return $this->objectManager->create($this->instanceName, $data);
    }
}
```

## Usar una Factory

```php
namespace MiVendor\Blog\Model;

class PostRepository
{
    public function __construct(
        private readonly PostFactory                          $postFactory,
        private readonly ResourceModel\Post                  $postResource,
        private readonly ResourceModel\Post\CollectionFactory $collectionFactory,
    ) {}

    // Crear un post nuevo
    public function create(array $data): Post
    {
        $post = $this->postFactory->create();
        $post->setData($data);
        $this->postResource->save($post);
        return $post;
    }

    // Cargar un post por ID
    public function getById(int $id): Post
    {
        $post = $this->postFactory->create();
        $this->postResource->load($post, $id);

        if (!$post->getId()) {
            throw new \Magento\Framework\Exception\NoSuchEntityException(
                __('Post with id "%1" does not exist.', $id)
            );
        }

        return $post;
    }

    // Obtener colección
    public function getList(): ResourceModel\Post\Collection
    {
        return $this->collectionFactory->create();
    }
}
```

## Pasar datos al crear con la Factory

```php
// create() acepta un array de datos que se pasan al constructor
$post = $this->postFactory->create([
    'data' => [
        'title'   => 'Mi Post',
        'content' => 'Contenido...',
        'status'  => Post::STATUS_DRAFT,
    ]
]);

// O más común — crear vacío y usar setters:
$post = $this->postFactory->create();
$post->setTitle('Mi Post');
$post->setContent('Contenido...');
$post->setStatus(Post::STATUS_DRAFT);
```

## CollectionFactory — para queries múltiples

Cada ResourceModel\Collection también tiene su Factory auto-generada:

```php
// Clase: MiVendor\Blog\Model\ResourceModel\Post\Collection
// Factory: MiVendor\Blog\Model\ResourceModel\Post\CollectionFactory

public function __construct(
    private readonly \MiVendor\Blog\Model\ResourceModel\Post\CollectionFactory $collectionFactory
) {}

public function getPublishedPosts(int $limit = 10): array
{
    $collection = $this->collectionFactory->create();
    $collection
        ->addFieldToFilter('status', Post::STATUS_PUBLISHED)
        ->addFieldToFilter('created_at', ['gteq' => date('Y-m-01')])
        ->setOrder('created_at', 'DESC')
        ->setPageSize($limit);

    return $collection->getItems();
}
```

## Factory custom — cuando necesitas lógica de creación

A veces necesitas lógica adicional al crear un objeto. Crea tu propia Factory:

```php
// app/code/MiVendor/Blog/Model/PostFactory.php
// ← NO se autogenera porque ya existe el archivo

namespace MiVendor\Blog\Model;

use Magento\Framework\ObjectManagerInterface;
use Magento\Store\Model\StoreManagerInterface;
use Psr\Log\LoggerInterface;

class PostFactory
{
    public function __construct(
        private readonly ObjectManagerInterface $objectManager,
        private readonly StoreManagerInterface  $storeManager,
        private readonly LoggerInterface        $logger,
    ) {}

    public function create(array $data = []): Post
    {
        // Lógica custom antes de crear
        $storeId = $this->storeManager->getStore()->getId();

        $data['store_id']   = $data['store_id'] ?? $storeId;
        $data['created_at'] = $data['created_at'] ?? date('Y-m-d H:i:s');
        $data['status']     = $data['status'] ?? Post::STATUS_DRAFT;

        $this->logger->debug('Creando post', ['store_id' => $data['store_id']]);

        return $this->objectManager->create(Post::class, ['data' => $data]);
    }

    public function createFromApiData(array $apiData): Post
    {
        // Transformar datos de API al formato interno
        return $this->create([
            'title'      => $apiData['headline'],
            'content'    => $apiData['body'],
            'author'     => $apiData['author']['name'],
            'api_id'     => $apiData['id'],
        ]);
    }
}
```

Si el archivo `PostFactory.php` existe en tu módulo, Magento usa el tuyo en lugar de generar uno automático.

## AbstractFactory — para familias de objetos

Cuando necesitas crear diferentes tipos de un mismo concepto:

```php
namespace MiVendor\Blog\Model;

use Magento\Framework\ObjectManagerInterface;

class PostTypeFactory
{
    private array $typeMap = [
        'article'  => Post\Article::class,
        'video'    => Post\Video::class,
        'gallery'  => Post\Gallery::class,
        'podcast'  => Post\Podcast::class,
    ];

    public function __construct(
        private readonly ObjectManagerInterface $objectManager
    ) {}

    public function create(string $type, array $data = []): PostInterface
    {
        if (!isset($this->typeMap[$type])) {
            throw new \InvalidArgumentException("Unknown post type: {$type}");
        }

        return $this->objectManager->create($this->typeMap[$type], ['data' => $data]);
    }
}
```

O mejor aún, hacer el mapa extensible vía DI:

```php
class PostTypeFactory
{
    /**
     * @param string[] $typeMap  Inyectado vía di.xml
     */
    public function __construct(
        private readonly ObjectManagerInterface $objectManager,
        private readonly array $typeMap = []
    ) {}
}
```

```xml
<type name="MiVendor\Blog\Model\PostTypeFactory">
    <arguments>
        <argument name="typeMap" xsi:type="array">
            <item name="article" xsi:type="string">MiVendor\Blog\Model\Post\Article</item>
            <item name="video"   xsi:type="string">MiVendor\Blog\Model\Post\Video</item>
        </argument>
    </arguments>
</type>
```

## Factories en Repositories — patrón completo

```php
namespace MiVendor\Blog\Model;

use MiVendor\Blog\Api\PostRepositoryInterface;
use MiVendor\Blog\Api\Data\PostInterface;
use MiVendor\Blog\Api\Data\PostSearchResultsInterfaceFactory;

class PostRepository implements PostRepositoryInterface
{
    public function __construct(
        private readonly PostFactory                        $postFactory,
        private readonly PostSearchResultsInterfaceFactory  $searchResultsFactory,
        private readonly ResourceModel\Post                 $resource,
        private readonly ResourceModel\Post\CollectionFactory $collectionFactory,
    ) {}

    public function getById(int $id): PostInterface
    {
        $post = $this->postFactory->create();
        $this->resource->load($post, $id);
        if (!$post->getId()) {
            throw new \Magento\Framework\Exception\NoSuchEntityException(
                __('Post "%1" does not exist.', $id)
            );
        }
        return $post;
    }

    public function save(PostInterface $post): PostInterface
    {
        $this->resource->save($post);
        return $post;
    }

    public function delete(PostInterface $post): bool
    {
        $this->resource->delete($post);
        return true;
    }

    public function getList(\Magento\Framework\Api\SearchCriteriaInterface $criteria)
    {
        $collection = $this->collectionFactory->create();
        // aplicar criterios de búsqueda...

        $results = $this->searchResultsFactory->create();
        $results->setItems($collection->getItems());
        $results->setTotalCount($collection->getSize());
        return $results;
    }
}
```

## Reglas de cuándo usar Factory

```
¿Necesitas más de una instancia del objeto?      → Factory
¿El objeto representa un registro de DB?         → Factory
¿El objeto guarda estado mutable por request?    → Factory
¿Es un Service/Repository/Helper sin estado?     → Inyección directa (singleton)
¿Necesitas lógica custom al crear?               → Factory custom en tu módulo
¿Creas objetos de diferentes tipos en runtime?   → AbstractFactory con typeMap
```

---

## Resumen

```
PostFactory             →  genera Magento automáticamente con setup:di:compile
$factory->create()      →  nueva instancia limpia del ObjectManager
$factory->create($data) →  nueva instancia con datos iniciales
CollectionFactory       →  también auto-generada para cada Collection

NUNCA:  new Post()             ← rompe el DI
NUNCA:  $objectManager->get()  ← singleton, datos compartidos
SIEMPRE: $this->postFactory->create()
```

## Ejercicios

### Ejercicio 1 — Usar Factory correctamente

Dado este código incorrecto, identifica el problema y corrígelo usando Factory:

```php
// ❌ Código con problema
class PostService
{
    public function __construct(private readonly Post $post) {}

    public function createDraft(string $title, string $content): Post
    {
        $this->post->setTitle($title);
        $this->post->setContent($content);
        $this->post->setStatus('draft');
        return $this->post;
    }
}
```

<details>
<summary>Ver solución</summary>

**Problema**: `Post` es singleton — todas las llamadas a `createDraft()` modifican la misma instancia, mezclando datos entre posts.

```php
// ✅ Corrección con Factory
class PostService
{
    public function __construct(
        private readonly PostFactory $postFactory  // ← Factory, no la clase directa
    ) {}

    public function createDraft(string $title, string $content): Post
    {
        $post = $this->postFactory->create(); // nueva instancia limpia cada vez
        $post->setTitle($title);
        $post->setContent($content);
        $post->setStatus('draft');
        return $post;
    }
}
```

```bash
# Verificar que la Factory se genera correctamente:
php bin/magento setup:di:compile
ls generated/code/MiVendor/Blog/Model/PostFactory.php
```

</details>

### Ejercicio 2 — Factory custom con lógica de inicialización

Crea una `PostFactory` custom que automáticamente asigne:
- `created_at` con la fecha actual si no se proporciona
- `status` como `draft` si no se proporciona
- `store_id` con el store actual si no se proporciona

<details>
<summary>Ver solución</summary>

```php
// Model/PostFactory.php
// Al existir este archivo, Magento NO genera el automático
namespace MiVendor\Blog\Model;

use Magento\Framework\ObjectManagerInterface;
use Magento\Store\Model\StoreManagerInterface;

class PostFactory
{
    public function __construct(
        private readonly ObjectManagerInterface $objectManager,
        private readonly StoreManagerInterface  $storeManager,
    ) {}

    public function create(array $data = []): Post
    {
        $data['created_at'] = $data['created_at'] ?? date('Y-m-d H:i:s');
        $data['status']     = $data['status'] ?? Post::STATUS_DRAFT;
        $data['store_id']   = $data['store_id']
            ?? (int) $this->storeManager->getStore()->getId();

        return $this->objectManager->create(Post::class, ['data' => $data]);
    }
}
```

```php
// Uso — los valores por defecto se aplican automáticamente:
$post = $this->postFactory->create(['title' => 'Mi Post']);
// $post->getCreatedAt() → fecha actual
// $post->getStatus()    → 'draft'
// $post->getStoreId()   → id del store actual

// O con valores custom que sobreescriben los defaults:
$post = $this->postFactory->create([
    'title'  => 'Post Publicado',
    'status' => Post::STATUS_PUBLISHED,
]);
```

</details>
