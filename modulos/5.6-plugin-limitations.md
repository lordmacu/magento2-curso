# 5.6 — Limitaciones de Plugins: Qué NO Se Puede Interceptar

> **Objetivo**: Conocer exactamente qué métodos y clases no pueden ser interceptados por Plugins, entender por qué, y saber qué alternativas usar en cada caso.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [5.5 — Plugin Sort Order](5.5-plugin-sort-order.md)

---

## Métodos que NO se pueden interceptar

### 1. Métodos `private`

```php
class ProductRepository
{
    // ❌ No interceptable
    private function validateProduct(ProductInterface $product): void
    {
        // lógica interna
    }

    // ✅ Interceptable
    public function save(ProductInterface $product): ProductInterface
    {
        $this->validateProduct($product); // llama al private internamente
        // ...
    }
}
```

**Por qué**: PHP no permite sobreescribir métodos `private` — el Interceptor generado extiende la clase pero no puede acceder ni sobreescribir métodos privados.

**Alternativa**: Intercepta el método público que llama al privado (`save` en este caso).

---

### 2. Métodos `protected`

```php
class AbstractModel
{
    // ❌ No interceptable
    protected function _beforeSave(): void {}
    protected function _afterSave(): void {}
}
```

**Por qué**: Aunque técnicamente heredables, Magento excluye los `protected` del sistema de plugins por diseño — son considerados implementación interna.

**Alternativa**: Intercepta el método público que los llama, o usa un Observer del evento correspondiente.

---

### 3. Métodos `static`

```php
class ObjectManager
{
    // ❌ No interceptable
    public static function getInstance(): self
    {
        return self::$instance;
    }
}
```

**Por qué**: Los métodos estáticos pertenecen a la clase, no a la instancia. El Interceptor trabaja a nivel de instancia.

**Alternativa**: Si necesitas modificar comportamiento estático, considera refactorizar a un método de instancia o usar un Observer.

---

### 4. Métodos `final`

```php
class Interceptor
{
    // ❌ No interceptable — final impide sobreescritura
    final public function ___callPlugins(string $method, array $args, array $pluginInfo): mixed
    {
        // ...
    }
}
```

**Por qué**: PHP no permite sobreescribir métodos `final` — el Interceptor no puede hacerlo.

**Búsqueda rápida de métodos final en el core**:

```bash
grep -r "final public function" vendor/magento/framework/ --include="*.php" | head -10
```

**Alternativa**: Intercepta otro método público no-final de la misma clase, o usa Preference (con cuidado).

---

### 5. El constructor `__construct`

```php
class Product
{
    // ❌ No interceptable
    public function __construct(
        private readonly ResourceModel $resource,
        // ...
    ) {}
}
```

**Por qué**: Los constructores se ejecutan durante la instanciación, antes de que el Interceptor pueda envolver nada.

**Alternativa**:
- Usa el evento `_afterConstruct()` si la clase lo dispara
- Usa un Observer de evento de inicialización
- Usa un Plugin en el primer método que se llama después de la construcción

---

### 6. Clases `final`

```php
// ❌ Toda la clase es no-interceptable
final class SomeUtility
{
    public function doSomething(): void {}
}
```

**Por qué**: El Interceptor necesita extender la clase — no puede extender una clase `final`.

**Alternativa**: Preference (si la clase implementa una interfaz) o refactorización.

---

### 7. Clases que implementan `NoninterceptableInterface`

```php
// ❌ Magento marca estas clases explícitamente como no-interceptables
class SomeClass implements \Magento\Framework\ObjectManager\NoninterceptableInterface
{
    public function someMethod(): void {}
}
```

**Por qué**: Esta interfaz es un marcador que le dice al compilador DI que no genere un Interceptor para esta clase. Los propios Interceptors y Proxies generados la implementan para evitar interceptación infinita.

---

## Cómo saber si un método es interceptable

```bash
# Verificar si una clase tiene Interceptor generado
ls generated/code/Magento/Catalog/Model/Product/
# Si existe Interceptor.php → los métodos públicos son interceptables

# Si NO hay Interceptor.php → la clase no puede ser interceptada
# (es final, implementa NoninterceptableInterface, o no tiene plugins registrados)

# Buscar métodos final en una clase específica
grep "final public\|final protected" vendor/magento/module-catalog/Model/Product.php
```

---

## Tabla de resumen

| Tipo de método/clase | ¿Interceptable? | Alternativa |
|---|---|---|
| `public function` | ✅ Sí | — |
| `protected function` | ❌ No | Observer, interceptar método público que lo llama |
| `private function` | ❌ No | Interceptar el método público que lo llama |
| `public static function` | ❌ No | Observer, refactorizar |
| `final public function` | ❌ No | Preference (cuidado), otro método |
| `__construct` | ❌ No | Observer de inicialización |
| Clase `final` | ❌ No | Preference si tiene interfaz |
| `NoninterceptableInterface` | ❌ No | No hay — es intencional |

## Errores comunes al intentar interceptar lo no-interceptable

### Plugin registrado pero nunca se ejecuta

```bash
# Síntoma: registraste el plugin en di.xml pero no se dispara
# Causa más común: el método es protected o private

# Verificar:
php bin/magento dev:di:info "Vendor\Clase"
# Si el plugin no aparece en la lista → el método no es interceptable

# También verificar:
grep "protected\|private\|final\|static" vendor/.../MiClase.php | grep "function miMetodo"
```

### Error en setup:di:compile

```
[ERROR] Magento\Framework\Exception\RuntimeException:
  Can't generate Interceptor for Magento\SomeModule\Model\SomeFinalClass
  because it's marked as final
```

**Solución**: No pongas un plugin sobre esa clase. Usa una alternativa.

---

## Estrategias alternativas cuando no puedes usar Plugin

### Caso: necesitas interceptar un método protected

```php
// El método protected que quieres interceptar:
protected function _beforeSave(): AbstractModel

// Alternativa 1: Observer del evento que dispara _beforeSave
// events.xml:
// <event name="model_save_before">
//     <observer name="mi_observer" instance="Mi\Observer"/>
// </event>

// Alternativa 2: Interceptar el método público save() que llama a _beforeSave()
public function beforeSave(AbstractModel $subject): ?array
{
    // tu lógica aquí, antes de que save() llame a _beforeSave()
    return null;
}
```

### Caso: necesitas interceptar un método static

```php
// Alternativa: si hay un método de instancia equivalente, úsalo
// Si no, considera usar un Observer o crear un wrapper no-estático

// Wrapper de instancia que delega al static:
class MyWrapper
{
    public function getInstance(): ObjectManager
    {
        return ObjectManager::getInstance(); // llama al static internamente
    }
}
// Ahora puedes interceptar MyWrapper::getInstance()
```

---

## Resumen

```
NO interceptable:
  private, protected, static, final methods
  __construct
  Clases final
  Clases con NoninterceptableInterface

Para diagnosticar:
  php bin/magento dev:di:info "Vendor\Clase"
  grep "final\|static\|private\|protected" ClaseTarget.php | grep "function metodo"

Alternativas:
  Observer → para reaccionar a eventos del ciclo de vida
  Interceptar el método público padre → cuando el target es protected/private
  Preference → último recurso para clases final con interfaz
```
