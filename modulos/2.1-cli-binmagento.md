## El equivalente a `php artisan`

🔄 **Laravel**: `php artisan` es la navaja suiza de Laravel. En Magento es `php bin/magento` — misma filosofía, pero con muchos más comandos y más impacto cuando los usas mal.

```bash
# Laravel
php artisan list

# Magento
php bin/magento list

# En tu Docker:
docker exec magento_app php /var/www/html/bin/magento list
```

Para no escribir la ruta completa todo el tiempo, conviene crear un alias:

```bash
# Agrega esto a tu ~/.zshrc o ~/.bashrc
alias mage='docker exec magento_app php /var/www/html/bin/magento'

# Luego puedes hacer:
mage cache:flush
mage setup:upgrade
mage deploy:mode:show
```

## Los grupos de comandos

```
setup:*         → Instalación, migraciones, compilación
cache:*         → Gestión del caché (los más usados)
indexer:*       → Reindexación del catálogo
module:*        → Habilitar/deshabilitar módulos
deploy:*        → Modos y assets estáticos
cron:*          → Gestión de cron jobs
maintenance:*   → Modo mantenimiento
store:*         → Info de stores
config:*        → Leer/escribir configuración
catalog:*       → Operaciones del catálogo
queue:*         → Message queues
i18n:*          → Internacionalización
dev:*           → Herramientas de desarrollo
```

## Grupo 1: Cache — los que más usarás

```bash
# Limpiar TODO el caché (lo harás 50 veces al día)
php bin/magento cache:flush

# Limpiar solo tipos específicos (más quirúrgico)
php bin/magento cache:clean config
php bin/magento cache:clean layout
php bin/magento cache:clean block_html
php bin/magento cache:clean full_page
php bin/magento cache:clean collections
php bin/magento cache:clean translate

# Ver estado de cada tipo
php bin/magento cache:status

# Deshabilitar tipos (útil en desarrollo)
php bin/magento cache:disable full_page block_html
php bin/magento cache:enable full_page block_html
```

### ¿`cache:flush` o `cache:clean`?

```
cache:clean  → Invalida las entradas del caché (marca como expiradas)
               El storage sigue ocupando espacio hasta que se sobrescriba

cache:flush  → Vacía completamente el storage del caché
               Más lento pero más definitivo

En desarrollo: usa cache:flush siempre.
En producción: cache:clean es más seguro para no generar picos de carga.
```

💡 **TIP**: Si cambias código PHP y no ves el cambio, haz `cache:flush`. Si cambias un XML de configuración (`di.xml`, `events.xml`, `routes.xml`) y no aplica, haz `setup:upgrade` + `cache:flush`.

## Grupo 2: Setup — los más críticos

```bash
# Aplica migraciones de schema y datos de TODOS los módulos
# Úsalo cuando: habilitas un módulo nuevo, cambias db_schema.xml, corres patches
php bin/magento setup:upgrade

# Compila el DI container (Factories, Proxies, Interceptors)
# Úsalo cuando: cambias di.xml en producción, o cuando hay errores raros de DI
php bin/magento setup:di:compile

# Despliega assets estáticos (CSS, JS, imágenes de tema)
# Solo en producción — en development se generan automáticamente
php bin/magento setup:static-content:deploy es_MX en_US -f

# Ver la versión instalada de Magento
php bin/magento setup:db:status

# Instalar Magento (solo al inicio, ya lo vimos)
php bin/magento setup:install [opciones...]
```

### El orden correcto en deploy

```bash
# SIEMPRE en este orden — nunca al revés:
php bin/magento setup:upgrade          # 1. primero schema/datos
php bin/magento setup:di:compile       # 2. luego compilar DI
php bin/magento setup:static-content:deploy -f  # 3. assets al final
php bin/magento cache:flush            # 4. limpiar caché
```

⚠️ **Error clásico**: Correr `setup:di:compile` antes de `setup:upgrade`. Si hay nuevas tablas o configuraciones que el código compilado necesita y aún no existen, el compile falla o genera código incorrecto.

## Grupo 3: Indexer — el catálogo siempre al día

Los indexers pre-computan datos para performance (precios, búsqueda, URL, stock):

```bash
# Ver estado de todos los indexers
php bin/magento indexer:status

# Reindexar TODO (tarda varios minutos en catálogos grandes)
php bin/magento indexer:reindex

# Reindexar solo los que necesitas
php bin/magento indexer:reindex catalog_product_price
php bin/magento indexer:reindex catalogsearch_fulltext
php bin/magento indexer:reindex catalog_product_flat
php bin/magento indexer:reindex catalog_category_flat
php bin/magento indexer:reindex cataloginventory_stock
php bin/magento indexer:reindex catalog_url_rewrite

# Ver el modo de cada indexer (realtime vs schedule)
php bin/magento indexer:show-mode

# Cambiar a modo "schedule" (se reindexan via cron, mejor para producción)
php bin/magento indexer:set-mode schedule catalog_product_price

# Cambiar a modo "realtime" (se reindexan al guardar, mejor para desarrollo)
php bin/magento indexer:set-mode realtime catalog_product_price
```

### Los indexers más importantes

| Indexer | Qué pre-computa |
|---|---|
| `catalog_product_price` | Precios finales de productos |
| `catalogsearch_fulltext` | Índice de búsqueda en Elasticsearch |
| `catalog_product_flat` | Tabla plana de productos (performance) |
| `catalog_url_rewrite` | URLs amigables de productos y categorías |
| `cataloginventory_stock` | Estado de stock |
| `customer_grid` | Grid de clientes en el admin |

💡 **TIP**: Si ves un producto con precio 0, stock incorrecto o que no aparece en la búsqueda, lo primero que haces es `indexer:reindex` del indexer correspondiente.

## Grupo 4: Module — gestión de módulos

```bash
# Ver todos los módulos y su estado
php bin/magento module:status

# Habilitar un módulo
php bin/magento module:enable MiVendor_MiModulo
php bin/magento setup:upgrade   # siempre después de habilitar

# Deshabilitar un módulo
php bin/magento module:disable MiVendor_MiModulo
php bin/magento setup:upgrade

# Ver solo los módulos deshabilitados
php bin/magento module:status --disabled

# Ver solo los habilitados
php bin/magento module:status --enabled
```

## Grupo 5: Deploy — modos y assets

```bash
# Ver el modo actual
php bin/magento deploy:mode:show

# Cambiar a modo developer (tu entorno de trabajo)
php bin/magento deploy:mode:set developer

# Cambiar a modo producción
php bin/magento deploy:mode:set production

# Desplegar assets para locales específicos
php bin/magento setup:static-content:deploy es_MX en_US

# Desplegar assets para un tema específico
php bin/magento setup:static-content:deploy es_MX -t Magento/luma

# Forzar re-deploy aunque ya estén desplegados
php bin/magento setup:static-content:deploy -f

# En paralelo (mucho más rápido en catálogos grandes)
php bin/magento setup:static-content:deploy -j 4
```

## Grupo 6: Maintenance — modo mantenimiento

```bash
# Activar — muestra página de mantenimiento a todos
php bin/magento maintenance:enable

# Desactivar
php bin/magento maintenance:disable

# Activar pero permitir IPs específicas (para revisar antes de abrir)
php bin/magento maintenance:enable --ip=192.168.1.100 --ip=10.0.0.1

# Ver estado
php bin/magento maintenance:status
```

## Grupo 7: Config — leer y escribir configuración

```bash
# Leer un valor de configuración
php bin/magento config:show web/unsecure/base_url
php bin/magento config:show catalog/frontend/grid_per_page

# Escribir un valor (a nivel global por defecto)
php bin/magento config:set web/unsecure/base_url "http://localhost:8181/"

# Escribir para un scope específico
php bin/magento config:set --scope=website --scope-code=base \
    catalog/frontend/grid_per_page 24

# Escribir valor encriptado
php bin/magento config:set --lock-env payment/paypal/api_key "mi-api-key"
```

## Grupo 8: Cron — tareas programadas

```bash
# Correr todos los cron jobs pendientes (simula lo que hace el sistema)
php bin/magento cron:run

# Correr solo un grupo específico
php bin/magento cron:run --group=default
php bin/magento cron:run --group=index

# Ver los cron jobs registrados
php bin/magento cron:status

# Instalar los cron jobs en el sistema (en producción)
php bin/magento cron:install
```

## Grupo 9: Herramientas de desarrollo

```bash
# Convertir un template/block a un ViewModel (análisis)
php bin/magento dev:template-hints:enable   # muestra paths de templates en frontend
php bin/magento dev:template-hints:disable

# Generar un reporte de URIs de la app
php bin/magento dev:query-log:enable        # loguea todas las queries SQL
php bin/magento dev:query-log:disable

# Generar código DI sin compilar todo
php bin/magento dev:di:info "Magento\Catalog\Model\Product"
# Muestra qué se inyecta en el constructor de Product
```

### `dev:di:info` — el más útil para debuggear DI

```bash
php bin/magento dev:di:info "Magento\Catalog\Api\ProductRepositoryInterface"

# Output:
# DI configuration for the class Magento\Catalog\Api\ProductRepositoryInterface
# Preference: Magento\Catalog\Model\ProductRepository
# Constructor Parameters:
#   productFactory       Magento\Catalog\Model\ProductFactory       (object)
#   collectionFactory    ...ProductCollection\Factory                (object)
#   ...
```

## Grupo 10: i18n — traducciones

```bash
# Recolectar frases traducibles de todo el código
php bin/magento i18n:collect-phrases --output="var/phrases.csv" app/code/MiVendor/

# Crear un paquete de idioma
php bin/magento i18n:pack es_MX.csv --locale es_MX
```

## Comandos de emergencia — cuando algo está muy mal

```bash
# La tienda está en blanco y no sabes qué pasa
tail -f var/log/exception.log   # primero esto

# Regenerar todo desde cero (nuclear option)
rm -rf generated/ var/cache/ var/page_cache/ var/view_preprocessed/ pub/static/frontend/
php bin/magento setup:upgrade
php bin/magento setup:di:compile
php bin/magento setup:static-content:deploy -f
php bin/magento cache:flush

# Errores de "Class X does not exist" en generated/
rm -rf generated/code/ generated/metadata/
php bin/magento setup:di:compile
php bin/magento cache:flush

# La sesión del admin no funciona
php bin/magento cache:flush
# Si persiste: vacía var/session/

# Olvidaste la contraseña del admin
php bin/magento admin:user:create \
    --admin-user=admin2 \
    --admin-password=Admin123! \
    --admin-email=admin2@example.com \
    --admin-firstname=Admin \
    --admin-lastname=User
```

## Referencia rápida — cheat sheet

```bash
# ─── CACHÉ ────────────────────────────────────────────
cache:flush                     # Limpiar todo (lo más usado)
cache:status                    # Ver estado
cache:disable full_page         # Deshabilitar FPC en dev

# ─── MÓDULOS ──────────────────────────────────────────
module:enable Vendor_Module     # Habilitar módulo
module:status                   # Ver todos los módulos

# ─── SETUP ────────────────────────────────────────────
setup:upgrade                   # Aplicar migraciones
setup:di:compile                # Compilar DI (producción)
setup:static-content:deploy -f  # Desplegar assets

# ─── INDEXERS ─────────────────────────────────────────
indexer:status                  # Ver estado
indexer:reindex                 # Reindexar todo

# ─── MODO ─────────────────────────────────────────────
deploy:mode:show                # Ver modo actual
deploy:mode:set developer       # Modo desarrollo
deploy:mode:set production      # Modo producción

# ─── DEBUG ────────────────────────────────────────────
dev:di:info "Vendor\Class"      # Ver DI de una clase
dev:template-hints:enable       # Ver paths de templates
```
