## Por qué necesitas declarar tipos explícitamente

El ObjectManager resuelve dependencias de objeto automáticamente por el type hint del constructor. Pero para valores primitivos (strings, ints, booleans) y para elegir una implementación concreta específica, necesitas decírselo explícitamente en `di.xml`.

```php
public function __construct(
    private readonly LoggerInterface $logger,   // ← resuelto automáticamente
    private readonly string $apiKey,            // ← ¿de dónde viene este string?
    private readonly bool $debugMode,           // ← ¿cómo sabe Magento el valor?
) {}
```

Para los primitivos, Magento no puede adivinar el valor — necesita el `di.xml`.

## Tipo: `object`

Inyecta una instancia de una clase. El ObjectManager la construye (respetando su propio DI).

```xml
<type name="MiVendor\Blog\Model\PostService">
    <arguments>
        <argument name="cache" xsi:type="object">
            Magento\Framework\Cache\Frontend\Decorator\Logger
        </argument>
    </arguments>
</type>
```

```php
public function __construct(
    private readonly \Magento\Framework\Cache\Frontend\Decorator\Logger $cache
) {}
```

### Objeto shared vs non-shared

```xml
<!-- Singleton (default) — misma instancia -->
<argument name="cache" xsi:type="object">Magento\Framework\Cache\Type\Config</argument>

<!-- Nueva instancia cada vez -->
<argument name="cache" xsi:type="object">Magento\Framework\Cache\Type\Config\Proxy</argument>

<!-- Forzar non-shared explícitamente -->
<argument name="post" xsi:type="object" shared="false">MiVendor\Blog\Model\Post</argument>
```

### Casos de uso comunes para `object`

```xml
<!-- Inyectar un logger específico en lugar del genérico -->
<type name="MiVendor\Blog\Model\PostService">
    <arguments>
        <argument name="logger" xsi:type="object">MiVendor\Blog\Logger\Logger</argument>
    </arguments>
</type>

<!-- Inyectar una implementación concreta de una interfaz (alternativa a preference) -->
<type name="MiVendor\Blog\Controller\Post\View">
    <arguments>
        <argument name="postRepository" xsi:type="object">
            MiVendor\Blog\Model\CachedPostRepository
        </argument>
    </arguments>
</type>
```

**Diferencia con `<preference>`**:
- `<preference>` aplica a **toda la aplicación** — cualquier clase que pida esa interfaz recibe esa implementación
- `<argument xsi:type="object">` aplica **solo a esa clase específica** — más quirúrgico

## Tipo: `string`

```xml
<type name="MiVendor\Blog\Model\ApiClient">
    <arguments>
        <argument name="baseUrl"   xsi:type="string">https://api.ejemplo.com/v2</argument>
        <argument name="userAgent" xsi:type="string">MagentoBlog/1.0</argument>
        <argument name="version"   xsi:type="string">2.0</argument>
    </arguments>
</type>
```

```php
public function __construct(
    private readonly string $baseUrl,    // "https://api.ejemplo.com/v2"
    private readonly string $userAgent,  // "MagentoBlog/1.0"
    private readonly string $version,    // "2.0"
) {}
```

### String vacío y string con espacios

```xml
<!-- String vacío -->
<argument name="prefix" xsi:type="string"></argument>
<argument name="prefix" xsi:type="string"/>

<!-- String con espacios — el XML los preserva -->
<argument name="separator" xsi:type="string"> | </argument>
```

### Usar constantes PHP como string

```xml
<!-- Referenciar una constante de clase -->
<argument name="cacheType" xsi:type="const">
    Magento\Framework\App\Cache\Type\Config::TYPE_IDENTIFIER
</argument>
```

Nota: `const` es técnicamente un tipo separado, pero su resultado es siempre un string/int. Lo veremos más en [4.3](4.3-argument-types-2.md).

## Tipo: `boolean`

```xml
<type name="MiVendor\Blog\Model\PostService">
    <arguments>
        <argument name="debugMode"    xsi:type="boolean">false</argument>
        <argument name="cacheEnabled" xsi:type="boolean">true</argument>
        <argument name="strictMode"   xsi:type="boolean">false</argument>
    </arguments>
</type>
```

```php
public function __construct(
    private readonly bool $debugMode,     // false
    private readonly bool $cacheEnabled,  // true
    private readonly bool $strictMode,    // false
) {}
```

### Valores aceptados para boolean

```xml
<!-- true -->
<argument name="flag" xsi:type="boolean">true</argument>
<argument name="flag" xsi:type="boolean">1</argument>
<argument name="flag" xsi:type="boolean">yes</argument>

<!-- false -->
<argument name="flag" xsi:type="boolean">false</argument>
<argument name="flag" xsi:type="boolean">0</argument>
<argument name="flag" xsi:type="boolean">no</argument>
```

## Tipo: `number`

Para enteros y flotantes:

```xml
<type name="MiVendor\Blog\Model\PostService">
    <arguments>
        <argument name="maxRetries"   xsi:type="number">3</argument>
        <argument name="timeout"      xsi:type="number">30</argument>
        <argument name="cacheLifetime" xsi:type="number">3600</argument>
        <argument name="taxRate"      xsi:type="number">0.16</argument>
    </arguments>
</type>
```

```php
public function __construct(
    private readonly int   $maxRetries,    // 3
    private readonly int   $timeout,       // 30
    private readonly int   $cacheLifetime, // 3600
    private readonly float $taxRate,       // 0.16
) {}
```

---

## Tipo: `null`

Para hacer que una dependencia sea `null` en vez de instanciar la clase:

```xml
<type name="MiVendor\Blog\Model\PostService">
    <arguments>
        <!-- Deshabilitar una dependencia opcional -->
        <argument name="optionalCache" xsi:type="null"/>
    </arguments>
</type>
```

```php
public function __construct(
    private readonly ?CacheInterface $optionalCache = null
) {
    // $this->optionalCache es null — el DI lo inyectó como null
}

public function get(int $id): Post
{
    if ($this->optionalCache !== null) {
        $cached = $this->optionalCache->load($id);
        if ($cached) return $cached;
    }
    // ... obtener de DB
}
```

**Cuándo usarlo**: cuando una dependencia tiene un valor por defecto en el constructor pero quieres forzar `null` para una configuración específica sin tocar el código.

## Combinar todos los tipos en un ejemplo real

```xml
<!-- etc/di.xml -->
<type name="MiVendor\Blog\Service\SyncService">
    <arguments>
        <!-- Objeto: implementación específica del logger -->
        <argument name="logger" xsi:type="object">
            MiVendor\Blog\Logger\SyncLogger
        </argument>

        <!-- String: endpoint de la API externa -->
        <argument name="apiEndpoint" xsi:type="string">
            https://erp.miempresa.com/api/v2
        </argument>

        <!-- Boolean: activar modo simulación -->
        <argument name="dryRun" xsi:type="boolean">false</argument>

        <!-- Number: límite de items por batch -->
        <argument name="batchSize" xsi:type="number">100</argument>

        <!-- Number: timeout en segundos -->
        <argument name="timeout" xsi:type="number">30</argument>

        <!-- Null: sin caché en este servicio -->
        <argument name="cache" xsi:type="null"/>
    </arguments>
</type>
```

```php
namespace MiVendor\Blog\Service;

use Psr\Log\LoggerInterface;
use Magento\Framework\App\CacheInterface;

class SyncService
{
    public function __construct(
        private readonly LoggerInterface  $logger,
        private readonly string           $apiEndpoint,
        private readonly bool             $dryRun,
        private readonly int              $batchSize,
        private readonly int              $timeout,
        private readonly ?CacheInterface  $cache = null,
    ) {}
}
```

## Sobrescribir argumentos por área

Puedes tener valores diferentes en frontend vs admin vs CLI:

```xml
<!-- etc/di.xml (global) -->
<type name="MiVendor\Blog\Service\SyncService">
    <arguments>
        <argument name="dryRun" xsi:type="boolean">false</argument>
        <argument name="batchSize" xsi:type="number">100</argument>
    </arguments>
</type>
```

```xml
<!-- etc/frontend/di.xml — solo en frontend -->
<type name="MiVendor\Blog\Service\SyncService">
    <arguments>
        <!-- En frontend, deshabilitar sync automático -->
        <argument name="dryRun" xsi:type="boolean">true</argument>
    </arguments>
</type>
```

Magento mergea los `di.xml` — el del área sobreescribe el global para ese argumento específico.

## Errores comunes

### Type mismatch silencioso

```xml
<!-- ⚠️ El constructor pide int pero declaras string — PHP puede castear, puede no -->
<argument name="timeout" xsi:type="string">30</argument>
```

```php
// Siempre usa el tipo correcto en di.xml:
private readonly int $timeout  →  xsi:type="number"
private readonly string $url   →  xsi:type="string"
private readonly bool $flag    →  xsi:type="boolean"
```

### Argumento no encontrado

```bash
# Error: "Missing required argument $apiEndpoint"
# Causa: el nombre en di.xml no coincide con el parámetro del constructor

# Constructor:          $apiEndpoint
# di.xml:              api_endpoint   ← incorrecto (snake vs camel)
# Correcto:            apiEndpoint
```

El nombre del `<argument name="">` debe coincidir **exactamente** con el nombre del parámetro en el constructor, en camelCase.

---

## Resumen

| Tipo XML | PHP type | Ejemplo |
|---|---|---|
| `xsi:type="object"` | Clase/Interfaz | `MyClass\Foo` |
| `xsi:type="string"` | `string` | `"valor"` |
| `xsi:type="boolean"` | `bool` | `true` / `false` |
| `xsi:type="number"` | `int` / `float` | `42` / `0.16` |
| `xsi:type="null"` | `null` | *(sin valor)* |

## Ejercicios

### Ejercicio 1 — Inyectar null para deshabilitar una dependencia opcional

Tienes este servicio con una dependencia de caché opcional. En el área `adminhtml`, quieres deshabilitar el caché completamente pasando `null`. Hazlo solo con `di.xml`.

```php
class PostService
{
    public function __construct(
        private readonly PostRepositoryInterface $repository,
        private readonly ?CacheInterface $cache = null,
    ) {}

    public function getPost(int $id): Post
    {
        if ($this->cache !== null) {
            $cached = $this->cache->load("post_{$id}");
            if ($cached) return unserialize($cached);
        }
        return $this->repository->getById($id);
    }
}
```

<details>
<summary>Ver solución</summary>

```xml
<!-- etc/di.xml — configuración global: caché activo -->
<type name="MiVendor\Blog\Model\PostService">
    <arguments>
        <argument name="cache" xsi:type="object">
            Magento\Framework\App\Cache\Type\Collection
        </argument>
    </arguments>
</type>
```

```xml
<!-- etc/adminhtml/di.xml — en el admin: deshabilitar caché -->
<type name="MiVendor\Blog\Model\PostService">
    <arguments>
        <!-- xsi:type="null" inyecta null, ignorando el valor global -->
        <argument name="cache" xsi:type="null"/>
    </arguments>
</type>
```

```bash
php bin/magento cache:flush
php bin/magento dev:di:info "MiVendor\Blog\Model\PostService"
# En área frontend: cache = Magento\Framework\App\Cache\Type\Collection
# En área adminhtml: cache = null
```

**Resultado**: en el frontend se usa caché; en el admin, `$this->cache` es `null` y el servicio va directo al repositorio.

</details>

### Ejercicio 2 — Inyectar una implementación concreta solo para una clase específica

Tienes dos implementaciones de `LoggerInterface`: el logger general (default) y un `AuditLogger` que escribe en `var/log/audit.log`. Quieres que `OrderService` use el `AuditLogger` pero que el resto del sistema siga usando el logger general.

<details>
<summary>Ver solución</summary>

```xml
<!-- etc/di.xml -->

<!-- 1. Definir el AuditLogger como virtual type -->
<virtualType name="MiVendor\Blog\Logger\AuditHandler"
             type="Magento\Framework\Logger\Handler\Base">
    <arguments>
        <argument name="fileName" xsi:type="string">/var/log/audit.log</argument>
    </arguments>
</virtualType>

<virtualType name="MiVendor\Blog\Logger\AuditLogger"
             type="Magento\Framework\Logger\Monolog">
    <arguments>
        <argument name="name" xsi:type="string">audit</argument>
        <argument name="handlers" xsi:type="array">
            <item name="audit" xsi:type="object">MiVendor\Blog\Logger\AuditHandler</item>
        </argument>
    </arguments>
</virtualType>

<!-- 2. Inyectarlo SOLO en OrderService — el resto no se ve afectado -->
<type name="MiVendor\Blog\Model\OrderService">
    <arguments>
        <argument name="logger" xsi:type="object">
            MiVendor\Blog\Logger\AuditLogger
        </argument>
    </arguments>
</type>
```

**Diferencia clave vs `<preference>`**:
- Un `<preference>` cambiaría `LoggerInterface` para **todas** las clases del sistema
- `<argument xsi:type="object">` solo afecta a **esta clase específica** — más quirúrgico y seguro

</details>
