# 4.6 — Virtual Types: Alias de Configuración en di.xml

> **Objetivo**: Entender qué son los Virtual Types, por qué son uno de los patrones más elegantes del DI de Magento, y cómo usarlos para crear configuraciones reutilizables sin escribir código PHP adicional.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [4.5 — Proxies](4.5-proxies.md)

---

## El problema que resuelven

Imagina que tienes un logger genérico y quieres tres instancias configuradas diferente — una para pedidos, una para pagos, una para sincronización — cada una escribiendo en su propio archivo.

**Sin Virtual Types** tendrías que crear tres clases PHP idénticas que solo difieren en el nombre del archivo:

```php
// ❌ Repetición innecesaria — tres clases con el mismo código
class OrderLogger extends Monolog { /* fileName = order.log */ }
class PaymentLogger extends Monolog { /* fileName = payment.log */ }
class SyncLogger extends Monolog { /* fileName = sync.log */ }
```

**Con Virtual Types** haces todo en `di.xml` sin escribir ninguna clase PHP nueva:

```xml
<!-- ✅ Tres "clases" configuradas distinto, cero código PHP nuevo -->
<virtualType name="OrderLogger" type="Magento\Framework\Logger\Monolog">
    <arguments>
        <argument name="name" xsi:type="string">order</argument>
        <argument name="handlers" xsi:type="array">
            <item name="system" xsi:type="object">OrderLogHandler</item>
        </argument>
    </arguments>
</virtualType>
```

---

## Qué es un Virtual Type

Un Virtual Type es un **alias con configuración** — es como crear una subclase en XML sin escribir código PHP. Hereda todos los métodos y comportamiento de la clase base, pero con argumentos diferentes.

```
VirtualType  =  clase PHP existente  +  argumentos específicos  =  "nueva clase" sin código
```

No existe como archivo `.php` — solo en la configuración del DI container.

---

## Sintaxis básica

```xml
<virtualType name="NombreVirtual" type="ClaseBase">
    <arguments>
        <argument name="argumento" xsi:type="string">valor</argument>
    </arguments>
</virtualType>
```

- `name` — el nombre del Virtual Type (actúa como nombre de clase en el DI)
- `type` — la clase PHP real que se instancia
- `arguments` — configuración específica para esta "variante"

## Ejemplo completo: Logger por módulo

```xml
<!-- etc/di.xml -->

<!-- 1. Definir el handler para pedidos -->
<virtualType name="MiVendor\Blog\Logger\OrderHandler"
             type="Magento\Framework\Logger\Handler\Base">
    <arguments>
        <argument name="fileName" xsi:type="string">/var/log/blog_orders.log</argument>
        <argument name="loggerType" xsi:type="number">100</argument>
    </arguments>
</virtualType>

<!-- 2. Definir el logger que usa ese handler -->
<virtualType name="MiVendor\Blog\Logger\OrderLogger"
             type="Magento\Framework\Logger\Monolog">
    <arguments>
        <argument name="name" xsi:type="string">blog_orders</argument>
        <argument name="handlers" xsi:type="array">
            <item name="system" xsi:type="object">MiVendor\Blog\Logger\OrderHandler</item>
        </argument>
    </arguments>
</virtualType>

<!-- 3. Inyectar el logger virtual en la clase que lo necesita -->
<type name="MiVendor\Blog\Model\OrderProcessor">
    <arguments>
        <argument name="logger" xsi:type="object">MiVendor\Blog\Logger\OrderLogger</argument>
    </arguments>
</type>
```

```php
// OrderProcessor recibe el logger configurado para órdenes
class OrderProcessor
{
    public function __construct(
        private readonly \Psr\Log\LoggerInterface $logger  // ← LoggerInterface normal
    ) {}

    public function process(int $orderId): void
    {
        // Escribe en var/log/blog_orders.log
        $this->logger->info('Procesando orden', ['id' => $orderId]);
    }
}
```

## Ejemplo: múltiples variantes de un servicio

Un caso muy común — el mismo servicio con diferentes configuraciones según el contexto:

```xml
<!-- Servicio de caché con TTL corto para precios -->
<virtualType name="MiVendor\Blog\Cache\PriceCache"
             type="MiVendor\Blog\Service\CacheService">
    <arguments>
        <argument name="cacheTag"  xsi:type="string">blog_prices</argument>
        <argument name="lifetime"  xsi:type="number">300</argument>
        <argument name="compress"  xsi:type="boolean">false</argument>
    </arguments>
</virtualType>

<!-- Mismo servicio con TTL largo para contenido estático -->
<virtualType name="MiVendor\Blog\Cache\ContentCache"
             type="MiVendor\Blog\Service\CacheService">
    <arguments>
        <argument name="cacheTag"  xsi:type="string">blog_content</argument>
        <argument name="lifetime"  xsi:type="number">86400</argument>
        <argument name="compress"  xsi:type="boolean">true</argument>
    </arguments>
</virtualType>

<!-- Inyectar cada variante donde corresponde -->
<type name="MiVendor\Blog\Model\PriceCalculator">
    <arguments>
        <argument name="cache" xsi:type="object">MiVendor\Blog\Cache\PriceCache</argument>
    </arguments>
</type>

<type name="MiVendor\Blog\Model\ContentRenderer">
    <arguments>
        <argument name="cache" xsi:type="object">MiVendor\Blog\Cache\ContentCache</argument>
    </arguments>
</type>
```

```php
// CacheService — una sola clase, dos comportamientos configurados
class CacheService
{
    public function __construct(
        private readonly string $cacheTag,
        private readonly int    $lifetime,
        private readonly bool   $compress,
    ) {}
}
```

## Virtual Types en cadena

Puedes usar un Virtual Type como base de otro Virtual Type:

```xml
<!-- Base: logger con formato JSON -->
<virtualType name="JsonLogger" type="Magento\Framework\Logger\Monolog">
    <arguments>
        <argument name="name" xsi:type="string">json_base</argument>
    </arguments>
</virtualType>

<!-- Extiende JsonLogger agregando un handler específico -->
<virtualType name="MiVendor\Blog\Logger\ApiLogger" type="JsonLogger">
    <arguments>
        <argument name="name" xsi:type="string">api_logger</argument>
        <argument name="handlers" xsi:type="array">
            <item name="api" xsi:type="object">MiVendor\Blog\Logger\ApiHandler</item>
        </argument>
    </arguments>
</virtualType>
```

## Virtual Types en el core de Magento

Magento usa Virtual Types extensamente — ver algunos ejemplos reales:

```xml
<!-- vendor/magento/module-catalog/etc/di.xml -->

<!-- Virtual Type para el caché de productos -->
<virtualType name="Magento\Catalog\Model\ResourceModel\Product\Collection\Grid\Plugin"
             type="Magento\Framework\Model\ResourceModel\Db\Collection\AbstractCollection">
    ...
</virtualType>

<!-- Virtual Type para el indexer de precios -->
<virtualType name="Magento\Catalog\Model\Indexer\Product\Price\Action\Row"
             type="Magento\Catalog\Model\Indexer\Product\Price\Action\Full">
    <arguments>
        <argument name="rowStrategy" xsi:type="object">
            Magento\Catalog\Model\Indexer\Product\Price\Action\RowStrategy
        </argument>
    </arguments>
</virtualType>
```

```bash
# Ver todos los Virtual Types definidos en Magento:
grep -r "virtualType" vendor/magento/ --include="di.xml" | wc -l
# → 500+
```

## Cuándo usar Virtual Types

```
✅ Usar Virtual Type cuando:
   - Necesitas la misma clase con diferentes argumentos en distintos lugares
   - Quieres evitar crear subclases PHP vacías solo para cambiar configuración
   - Defines loggers, caches, o servicios con configuración específica por módulo
   - La variación es solo de configuración, no de comportamiento

❌ NO usar Virtual Type cuando:
   - Necesitas sobreescribir métodos (usa subclase PHP real o Plugin)
   - La lógica difiere entre variantes (usa subclase o Strategy pattern)
   - Solo lo usas en un lugar (usa <arguments> directamente en <type>)
```

---

## Virtual Type vs las alternativas

| Necesidad | Solución |
|---|---|
| Misma clase, distinta configuración | **Virtual Type** |
| Misma clase, distinta lógica | Subclase PHP |
| Cambiar comportamiento de clase del core | Plugin |
| Reemplazar clase completamente | Preference |
| Múltiples instancias con estado | Factory |

---

## Resumen

```xml
<!-- Patrón completo -->

<!-- 1. Definir el Virtual Type (sin código PHP) -->
<virtualType name="MiNombreVirtual" type="ClaseBaseReal">
    <arguments>
        <argument name="param" xsi:type="string">valor específico</argument>
    </arguments>
</virtualType>

<!-- 2. Usarlo igual que una clase real -->
<type name="MiClase">
    <arguments>
        <argument name="dep" xsi:type="object">MiNombreVirtual</argument>
    </arguments>
</type>
```

```
Virtual Type  =  configuración reutilizable sin código PHP
               =  la forma más elegante de evitar subclases vacías
               =  muy usada para loggers, caches y servicios configurables
```
