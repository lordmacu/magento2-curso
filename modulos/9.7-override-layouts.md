# 9.7 — Override de Layouts y Templates del Core

> **Objetivo**: Sobrescribir layouts y templates del core de Magento correctamente — desde un módulo o desde un tema — sin modificar los archivos originales.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [9.6 — Containers vs Blocks: estructura del árbol de layout](9.6-containers.md)

## Dos formas de sobrescribir

```
1. Desde un módulo (app/code/)
   → Mejor para cambios ligados a lógica de negocio
   → Se aplica en todos los temas

2. Desde un tema (app/design/)
   → Mejor para cambios puramente visuales
   → Solo aplica cuando ese tema está activo
```

---

## Override de layout XML desde un módulo

Simplemente crea un archivo con el mismo handle en tu módulo — Magento los fusiona:

```xml
<!-- Para modificar catalog_product_view.xml del core: -->
<!-- app/code/MiVendor/Blog/view/frontend/layout/catalog_product_view.xml -->
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">
    <body>
        <!-- Eliminar el bloque de comparación -->
        <referenceBlock name="catalog.compare.sidebar" remove="true"/>

        <!-- Modificar argumentos de un bloque existente -->
        <referenceBlock name="product.info.upsell">
            <arguments>
                <argument name="product_count" xsi:type="number">4</argument>
            </arguments>
        </referenceBlock>

        <!-- Agregar tu propio bloque -->
        <referenceContainer name="product.info.main">
            <block class="MiVendor\Blog\Block\Product\RelatedPosts"
                   name="mivendor.product.related.posts"
                   template="MiVendor_Blog::product/related-posts.phtml"
                   after="product.info.addtocart"/>
        </referenceContainer>
    </body>
</page>
```

Los layouts de módulos se **fusionan**, no se reemplazan. No puedes "reemplazar completamente" un layout desde un módulo — solo puedes agregar, modificar y eliminar elementos.

---

## Override de template desde un módulo

Para reemplazar un archivo `.phtml` del core, declara el override en `view.xml` o usando `di.xml`:

### Método 1: `view/frontend/templates/` con el path correcto

```
El template original está en:
  vendor/magento/module-catalog/view/frontend/templates/product/view/gallery.phtml
  → Módulo: Magento_Catalog
  → Path:   product/view/gallery.phtml

Tu override va en:
  app/code/MiVendor/Blog/view/frontend/templates/Magento_Catalog/product/view/gallery.phtml
```

```
Estructura de directorios:
app/code/MiVendor/Blog/
└── view/
    └── frontend/
        └── templates/
            └── Magento_Catalog/           ← nombre del módulo original
                └── product/
                    └── view/
                        └── gallery.phtml  ← tu versión
```

### Método 2: Desde un tema

```
app/design/frontend/MiVendor/MiTema/
└── Magento_Catalog/
    └── templates/
        └── product/
            └── view/
                └── gallery.phtml
```

---

## Override de layout XML desde un tema

```
app/design/frontend/MiVendor/MiTema/
└── Magento_Catalog/
    └── layout/
        └── catalog_product_view.xml   ← fusionado con el del módulo
```

En temas, el layout también se fusiona — no reemplaza. Si quieres reemplazar completamente, usa `override/`:

```
app/design/frontend/MiVendor/MiTema/
└── Magento_Catalog/
    └── layout/
        └── override/
            └── base/
                └── catalog_product_view.xml   ← reemplaza completamente
```

---

## Override de template desde un tema

```
app/design/frontend/MiVendor/MiTema/
└── Magento_Catalog/
    └── templates/
        └── product/
            └── view/
                └── gallery.phtml   ← reemplaza completamente el original
```

En temas, los templates **sí se reemplazan** completamente (a diferencia de los layouts que se fusionan).

---

## Cambiar el template de un block desde el layout XML

La forma más limpia — no duplicas el template, solo apuntas a uno diferente:

```xml
<!-- En tu módulo, apuntar a un template diferente para un block del core -->
<referenceBlock name="product.info.addtocart">
    <action method="setTemplate">
        <argument name="template" xsi:type="string">
            MiVendor_Blog::product/custom-addtocart.phtml
        </argument>
    </action>
</referenceBlock>
```

---

## Jerarquía de resolución de templates

Cuando Magento busca un template, sigue este orden (mayor número = mayor prioridad):

```
1. vendor/magento/module-xxx/view/frontend/templates/  (core)
2. app/code/OtroVendor/OtroModulo/view/frontend/templates/Magento_Xxx/ (override de módulo)
3. app/design/frontend/MiVendor/MiTema/Magento_Xxx/templates/ (override de tema)
```

El tema siempre gana sobre el módulo, que siempre gana sobre el core.

---

## Qué NO hacer

```
❌ Modificar archivos en vendor/ directamente
   → Se pierden en el próximo composer update

❌ Copiar el template al tema sin necesidad
   → Queda desactualizado cuando el core actualiza el original
   → Preferir override de layout para cambios estructurales

❌ Usar Preference para sobrescribir Blocks del core
   → Solo para necesidades muy específicas (ver módulo 4.7)
   → Preferir layout XML + templates

✅ Usar layout XML para cambios estructurales (agregar/quitar/mover)
✅ Usar template override solo cuando el cambio HTML no se puede
   hacer añadiendo/modificando blocks desde XML
```

---

## Resumen

```
Módulo (app/code/):
  Layout:   view/frontend/layout/{handle}.xml        → fusiona
  Template: view/frontend/templates/Magento_X/...    → reemplaza

Tema (app/design/frontend/Vendor/Theme/):
  Layout:   Magento_X/layout/{handle}.xml            → fusiona
  Layout*:  Magento_X/layout/override/base/{handle}  → reemplaza
  Template: Magento_X/templates/...                  → reemplaza

Orden de prioridad (mayor gana):
  Core < Módulo override < Tema

Cambio de template sin duplicar archivo:
  <referenceBlock name="...">
      <action method="setTemplate"><argument ...>Mi_Modulo::path.phtml</argument></action>
  </referenceBlock>
```

## Ejercicios

### Ejercicio 1 — Personalizar el template de minicart

Necesitas agregar un mensaje de envío gratis al minicart cuando el total supera $50. El template original es `Magento_Checkout::cart/minicart.phtml`. ¿Cuál es el enfoque correcto y dónde va el archivo?

<details>
<summary>Ver solución</summary>

**Enfoque recomendado: agregar un block nuevo, no copiar el template**

```xml
<!-- view/frontend/layout/default.xml (el minicart aparece en todas las páginas) -->
<?xml version="1.0"?>
<page ...>
    <body>
        <referenceBlock name="minicart">
            <block class="MiVendor\Blog\Block\Cart\FreeShippingBanner"
                   name="mivendor.free.shipping.banner"
                   template="MiVendor_Blog::cart/free-shipping-banner.phtml"
                   after="-"/>
        </referenceBlock>
    </body>
</page>
```

```php
// Block/Cart/FreeShippingBanner.php
class FreeShippingBanner extends Template
{
    public function __construct(
        Context $context,
        private readonly \Magento\Checkout\Model\Cart $cart,
        array $data = []
    ) {
        parent::__construct($context, $data);
    }

    public function getRemainingForFreeShipping(): float
    {
        $threshold = 50.0;
        $total = $this->cart->getQuote()->getSubtotal();
        return max(0, $threshold - $total);
    }
}
```

**Si sí necesitas modificar el template** (cambio profundo en la estructura HTML):

```
app/code/MiVendor/Blog/view/frontend/templates/
└── Magento_Checkout/
    └── cart/
        └── minicart.phtml   ← copia del original + tus cambios
```

Riesgo: cuando Magento actualiza `minicart.phtml`, tu copia queda desactualizada.

</details>

### Ejercicio 2 — Override de layout de producto en tema

Desde un tema `MiVendor/MiTema`, elimina el bloque `product.info.upsell` de todas las páginas de producto y cambia el template del bloque `product.info.addtocart` a uno propio.

<details>
<summary>Ver solución</summary>

```xml
<!-- app/design/frontend/MiVendor/MiTema/Magento_Catalog/layout/catalog_product_view.xml -->
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">
    <body>
        <!-- Eliminar upsell -->
        <referenceBlock name="product.info.upsell" remove="true"/>

        <!-- Cambiar template del botón de agregar al carrito -->
        <referenceBlock name="product.info.addtocart">
            <action method="setTemplate">
                <argument name="template" xsi:type="string">
                    Magento_Catalog::product/view/custom-addtocart.phtml
                </argument>
            </action>
        </referenceBlock>
    </body>
</page>
```

```
El template custom va en:
app/design/frontend/MiVendor/MiTema/
└── Magento_Catalog/
    └── templates/
        └── product/
            └── view/
                └── custom-addtocart.phtml
```

</details>
