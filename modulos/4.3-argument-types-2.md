## Tipo: `array`

El tipo más poderoso del DI de Magento. Permite inyectar colecciones de objetos, strings o mixtos. Es la base de patrones como **Pool**, **Chain of Responsibility** y **Strategy**.

### Array de strings

```xml
<type name="MiVendor\Blog\Model\Validator">
    <arguments>
        <argument name="allowedStatuses" xsi:type="array">
            <item name="draft"     xsi:type="string">draft</item>
            <item name="published" xsi:type="string">published</item>
            <item name="archived"  xsi:type="string">archived</item>
        </argument>
    </arguments>
</type>
```

```php
public function __construct(
    private readonly array $allowedStatuses  // ['draft' => 'draft', 'published' => 'published', ...]
) {}
```

### Array de objetos — el patrón más usado

```xml
<type name="MiVendor\Blog\Model\PostValidator">
    <arguments>
        <argument name="validators" xsi:type="array">
            <item name="title"   xsi:type="object">MiVendor\Blog\Validator\TitleValidator</item>
            <item name="content" xsi:type="object">MiVendor\Blog\Validator\ContentValidator</item>
            <item name="slug"    xsi:type="object">MiVendor\Blog\Validator\SlugValidator</item>
        </argument>
    </arguments>
</type>
```

```php
namespace MiVendor\Blog\Model;

use MiVendor\Blog\Api\ValidatorInterface;

class PostValidator
{
    /**
     * @param ValidatorInterface[] $validators
     */
    public function __construct(
        private readonly array $validators
    ) {}

    public function validate(array $data): array
    {
        $errors = [];
        foreach ($this->validators as $name => $validator) {
            $result = $validator->validate($data);
            if (!$result->isValid()) {
                $errors[$name] = $result->getErrors();
            }
        }
        return $errors;
    }
}
```

## El patrón Pool — extensible por otros módulos

Este es uno de los patrones más importantes de Magento. Defines una lista de handlers en `di.xml` y otros módulos pueden **agregar los suyos sin modificar tu código**.

```xml
<!-- Tu módulo: MiVendor_Blog/etc/di.xml -->
<type name="MiVendor\Blog\Model\PostProcessorPool">
    <arguments>
        <argument name="processors" xsi:type="array">
            <item name="sanitize_html" xsi:type="object">
                MiVendor\Blog\Processor\SanitizeHtmlProcessor
            </item>
            <item name="generate_slug" xsi:type="object">
                MiVendor\Blog\Processor\GenerateSlugProcessor
            </item>
        </argument>
    </arguments>
</type>
```

```xml
<!-- Módulo externo: OtroVendor_BlogSeo/etc/di.xml -->
<!-- Agrega su propio processor SIN tocar el código de MiVendor_Blog -->
<type name="MiVendor\Blog\Model\PostProcessorPool">
    <arguments>
        <argument name="processors" xsi:type="array">
            <item name="seo_meta" xsi:type="object">
                OtroVendor\BlogSeo\Processor\SeoMetaProcessor
            </item>
        </argument>
    </arguments>
</type>
```

Magento **mergea los arrays** de todos los `di.xml` — el resultado final tiene los tres processors. Esto es extensibilidad sin modificar código.

```php
class PostProcessorPool
{
    /** @param ProcessorInterface[] $processors */
    public function __construct(private readonly array $processors) {}

    public function process(array $postData): array
    {
        foreach ($this->processors as $processor) {
            $postData = $processor->process($postData);
        }
        return $postData;
    }
}
```

### Eliminar un item de un array heredado

```xml
<!-- Quitar un processor del array (xsi:type="null" sobre el item) -->
<type name="MiVendor\Blog\Model\PostProcessorPool">
    <arguments>
        <argument name="processors" xsi:type="array">
            <item name="sanitize_html" xsi:type="null"/>
        </argument>
    </arguments>
</type>
```

<type name="MiVendor\Blog\Model\ConfigService">

public function __construct(private readonly array $config)

## Tipo: `const`

Inyecta el valor de una constante de clase PHP. Útil para evitar magic strings y mantenerse sincronizado con el código del core.

```xml
<type name="MiVendor\Blog\Model\PostService">
    <arguments>
        <!-- Constante de clase del core de Magento -->
        <argument name="cacheTag" xsi:type="const">
            Magento\Catalog\Model\Product::CACHE_TAG
        </argument>

        <!-- Constante de tu propia clase -->
        <argument name="defaultStatus" xsi:type="const">
            MiVendor\Blog\Model\Post::STATUS_DRAFT
        </argument>

        <!-- Constante de PHP nativo -->
        <argument name="sortOrder" xsi:type="const">SORT_ASC</argument>
    </arguments>
</type>
```

```php
// En MiVendor\Blog\Model\Post:
class Post
{
    const STATUS_DRAFT     = 'draft';
    const STATUS_PUBLISHED = 'published';
    const STATUS_ARCHIVED  = 'archived';
}
```

```php
// El servicio recibe el valor de la constante, no el nombre:
public function __construct(
    private readonly string $cacheTag,      // "cat_p" (valor real de Product::CACHE_TAG)
    private readonly string $defaultStatus, // "draft"  (valor real de Post::STATUS_DRAFT)
) {}
```

**Por qué usar `const` en lugar de `string`**:
- Si el valor de la constante cambia en el core, tu `di.xml` se actualiza automáticamente
- Hace explícito que ese valor viene de una constante — mejor legibilidad
- El IDE puede encontrar referencias a la constante

## Tipo: `init_parameter`

Inyecta un parámetro de entorno de Magento definido en `app/etc/env.php` o como variable de entorno del sistema.

```php
// app/etc/env.php
return [
    'system' => [...],
    'mi_parametro' => 'valor-de-entorno',
];
```

```xml
<type name="MiVendor\Blog\Model\ApiClient">
    <arguments>
        <!-- Lee el valor de Init::PARAM_BACKEND_FRONT_NAME desde Bootstrap -->
        <argument name="adminPath" xsi:type="init_parameter">
            Magento\Store\Model\Store::PARAM_RUN_CODE
        </argument>
    </arguments>
</type>
```

En la práctica, `init_parameter` se usa raramente en módulos de terceros — es más un mecanismo interno del core. Para leer configuración de entorno en tu código, usa `ScopeConfigInterface` o lee directamente de `env.php` vía el `DeploymentConfig`.

### Alternativa práctica: DeploymentConfig

```php
use Magento\Framework\App\DeploymentConfig;

class MiServicio
{
    public function __construct(
        private readonly DeploymentConfig $deploymentConfig
    ) {}

    public function getDbHost(): string
    {
        // Lee de app/etc/env.php
        return (string) $this->deploymentConfig->get('db/connection/default/host');
    }
}
```

## Patrones reales del core que usan arrays

### Payment Methods Pool

```xml
<!-- Magento usa un array de métodos de pago — cada módulo agrega el suyo -->
<type name="Magento\Payment\Model\MethodList">
    <arguments>
        <argument name="paymentMethods" xsi:type="array">
            <item name="free"       xsi:type="object">Magento\Payment\Model\Method\Free</item>
            <item name="checkmo"    xsi:type="object">Magento\OfflinePayments\Model\Checkmo</item>
            <!-- PayPal agrega el suyo en su propio di.xml -->
        </argument>
    </arguments>
</type>
```

### Shipping Carriers Pool

```xml
<type name="Magento\Shipping\Model\Config">
    <arguments>
        <argument name="carriers" xsi:type="array">
            <item name="flatrate" xsi:type="object">Magento\OfflineShipping\Model\Carrier\Flatrate</item>
            <item name="freeshipping" xsi:type="object">Magento\OfflineShipping\Model\Carrier\Freeshipping</item>

```

### Tu módulo puede seguir el mismo patrón

```php
// Define la interfaz que deben implementar los items del array:
interface PostExporterInterface
{
    public function export(array $posts): void;
}

// El pool los usa sin saber cuántos hay:
class ExporterPool
{
    /** @param PostExporterInterface[] $exporters */
    public function __construct(private readonly array $exporters) {}

    public function exportAll(array $posts): void
    {
        foreach ($this->exporters as $exporter) {
            $exporter->export($posts);
        }
    }
}
```

```xml
<!-- Tu di.xml base -->
<type name="MiVendor\Blog\Model\ExporterPool">
    <arguments>
        <argument name="exporters" xsi:type="array">
            <item name="csv"  xsi:type="object">MiVendor\Blog\Exporter\CsvExporter</item>
            <item name="json" xsi:type="object">MiVendor\Blog\Exporter\JsonExporter</item>
        </argument>
    </arguments>
</type>

<!-- Otro módulo agrega XML sin tocar tu código -->
<type name="MiVendor\Blog\Model\ExporterPool">
    <arguments>
        <argument name="exporters" xsi:type="array">
            <item name="xml" xsi:type="object">OtroVendor\BlogXml\Exporter\XmlExporter</item>
        </argument>
    </arguments>
</type>
```

## Resumen completo de tipos

| Tipo XML | Cuándo usarlo |
|---|---|
| `xsi:type="object"` | Inyectar una clase o interfaz específica |
| `xsi:type="string"` | Valores de texto hardcodeados |
| `xsi:type="boolean"` | Flags true/false |
| `xsi:type="number"` | Enteros o flotantes |
| `xsi:type="null"` | Forzar null en dependencias opcionales |
| `xsi:type="array"` | Colecciones de objetos/strings — patrón Pool |
| `xsi:type="const"` | Valor de una constante de clase PHP |
| `xsi:type="init_parameter"` | Parámetros del Bootstrap de Magento |

## Ejercicios

### Ejercicio 1 — Implementar el patrón Pool

Crea un sistema de validación extensible para posts con estas reglas:
1. Define una interfaz `PostValidatorInterface` con método `validate(array $data): array`
2. Crea dos validadores: `TitleValidator` (mínimo 3 chars) y `SlugValidator` (solo letras, números y guiones)
3. Crea un `PostValidatorPool` que reciba un array de validadores vía DI y ejecute todos
4. Registra ambos validadores en `di.xml`

<details>
<summary>Ver solución</summary>

```php
// Api/PostValidatorInterface.php
namespace MiVendor\Blog\Api;

interface PostValidatorInterface
{
    /** @return string[] Lista de errores (vacía si válido) */
    public function validate(array $data): array;
}
```

```php
// Validator/TitleValidator.php
namespace MiVendor\Blog\Validator;

use MiVendor\Blog\Api\PostValidatorInterface;

class TitleValidator implements PostValidatorInterface
{
    public function validate(array $data): array
    {
        if (empty($data['title']) || strlen($data['title']) < 3) {
            return ['El título debe tener al menos 3 caracteres.'];
        }
        return [];
    }
}
```

```php
// Validator/SlugValidator.php
namespace MiVendor\Blog\Validator;

use MiVendor\Blog\Api\PostValidatorInterface;

class SlugValidator implements PostValidatorInterface
{
    public function validate(array $data): array
    {
        if (!empty($data['slug']) && !preg_match('/^[a-z0-9\-]+$/', $data['slug'])) {
            return ['El slug solo puede contener letras minúsculas, números y guiones.'];
        }
        return [];
    }
}
```

```php
// Model/PostValidatorPool.php
namespace MiVendor\Blog\Model;

use MiVendor\Blog\Api\PostValidatorInterface;

class PostValidatorPool
{
    /** @param PostValidatorInterface[] $validators */
    public function __construct(private readonly array $validators = []) {}

    public function validate(array $data): array
    {
        $errors = [];
        foreach ($this->validators as $name => $validator) {
            $errors[$name] = $validator->validate($data);
        }
        return array_filter($errors); // solo los que tienen errores
    }
}
```

```xml
<!-- etc/di.xml -->
<type name="MiVendor\Blog\Model\PostValidatorPool">
    <arguments>
        <argument name="validators" xsi:type="array">
            <item name="title" xsi:type="object">MiVendor\Blog\Validator\TitleValidator</item>
            <item name="slug"  xsi:type="object">MiVendor\Blog\Validator\SlugValidator</item>
        </argument>
    </arguments>
</type>
```

</details>

### Ejercicio 2 — Eliminar un validador del pool sin tocar el código

Supón que `SlugValidator` causa problemas en producción. Desactívalo solo en el área `adminhtml` sin modificar ningún archivo PHP ni el `di.xml` global.

<details>
<summary>Ver solución</summary>

```xml
<!-- etc/adminhtml/di.xml -->
<type name="MiVendor\Blog\Model\PostValidatorPool">
    <arguments>
        <argument name="validators" xsi:type="array">
            <!-- xsi:type="null" sobre el item lo elimina del array mergeado -->
            <item name="slug" xsi:type="null"/>
        </argument>
    </arguments>
</type>
```

```bash
php bin/magento cache:flush
# En el área adminhtml, PostValidatorPool solo tendrá TitleValidator
# En el área frontend, seguirá teniendo ambos
```

</details>
