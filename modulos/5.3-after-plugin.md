# 5.3 — After Plugin: Modificar el Resultado

> **Objetivo**: Dominar el After Plugin — cuándo usarlo, cómo se firma correctamente, qué puede modificar y casos reales donde es la herramienta perfecta.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [5.2 — Before Plugin](5.2-before-plugin.md)

---

## Qué hace un After Plugin

Se ejecuta **después** del método interceptado. Recibe el resultado que devolvió el método y puede:
- Modificarlo y retornar el valor transformado
- Ejecutar lógica posterior sin tocar el resultado
- Enriquecer objetos con datos adicionales

No tiene acceso a los argumentos originales del método (a menos que los captures con `before` primero).

---

## Firma del método

```php
public function after{NombreMetodo}(
    SubjectType $subject,   // instancia de la clase interceptada
    ResultType $result,     // lo que retornó el método original
    ...$args                // argumentos originales (desde Magento 2.2+)
): ResultType
```

- Siempre debe retornar un valor del mismo tipo que el método original
- El `$result` puede ser `null` si el método no retorna nada

---

## Ejemplo básico — sin modificar resultado

```php
namespace MiVendor\Blog\Plugin;

use Magento\Catalog\Api\ProductRepositoryInterface;
use Magento\Catalog\Api\Data\ProductInterface;
use Psr\Log\LoggerInterface;

class LogProductLoadPlugin
{
    public function __construct(
        private readonly LoggerInterface $logger
    ) {}

    public function afterGetById(
        ProductRepositoryInterface $subject,
        ProductInterface $result
    ): ProductInterface {
        $this->logger->info('Producto cargado', [
            'id'   => $result->getId(),
            'sku'  => $result->getSku(),
            'name' => $result->getName(),
        ]);

        // Retorna el resultado sin modificar
        return $result;
    }
}
```

## Ejemplo — enriquecer el resultado con datos externos

```php
namespace MiVendor\Blog\Plugin;

use Magento\Catalog\Api\ProductRepositoryInterface;
use Magento\Catalog\Api\Data\ProductInterface;
use MiVendor\Blog\Service\ReviewService;

class EnrichProductWithReviewsPlugin
{
    public function __construct(
        private readonly ReviewService $reviewService
    ) {}

    public function afterGetById(
        ProductRepositoryInterface $subject,
        ProductInterface $result
    ): ProductInterface {
        // Agregar datos de reviews al producto sin modificar el repositorio original
        $rating = $this->reviewService->getAverageRating($result->getId());
        $result->setCustomAttribute('average_rating', $rating);

        $reviewCount = $this->reviewService->getReviewCount($result->getId());
        $result->setCustomAttribute('review_count', $reviewCount);

        return $result;
    }
}
```

## Ejemplo — filtrar resultados de una colección

```php
namespace MiVendor\Blog\Plugin;

use Magento\Catalog\Api\ProductRepositoryInterface;
use Magento\Catalog\Api\Data\ProductSearchResultsInterface;
use Magento\Customer\Model\Session;

class FilterProductsByPermissionPlugin
{
    public function __construct(
        private readonly Session $customerSession
    ) {}

    public function afterGetList(
        ProductRepositoryInterface $subject,
        ProductSearchResultsInterface $result
    ): ProductSearchResultsInterface {
        // Filtrar productos según permisos del cliente
        if ($this->customerSession->isLoggedIn()) {
            return $result; // cliente logueado ve todo
        }

        // Filtrar productos que requieren login
        $filteredItems = array_filter(
            $result->getItems(),
            fn($product) => !$product->getCustomAttribute('requires_login')?->getValue()
        );

        $result->setItems(array_values($filteredItems));
        $result->setTotalCount(count($filteredItems));

        return $result;
    }
}
```

## Ejemplo — modificar string de retorno

```php
namespace MiVendor\Blog\Plugin;

use Magento\Catalog\Model\Product;

class AppendBadgeToProductNamePlugin
{
    public function afterGetName(
        Product $subject,
        ?string $result
    ): ?string {
        if ($result === null) {
            return null;
        }

        // Agregar badge si el producto es nuevo
        if ($subject->getNewsFromDate() && strtotime($subject->getNewsFromDate()) > strtotime('-30 days')) {
            return $result . ' 🆕';
        }

        return $result;
    }
}
```

## Acceder a los argumentos originales (Magento 2.2+)

Desde Magento 2.2 puedes recibir los argumentos del método original como parámetros adicionales:

```php
public function afterGetById(
    ProductRepositoryInterface $subject,
    ProductInterface $result,
    int $productId,          // ← argumento original del método
    bool $editMode = false,  // ← argumento original
    ?int $storeId = null     // ← argumento original
): ProductInterface {
    // Ahora tienes acceso tanto al resultado como a los argumentos originales
    $this->logger->debug('Producto cargado', [
        'requested_id'    => $productId,
        'actual_id'       => $result->getId(),
        'store_requested' => $storeId,
    ]);

    return $result;
}
```

Esto es especialmente útil cuando necesitas contexto del request para decidir cómo modificar el resultado.

## After Plugin sobre métodos void

Si el método original no retorna nada (`void` o `null`):

```php
// Método original: public function delete(ProductInterface $product): void
public function afterDelete(
    ProductRepositoryInterface $subject,
    ?bool $result,          // null para métodos void
    ProductInterface $product  // argumento original
): void {
    // Lógica posterior: limpiar caché, notificar, etc.
    $this->cache->clean(['tags' => ['product_' . $product->getId()]]);
    $this->eventManager->dispatch('blog_product_deleted', ['product' => $product]);
}
```

## Registrar el plugin

```xml
<!-- etc/di.xml -->
<type name="Magento\Catalog\Api\ProductRepositoryInterface">
    <plugin name="mivendor_blog_enrich_product"
            type="MiVendor\Blog\Plugin\EnrichProductWithReviewsPlugin"
            sortOrder="50"/>
</type>
```

## Casos de uso reales

```
✅ Enriquecer objetos con datos de servicios externos
✅ Filtrar colecciones según permisos o contexto
✅ Logging y auditoría del resultado
✅ Transformar el formato de retorno
✅ Limpiar caché o disparar eventos después de una operación
✅ Agregar custom attributes a Data Objects
✅ Modificar strings de presentación (nombres, descripciones)
```

---

## Lo que NO puede hacer un After Plugin

```
❌ Detener o evitar la ejecución del método original → usa around
❌ Modificar los argumentos de entrada → usa before
❌ Cambiar el tipo de retorno (debe ser compatible)
❌ Interceptar métodos privados, protected, static o final
```

---

## Errores comunes

### Olvidar retornar el resultado

```php
// ❌ Incorrecto — retorna null implícitamente
public function afterGetById($subject, $result): ProductInterface
{
    $result->setCustomAttribute('enriched', true);
    // ← falta return $result
}

// ✅ Correcto
public function afterGetById($subject, $result): ProductInterface
{
    $result->setCustomAttribute('enriched', true);
    return $result;
}
```

### Tipo de retorno incompatible

```php
// ❌ Incorrecto — retorna tipo diferente al del método original
public function afterGetById($subject, $result): array
{
    return $result->getData(); // array en lugar de ProductInterface
}

// ✅ Correcto — mismo tipo que el método original
public function afterGetById($subject, $result): ProductInterface
{
    return $result;
}
```

---

## Resumen

```
After Plugin:
  - Se ejecuta DESPUÉS del método original
  - Recibe el resultado y puede modificarlo
  - Debe retornar el mismo tipo que el método original
  - Puede recibir los argumentos originales como parámetros extra

Firma:
  public function after{Metodo}(SubjectType $subject, $result, ...$args): ResultType

Casos de uso: enriquecer resultados, filtrar colecciones,
              logging post-ejecución, limpiar caché, disparar eventos
```
