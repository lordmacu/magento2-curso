# 5.2 — Before Plugin: Modificar Argumentos de Entrada

> **Objetivo**: Dominar el Before Plugin — cuándo usarlo, cómo se firma correctamente, qué puede y qué no puede hacer, y casos reales de uso.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [5.1 — Plugin Overview](5.1-plugin-overview.md)

---

## Qué hace un Before Plugin

Se ejecuta **antes** del método interceptado. Su único propósito es:
- Ejecutar lógica previa (logging, validación, auditoría)
- Modificar los argumentos que recibirá el método original

No puede detener la ejecución del método original (para eso existe `around`).

---

## Firma del método

```php
public function before{NombreMetodo}(
    SubjectType $subject,   // instancia de la clase interceptada
    ...$args                // los mismos argumentos del método original
): array|null
```

- Retorna `array` con los argumentos modificados
- Retorna `null` si no modificas nada (Magento usa los originales)
- El nombre del método es `before` + nombre del método en **PascalCase**

---

## Ejemplo básico — sin modificar argumentos

```php
namespace MiVendor\Blog\Plugin;

use Magento\Catalog\Api\ProductRepositoryInterface;
use Psr\Log\LoggerInterface;

class LogProductAccessPlugin
{
    public function __construct(
        private readonly LoggerInterface $logger
    ) {}

    public function beforeGetById(
        ProductRepositoryInterface $subject,
        int $productId,
        bool $editMode = false,
        ?int $storeId = null,
        bool $forceReload = false
    ): ?array {
        $this->logger->info('Acceso a producto', ['id' => $productId]);

        // null = no modificar argumentos
        return null;
    }
}
```

---

## Ejemplo — modificar argumentos

```php
namespace MiVendor\Blog\Plugin;

use Magento\Catalog\Api\ProductRepositoryInterface;
use Magento\Store\Model\StoreManagerInterface;

class ForceCurrentStorePlugin
{
    public function __construct(
        private readonly StoreManagerInterface $storeManager
    ) {}

    // Fuerza que siempre se use el store actual si no se especificó uno
    public function beforeGetById(
        ProductRepositoryInterface $subject,
        int $productId,
        bool $editMode = false,
        ?int $storeId = null,
        bool $forceReload = false
    ): array {
        if ($storeId === null) {
            $storeId = (int) $this->storeManager->getStore()->getId();
        }

        // Retorna el array completo de argumentos — en el mismo orden
        return [$productId, $editMode, $storeId, $forceReload];
    }
}
```

## Ejemplo — validar antes de ejecutar

```php
namespace MiVendor\Blog\Plugin;

use Magento\Catalog\Api\ProductRepositoryInterface;
use Magento\Framework\Exception\LocalizedException;

class ValidateProductSavePlugin
{
    public function beforeSave(
        ProductRepositoryInterface $subject,
        \Magento\Catalog\Api\Data\ProductInterface $product
    ): array {
        // Validar antes de que el repositorio guarde
        if (strlen($product->getName()) < 3) {
            throw new LocalizedException(
                __('El nombre del producto debe tener al menos 3 caracteres.')
            );
        }

        if ($product->getPrice() < 0) {
            throw new LocalizedException(
                __('El precio no puede ser negativo.')
            );
        }

        // Normalizar datos antes de guardar
        $product->setName(trim($product->getName()));
        $product->setSku(strtolower(trim($product->getSku())));

        return [$product];
    }
}
```

## Interceptar métodos con un solo argumento

```php
// Método original: public function getById(int $id): Post
public function beforeGetById(
    PostRepositoryInterface $subject,
    int $id
): ?array {
    // Modificar el id (ej: asegurarse que sea positivo)
    $id = abs($id);
    return [$id];  // array con un solo elemento
}
```

---

## Interceptar métodos sin argumentos

```php
// Método original: public function getList(): array
public function beforeGetList(
    PostRepositoryInterface $subject
): ?array {
    // Solo lógica previa, sin argumentos que retornar
    $this->logger->debug('Obteniendo lista de posts');
    return null;  // o simplemente omite el return
}
```

---

## Registrar el plugin

```xml
<!-- etc/di.xml -->
<type name="Magento\Catalog\Api\ProductRepositoryInterface">
    <plugin name="mivendor_blog_validate_product_save"
            type="MiVendor\Blog\Plugin\ValidateProductSavePlugin"
            sortOrder="10"/>
</type>
```

**Tip**: intercepta la **interfaz** (`ProductRepositoryInterface`) en lugar de la clase concreta (`ProductRepository`). Así tu plugin funciona aunque otro módulo haya reemplazado la implementación con un Preference.

---

## Casos de uso reales

```
✅ Logging / auditoría antes de una operación
✅ Validación adicional de argumentos
✅ Normalización de datos de entrada (trim, lowercase, etc.)
✅ Forzar un valor por defecto si no se pasó argumento
✅ Añadir contexto (store ID, customer ID) automáticamente
✅ Rate limiting / throttling antes de operaciones costosas
```

---

## Lo que NO puede hacer un Before Plugin

```
❌ Detener la ejecución del método original → usa around
❌ Modificar el resultado del método → usa after
❌ Acceder al resultado del método → usa after
❌ Interceptar métodos privados, protected, static o final
```

---

## Errores comunes

### Firma incorrecta del retorno

```php
// ❌ Incorrecto — retorna solo el primer argumento
public function beforeGetById($subject, $id): int
{
    return $id;  // debe ser array o null
}

// ✅ Correcto
public function beforeGetById($subject, $id): ?array
{
    return [$id];  // array, aunque sea de un elemento
}
```

### Olvidar argumentos opcionales

```php
// ❌ Incorrecto — falta $storeId en el return
public function beforeGetById($subject, $id, $editMode = false, $storeId = null): array
{
    return [$id, $editMode];  // falta $storeId — Magento lo perderá
}

// ✅ Correcto — todos los argumentos en el return
public function beforeGetById($subject, $id, $editMode = false, $storeId = null): array
{
    return [$id, $editMode, $storeId];
}
```

---

## Resumen

```
Before Plugin:
  - Se ejecuta ANTES del método original
  - Puede modificar argumentos o ejecutar lógica previa
  - Retorna: array (args modificados) | null (sin cambios)
  - NO puede cambiar el resultado ni detener el método

Firma:
  public function before{Metodo}(SubjectType $subject, ...$args): ?array

Interceptar interfaz > clase concreta (más robusto)

Casos de uso: logging, validación, normalización, defaults
```

## Ejercicios

### Ejercicio 1 — Normalizar SKU antes de guardar

Crea un Before Plugin sobre `Magento\Catalog\Api\ProductRepositoryInterface::save()` que convierta el SKU a mayúsculas y elimine espacios antes de que se guarde.

<details>
<summary>Ver solución</summary>

```php
// Plugin/NormalizeSkuPlugin.php
namespace MiVendor\Blog\Plugin;

use Magento\Catalog\Api\ProductRepositoryInterface;
use Magento\Catalog\Api\Data\ProductInterface;

class NormalizeSkuPlugin
{
    public function beforeSave(
        ProductRepositoryInterface $subject,
        ProductInterface $product
    ): array {
        $product->setSku(strtoupper(trim($product->getSku())));
        return [$product];
    }
}
```

```xml
<!-- etc/di.xml -->
<type name="Magento\Catalog\Api\ProductRepositoryInterface">
    <plugin name="mivendor_blog_normalize_sku"
            type="MiVendor\Blog\Plugin\NormalizeSkuPlugin"
            sortOrder="10"/>
</type>
```

```bash
php bin/magento setup:di:compile && php bin/magento cache:flush
php bin/magento dev:di:info "Magento\Catalog\Model\ProductRepository"
# Verás: mivendor_blog_normalize_sku → beforeSave
```

</details>

### Ejercicio 2 — Forzar store ID en búsquedas

Crea un Before Plugin sobre `getById` que inyecte el `storeId` del store actual cuando no se pasa explícitamente.

<details>
<summary>Ver solución</summary>

```php
// Plugin/InjectStoreIdPlugin.php
namespace MiVendor\Blog\Plugin;

use Magento\Catalog\Api\ProductRepositoryInterface;
use Magento\Store\Model\StoreManagerInterface;

class InjectStoreIdPlugin
{
    public function __construct(
        private readonly StoreManagerInterface $storeManager
    ) {}

    public function beforeGetById(
        ProductRepositoryInterface $subject,
        int $productId,
        bool $editMode = false,
        ?int $storeId = null,
        bool $forceReload = false
    ): array {
        if ($storeId === null) {
            $storeId = (int) $this->storeManager->getStore()->getId();
        }
        return [$productId, $editMode, $storeId, $forceReload];
    }
}
```

```xml
<type name="Magento\Catalog\Api\ProductRepositoryInterface">
    <plugin name="mivendor_blog_inject_store_id"
            type="MiVendor\Blog\Plugin\InjectStoreIdPlugin"
            sortOrder="5"/>
</type>
```

</details>
