# 3.4 — File Structure del Módulo: Qué Va Dónde y Por Qué

> **Objetivo**: Conocer la convención de directorios dentro de un módulo a fondo — cada carpeta tiene un propósito específico y Magento los busca en lugares exactos. Poner un archivo en el lugar incorrecto hace que simplemente no funcione.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [3.3 — Sequence y dependencias entre módulos](3.3-module-sequence.md)

---

## La regla fundamental

En Magento, **la ubicación del archivo define su propósito**. No hay anotaciones como `@Route` de Symfony ni decorators — la carpeta le dice a Magento qué es cada cosa.

```
Controller/Post/View.php   →  Magento sabe que es un controller para /post/view
Observer/CheckStock.php    →  Magento sabe que es un observer
Plugin/ProductPlugin.php   →  Magento sabe que es un plugin
```

---

## Mapa completo de directorios

### `etc/` — Configuración XML

```
etc/
├── module.xml              ← Nombre, versión, sequence (OBLIGATORIO)
├── di.xml                  ← DI global: plugins, preferences, observers
├── config.xml              ← Valores de configuración por defecto
├── acl.xml                 ← Árbol de permisos para el admin
├── crontab.xml             ← Definición de cron jobs
├── webapi.xml              ← Endpoints REST y SOAP
├── extension_attributes.xml ← Extensión de interfaces del core
│
├── frontend/               ← Solo aplica en área frontend
│   ├── di.xml
│   ├── routes.xml          ← URLs del frontend (frontName)
│   └── events.xml          ← Observers del frontend
│
├── adminhtml/              ← Solo aplica en área adminhtml
│   ├── di.xml
│   ├── routes.xml          ← URLs del admin
│   ├── events.xml
│   ├── system.xml          ← Secciones de config en Stores → Configuration
│   └── menu.xml            ← Entradas en el menú del admin
│
└── webapi_rest/            ← Solo aplica en área API REST
    └── di.xml
```

**Regla**: Si un `di.xml` está en `etc/` aplica a todas las áreas. Si está en `etc/frontend/` solo aplica al frontend. Magento mergea ambos cuando está en el área frontend.

---

### `Api/` — Service Contracts (interfaces públicas)

```
Api/
├── PostRepositoryInterface.php      ← CRUD del repositorio
├── PostManagementInterface.php      ← Operaciones de negocio
└── Data/
    ├── PostInterface.php            ← Data Object (DTO)
    └── PostSearchResultsInterface.php
```

- Todo lo que esté en `Api/` es **contrato público** — otros módulos pueden depender de esto
- Las interfaces en `Api/Data/` son las que se serializan/deserializan en la API REST
- **Nunca pongas implementaciones en `Api/`** — solo interfaces

---

### `Model/` — Lógica de negocio y persistencia

```
Model/
├── Post.php                         ← Model principal (extiende AbstractModel)
├── PostRepository.php               ← Implementa Api\PostRepositoryInterface
├── PostManagement.php               ← Implementa Api\PostManagementInterface
│
└── ResourceModel/
    ├── Post.php                     ← Acceso a DB (extiende AbstractDb)
    └── Post/
        └── Collection.php           ← Colección de posts (queries múltiples)
```

- `Model/Post.php` — el objeto de dominio, getter/setters, lógica simple
- `Model/ResourceModel/Post.php` — todo lo relacionado con la DB (tabla, primary key)
- `Model/ResourceModel/Post/Collection.php` — para queries que devuelven múltiples filas
- `Model/PostRepository.php` — implementa el Service Contract, usa ResourceModel

---

### `Controller/` — Controllers HTTP

```
Controller/
├── Index/
│   └── Index.php            ← GET /blog  o  /blog/index/index
├── Post/
│   ├── View.php             ← GET /blog/post/view
│   ├── Save.php             ← POST /blog/post/save
│   └── Delete.php           ← POST /blog/post/delete
└── Adminhtml/
    └── Post/
        ├── Index.php        ← GET /admin/blog/post/index
        ├── Edit.php         ← GET /admin/blog/post/edit
        └── Save.php         ← POST /admin/blog/post/save
```

- La ruta URL mapea directamente a la estructura de carpetas
- `Adminhtml/` dentro de `Controller/` es para los controllers del panel admin
- Usa `HttpGetActionInterface` o `HttpPostActionInterface` — nunca extends Action (deprecado)

---

### `Block/` y `ViewModel/` — Presentación

```
Block/
├── Post/
│   └── View.php             ← Block clásico (extiende Template)
└── Adminhtml/
    └── Post/
        └── Grid.php

ViewModel/
├── PostViewModel.php        ← ViewModel moderno (implementa ArgumentInterface)
└── CategoryViewModel.php
```

- `Block/` — forma antigua, mezcla lógica con presentación. Aún necesario para algunos casos
- `ViewModel/` — forma moderna y preferida. Lógica pura, se inyecta en el layout XML
- Los templates `.phtml` viven en `view/`, no aquí

---

### `Plugin/` — Interceptors

```
Plugin/
├── ProductPlugin.php             ← Plugin sobre métodos del core
├── CheckoutPlugin.php
└── Model/
    └── OrderPlugin.php
```

No hay convención estricta de subcarpetas — lo importante es que el nombre deje claro sobre qué clase actúa. Se registran en `etc/di.xml`.

---

### `Observer/` — Event Listeners

```
Observer/
├── ProcessOrderAfterPlace.php     ← Implementa ObserverInterface
├── CheckInventoryBeforeSave.php
└── SendWelcomeEmail.php
```

Convención de nombre: **verbo + qué + cuándo**. Se registran en `etc/events.xml` o `etc/frontend/events.xml`.

---

### `Console/` — Comandos CLI

```
Console/
└── Command/
    ├── SincronizarProductosCommand.php   ← extends Command
    └── ExportarClientesCommand.php
```

Se registran en `etc/di.xml` dentro de `CommandList`.

---

### `Setup/` — Migraciones de base de datos

```
Setup/
└── Patch/
    ├── Data/
    │   ├── InsertDefaultCategories.php    ← Datos iniciales
    │   └── MigrateOldPrices.php          ← Migración de datos
    └── Schema/
        ├── CreatePostTable.php            ← Crear tabla
        └── AddIndexToPostTable.php        ← Modificar schema
```

- `Schema/` — cambios estructurales en la DB (CREATE TABLE, ADD COLUMN, ADD INDEX)
- `Data/` — inserción o modificación de datos (INSERT, UPDATE)
- Cada patch se ejecuta **una sola vez** y Magento lo registra en `patch_list` para no repetirlo

---

### `view/` — Assets, Layout y Templates

```
view/
├── frontend/
│   ├── layout/
│   │   ├── default.xml               ← Aplica a TODAS las páginas del frontend
│   │   ├── blog_index_index.xml      ← Solo para /blog/index/index
│   │   └── blog_post_view.xml        ← Solo para /blog/post/view
│   ├── templates/
│   │   └── post/
│   │       ├── view.phtml
│   │       └── list.phtml
│   └── web/
│       ├── css/
│       │   └── source/
│       │       └── _module.less
│       ├── js/
│       │   └── blog.js
│       └── images/
│
└── adminhtml/
    ├── layout/
    │   └── blog_adminhtml_post_index.xml
    ├── templates/
    └── ui_component/
        ├── blog_post_listing.xml       ← Grid del admin
        └── blog_post_form.xml          ← Formulario del admin
```

**Convención del handle de layout**:
```
{frontName}_{controller}_{action}.xml
blog_post_view.xml   →  aplica a  /blog/post/view
cms_page_view.xml    →  aplica a  /cms/page/view  (páginas CMS)
```

---

### `i18n/` — Traducciones

```
i18n/
├── es_MX.csv
├── es_ES.csv
└── en_US.csv
```

```csv
"Add to Cart","Agregar al carrito"
"Out of stock","Sin existencias"
"My custom phrase","Mi frase personalizada"
```

---

### `Helper/` — Utilidades (uso limitado)

```
Helper/
└── Data.php     ← Convención heredada, preferir ViewModel o Service
```

Los Helpers fueron el patrón antiguo para lógica reutilizable. Hoy se prefiere:
- **ViewModel** para lógica de presentación
- **Service/Model** para lógica de negocio
- **Repository** para acceso a datos

Úsalos solo si necesitas compatibilidad con código legacy o si son genuinamente utilidades stateless.

---

## Resumen visual

```
etc/           →  XMLs de configuración (di, routes, events, system...)
Api/           →  Interfaces públicas (Service Contracts)
Model/         →  Lógica de negocio + ORM
Controller/    →  HTTP handlers (routes → clases)
Block/         →  Presentación legacy
ViewModel/     →  Presentación moderna
Plugin/        →  Interceptors del DI
Observer/      →  Event listeners
Console/       →  Comandos CLI
Setup/Patch/   →  Migraciones de DB
view/          →  Layout XML + Templates + CSS/JS
i18n/          →  Traducciones
Helper/        →  Utilidades (evitar, preferir ViewModel/Service)
```
