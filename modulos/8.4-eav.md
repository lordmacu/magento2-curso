## El problema que resuelve EAV

Un catálogo de ecommerce necesita que:
- Una camisa tenga: talla, color, material
- Un televisor tenga: pulgadas, resolución, tecnología de pantalla
- Un libro tenga: autor, ISBN, número de páginas

Si usas una tabla tradicional con columnas fijas, necesitarías miles de columnas o una tabla por tipo de producto. Ninguna es viable.

🔄 **Laravel**: No hay equivalente directo. Podrías hacer algo similar con columnas JSON, polimorfismo o una tabla de metadatos. Ninguna es tan flexible como EAV.

**EAV** (Entity-Attribute-Value) resuelve esto con tres conceptos:
```
Entity    →  El objeto (producto, cliente, categoría)
Attribute →  El campo (talla, color, material)
Value     →  El valor (M, Rojo, Algodón)
```

---

## Cómo funciona EAV en MySQL

En vez de una tabla con 500 columnas:

```sql
-- Tabla de la entidad (solo datos fijos)
catalog_product_entity:
  entity_id | sku        | created_at
  ──────────────────────────────────────
  1         | CAM-001    | 2024-01-01
  2         | TV-55-4K   | 2024-01-02

-- Tabla de atributos
eav_attribute:
  attribute_id | entity_type_id | attribute_code | backend_type
  ──────────────────────────────────────────────────────────────
  71           | 4              | name           | varchar
  72           | 4              | price          | decimal
  73           | 4              | color          | int (FK a opciones)

-- Tablas de valores (una por tipo de dato)
catalog_product_entity_varchar:  (para strings cortos)
  entity_id | attribute_id | store_id | value
  ─────────────────────────────────────────────
  1         | 71           | 0        | "Camisa Básica"
  1         | 71           | 2        | "Basic Shirt"   (EN)

catalog_product_entity_decimal:  (para precios, pesos)
  entity_id | attribute_id | store_id | value
  ─────────────────────────────────────────────
  1         | 72           | 0        | 29.99
```

## Agregar un atributo de Producto (el caso más común)

La forma correcta es con un Data Patch + `EavSetup`:

```php
<?php
// Setup/Patch/Data/AddIsFeaturedAttribute.php
namespace MiVendor\Blog\Setup\Patch\Data;

use Magento\Framework\Setup\Patch\DataPatchInterface;
use Magento\Eav\Setup\EavSetupFactory;
use Magento\Framework\Setup\ModuleDataSetupInterface;
use Magento\Catalog\Model\Product;

class AddIsFeaturedAttribute implements DataPatchInterface
{
    public function __construct(
        private readonly EavSetupFactory $eavSetupFactory,
        private readonly ModuleDataSetupInterface $moduleDataSetup
    ) {}

    public function apply(): void
    {
        $eavSetup = $this->eavSetupFactory->create(['setup' => $this->moduleDataSetup]);

        $eavSetup->addAttribute(
            Product::ENTITY,       // entity_type_code
            'is_featured',         // attribute_code
            [
                // ── Tipo de dato ──────────────────────────────
                'type'     => 'int',       // backend_type: varchar, int, decimal, datetime, text
                'input'    => 'boolean',   // frontend_input: text, textarea, select, multiselect, boolean, date, ...
                'label'    => 'Is Featured Product',

                // ── Comportamiento ────────────────────────────
                'required'           => false,
                'default'            => 0,
                'global'             => \Magento\Eav\Model\Entity\Attribute\ScopedAttributeInterface::SCOPE_GLOBAL,
                'visible'            => true,
                'user_defined'       => true,  // aparece como "custom attribute" en el admin
                'searchable'         => false,
                'filterable'         => false,
                'comparable'         => false,
                'visible_on_front'   => false,
                'used_in_product_listing' => true,  // disponible en queries de listing

                // ── Asignar a un grupo en el formulario de producto ──
                'group'    => 'General',     // tab en el formulario de edición del producto
                'sort_order' => 100,
            ]
        );
    }

    public static function getDependencies(): array { return []; }
    public function getAliases(): array { return []; }
}
```

## Tipos de atributo y sus opciones de `input`

```
type (backend_type) →  dónde se guarda el valor
────────────────────────────────────────────────────
varchar      →  catalog_product_entity_varchar  (255 chars)
int          →  catalog_product_entity_int
decimal      →  catalog_product_entity_decimal
datetime     →  catalog_product_entity_datetime
text         →  catalog_product_entity_text (mediumtext)
static       →  en la tabla principal (catalog_product_entity)

input (cómo se edita en el admin)
────────────────────────────────────────────────────
text         →  campo de texto (type=varchar o int)
textarea     →  área de texto (type=text)
select       →  dropdown (type=int, FK a eav_attribute_option)
multiselect  →  múltiple selección (type=varchar, separado por comas)
boolean      →  checkbox Si/No (type=int, 0 o 1)
date         →  datepicker (type=datetime)
media_image  →  upload de imagen (type=varchar)
price        →  campo de precio (type=decimal)
```

## Atributo con opciones (select)

```php
$eavSetup->addAttribute(Product::ENTITY, 'fabric_type', [
    'type'    => 'int',
    'input'   => 'select',
    'label'   => 'Fabric Type',
    'required' => false,
    'global'  => \Magento\Eav\Model\Entity\Attribute\ScopedAttributeInterface::SCOPE_GLOBAL,

    // Las opciones del dropdown
    'option'  => [
        'values' => [
            0 => 'Cotton',      // posición => valor
            1 => 'Polyester',
            2 => 'Wool',
            3 => 'Silk',
        ]
    ],

    // Para filtros de la capa de navegación
    'filterable'         => true,
    'filterable_in_search' => true,
    'used_for_promo_rules' => true,
    'visible_on_front'   => true,
    'used_in_product_listing' => true,
]);
```

## Scope de los atributos

```php
use Magento\Eav\Model\Entity\Attribute\ScopedAttributeInterface;

// SCOPE_GLOBAL  → Un solo valor para todas las tiendas
// SCOPE_WEBSITE → Un valor por website
// SCOPE_STORE   → Un valor por store view (para traducciones)

'global' => ScopedAttributeInterface::SCOPE_GLOBAL,   // ← más común para atributos técnicos
'global' => ScopedAttributeInterface::SCOPE_STORE,    // ← para nombres, descripciones (multiidioma)
```

## Leer y escribir atributos EAV en código

```php
// Leer — exactamente igual que cualquier dato del modelo
$product = $this->productRepository->getById(42);
$isFeatured = $product->getData('is_featured');     // → 1 o 0
$fabricType = $product->getData('fabric_type');     // → ID de opción

// Con getters si defines el método:
$isFeatured = $product->getIsFeatured();

// Escribir
$product->setData('is_featured', 1);
$this->productRepository->save($product);

// O con el setter mágico:
$product->setIsFeatured(1);
$this->productRepository->save($product);
```

## Agregar atributo de Customer

```php
use Magento\Customer\Model\Customer;

$eavSetup->addAttribute(Customer::ENTITY, 'loyalty_points', [
    'type'     => 'int',
    'input'    => 'text',
    'label'    => 'Loyalty Points',
    'required' => false,
    'default'  => 0,
    'visible'  => true,
    'system'   => false,   // false = atributo de usuario, aparece en admin

    // Para que aparezca en el formulario de cuenta del cliente
    'used_in_forms' => [
        'adminhtml_customer',           // Formulario de edición en admin
        'customer_account_edit',        // Formulario de edición en storefront
    ],
]);

// Asignar el atributo al customer attribute set
$eavSetup->addAttributeToGroup(
    Customer::ENTITY,
    'Default',          // attribute set name
    'General',          // group name
    'loyalty_points',
    100                 // sort_order
);
```

## Eliminar un atributo

```php
// En un Data Patch si implementas PatchRevertableInterface:
public function revert(): void
{
    $eavSetup = $this->eavSetupFactory->create(['setup' => $this->moduleDataSetup]);
    $eavSetup->removeAttribute(Product::ENTITY, 'is_featured');
}

// O en el mismo patch si lo corres una vez en desarrollo:
$eavSetup->removeAttribute(Product::ENTITY, 'atributo_viejo');
```

---

## Actualizar un atributo existente

```php
// Modificar propiedades sin eliminar y recrear
$eavSetup->updateAttribute(
    Product::ENTITY,
    'is_featured',          // attribute_code
    'label',                // propiedad a cambiar
    'Featured Product'      // nuevo valor
);

// O múltiples propiedades:
$eavSetup->updateAttribute(Product::ENTITY, 'is_featured', [
    'label'             => 'Featured Product',
    'visible_on_front'  => true,
    'used_in_product_listing' => true,
]);
```

## Cuándo NO usar EAV

EAV tiene un costo: los queries son costosos porque necesitan JOINs múltiples.

```
✅ Usar EAV para:
  - Atributos de productos (es el sistema nativo)
  - Atributos de clientes y direcciones
  - Cuando necesitas scope por store view (multiidioma)
  - Cuando los atributos son configurables por el merchant

❌ No usar EAV para:
  - Módulos propios con entidades simples (usa tablas flat)
  - Datos que siempre se acceden juntos (mejor columnas normales)
  - Relaciones entre entidades (usa FK normales)
  - Datos con queries complejas (EAV + JOINs = caos)
```

---

## Resumen

```
EAV → Tabla de entidad + tablas de valores por tipo de dato
      Flexible pero costoso en queries

Agregar atributo:
  EavSetupFactory → addAttribute(ENTITY_TYPE, 'code', [...props...])
  En un DataPatch (se ejecuta una vez)

Tipos de dato:       varchar, int, decimal, datetime, text
Tipos de input:      text, select, multiselect, boolean, date, media_image

Scope:
  SCOPE_GLOBAL   → igual en todas las tiendas
  SCOPE_STORE    → puede tener valor diferente por store view

Leer:   $product->getData('attribute_code')
Escribir: $product->setData('attribute_code', $value) + save()
```

### Ejercicio 1 — Agregar atributos a un producto

Crea un Data Patch que agregue estos dos atributos al producto:
- `care_instructions` (textarea, scope store, no requerido)
- `sustainability_rating` (select con opciones: Bronze/Silver/Gold/Platinum, filterable)

<details>
<summary>Ver solución</summary>

```php
<?php
namespace MiVendor\Blog\Setup\Patch\Data;

use Magento\Framework\Setup\Patch\DataPatchInterface;
use Magento\Eav\Setup\EavSetupFactory;
use Magento\Framework\Setup\ModuleDataSetupInterface;
use Magento\Catalog\Model\Product;
use Magento\Eav\Model\Entity\Attribute\ScopedAttributeInterface;

class AddProductSustainabilityAttributes implements DataPatchInterface
{
    public function __construct(
        private readonly EavSetupFactory $eavSetupFactory,
        private readonly ModuleDataSetupInterface $moduleDataSetup
    ) {}

    public function apply(): void
    {
        $eavSetup = $this->eavSetupFactory->create(['setup' => $this->moduleDataSetup]);

        // Atributo 1: Instrucciones de cuidado (textarea multiidioma)
        $eavSetup->addAttribute(Product::ENTITY, 'care_instructions', [
            'type'             => 'text',
            'input'            => 'textarea',
            'label'            => 'Care Instructions',
            'required'         => false,
            'global'           => ScopedAttributeInterface::SCOPE_STORE,  // multiidioma
            'visible'          => true,
            'user_defined'     => true,
            'searchable'       => false,
            'filterable'       => false,
            'comparable'       => false,
            'visible_on_front' => true,
            'group'            => 'Content',
            'sort_order'       => 200,
        ]);

        // Atributo 2: Rating de sostenibilidad (select + filterable)
        $eavSetup->addAttribute(Product::ENTITY, 'sustainability_rating', [
            'type'    => 'int',
            'input'   => 'select',
            'label'   => 'Sustainability Rating',
            'required' => false,
            'global'  => ScopedAttributeInterface::SCOPE_GLOBAL,
            'option'  => [
                'values' => [
                    0 => 'Bronze',
                    1 => 'Silver',
                    2 => 'Gold',
                    3 => 'Platinum',
                ]
            ],
            'visible'                 => true,
            'user_defined'            => true,
            'filterable'              => true,     // aparece en layered navigation
            'filterable_in_search'    => true,
            'used_for_promo_rules'    => false,
            'visible_on_front'        => true,
            'used_in_product_listing' => true,     // disponible en colecciones de listing
            'group'                   => 'General',
            'sort_order'              => 150,
        ]);
    }

    public static function getDependencies(): array { return []; }
    public function getAliases(): array { return []; }
}
```

### Ejercicio 2 — Identificar el tipo de backend correcto

Para cada caso de uso, elige el `type` e `input` correcto y justifica:

| Campo | Tipo de dato | ¿Por qué? |
|---|---|---|
| Peso del producto (0.750 kg) | ? | ? |
| Tallas disponibles (S, M, L, XL) — múltiple | ? | ? |
| Fecha de caducidad | ? | ? |
| Descripción larga (HTML) | ? | ? |
| Está en oferta (sí/no) | ? | ? |

<details>
<summary>Ver solución</summary>

| Campo | `type` | `input` | Por qué |
|---|---|---|---|
| Peso (0.750 kg) | `decimal` | `text` | Decimal con precisión para pesos. Backend decimal usa `catalog_product_entity_decimal`. El campo de edición es un texto numérico. |
| Tallas múltiples | `varchar` | `multiselect` | Multiselect guarda IDs separados por coma en varchar. `int` no sirve porque son múltiples valores. |
| Fecha de caducidad | `datetime` | `date` | `datetime` en backend, `date` como input muestra un datepicker. Se guarda en `catalog_product_entity_datetime`. |
| Descripción larga HTML | `text` | `textarea` | `text` = MEDIUMTEXT en MySQL (hasta 16MB). `textarea` activa el editor WYSIWYG en el admin. |
| Está en oferta | `int` | `boolean` | Boolean es 0/1, se guarda como int. El input `boolean` muestra un toggle Si/No en el admin. |

**Regla mnemotécnica**:
```
Número entero/booleano  → type=int
Número con decimales    → type=decimal
Texto corto (<255)      → type=varchar
Texto largo (HTML)      → type=text
Fecha                   → type=datetime
Selección única         → type=int (FK a opciones)
Selección múltiple      → type=varchar (comas)
```

</details>
