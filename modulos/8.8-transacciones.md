## Por qué las transacciones importan

```php
// Sin transacción — qué pasa si falla el paso 2?
$this->postRepository->save($post);          // paso 1: OK
$this->categoryPivotResource->save($pivot);  // paso 2: FALLA
// Resultado: el post existe pero sin categoría — estado inconsistente en DB
```

Una transacción garantiza **atomicidad**: o todo se guarda, o nada.

🔄 **Laravel**: `DB::transaction(function() { ... })` o `DB::beginTransaction()`.

En Magento la API es muy similar:

```php
$connection->beginTransaction();
try {
    // ... operaciones ...
    $connection->commit();
} catch (\Exception $e) {
    $connection->rollBack();
    throw $e;
}
```

## Transacción básica con ResourceConnection

```php
use Magento\Framework\App\ResourceConnection;

class PostService
{
    public function __construct(
        private readonly ResourceConnection $resourceConnection,
        private readonly PostRepositoryInterface $postRepository
    ) {}

    public function createPostWithCategories(
        PostInterface $post,
        array $categoryIds
    ): PostInterface {
        $connection = $this->resourceConnection->getConnection();

        $connection->beginTransaction();
        try {
            // Guardar el post
            $savedPost = $this->postRepository->save($post);

            // Insertar relaciones de categoría
            $pivotTable = $connection->getTableName('mivendor_blog_post_category');
            $rows = array_map(
                fn($catId) => ['post_id' => $savedPost->getPostId(), 'category_id' => $catId],
                $categoryIds
            );
            $connection->insertMultiple($pivotTable, $rows);

            $connection->commit();
            return $savedPost;

        } catch (\Exception $e) {
            $connection->rollBack();
            throw new \Magento\Framework\Exception\CouldNotSaveException(
                __('Could not create post with categories: %1', $e->getMessage()),
                $e
            );
        }
    }
}
```

## Transacciones anidadas

Magento soporta transacciones anidadas con savepoints. Si el Repository interno llama a `beginTransaction()` dentro de una transacción ya activa, Magento crea un savepoint:

```php
$connection->beginTransaction();  // → BEGIN
    $connection->beginTransaction();  // → SAVEPOINT magento_savepoint_1
        // operaciones
    $connection->commit();            // → RELEASE SAVEPOINT magento_savepoint_1
$connection->commit();            // → COMMIT (el real)
```

Si el rollback ocurre en el nivel anidado:
```php
$connection->rollBack();  // → ROLLBACK TO SAVEPOINT magento_savepoint_1
```

En la práctica, esto significa que puedes llamar a Repositories que internamente usan transacciones sin preocuparte por conflictos.

## El patrón de transacción en ResourceModel

`AbstractDb` de Magento ya implementa transacciones internamente en `save()` y `delete()`. Pero cuando necesitas operaciones multi-tabla, envuelves todo tú:

```php
class PostResource extends AbstractDb
{
    // _beforeSave, _afterSave — hooks del ResourceModel
    protected function _afterSave(\Magento\Framework\Model\AbstractModel $object): self
    {
        // Esto corre DENTRO de la transacción de save()
        parent::_afterSave($object);

        // Sincronizar tabla de tags — seguro porque ya estamos en transacción
        $this->syncTags($object);

        return $this;
    }

    private function syncTags(Post $post): void
    {
        $connection = $this->getConnection();
        $tagTable = $this->getTable('mivendor_blog_post_tag');

        // Eliminar tags actuales
        $connection->delete($tagTable, ['post_id = ?' => $post->getId()]);

        // Insertar nuevos
        $tags = $post->getData('tags') ?? [];
        if (!empty($tags)) {
            $rows = array_map(
                fn($tagId) => ['post_id' => $post->getId(), 'tag_id' => $tagId],
                $tags
            );
            $connection->insertMultiple($tagTable, $rows);
        }
    }
}
```

## Manejo correcto de excepciones de DB

```php
use Magento\Framework\Exception\CouldNotSaveException;
use Magento\Framework\Exception\CouldNotDeleteException;
use Magento\Framework\Exception\NoSuchEntityException;

class PostRepository implements PostRepositoryInterface
{
    public function save(PostInterface $post): PostInterface
    {
        try {
            $this->postResource->save($post);
        } catch (\Magento\Framework\Exception\LocalizedException $e) {
            // Excepciones de Magento — re-lanzar directamente
            throw $e;
        } catch (\Exception $e) {
            // Excepciones genéricas de PHP/MySQL — envolver
            throw new CouldNotSaveException(
                __('Could not save post: %1', $e->getMessage()),
                $e  // ← exception anterior como $previous para el stack trace
            );
        }

        return $post;
    }

    public function delete(PostInterface $post): bool
    {
        try {
            $this->postResource->delete($post);
        } catch (\Exception $e) {
            throw new CouldNotDeleteException(
                __('Could not delete post with ID "%1": %2', $post->getPostId(), $e->getMessage()),
                $e
            );
        }

        return true;
    }
}
```

## Deadlocks: detección y retry

En sistemas con alta concurrencia, los deadlocks son inevitables. La solución correcta es reintentar:

```php
class PostService
{
    private const MAX_RETRIES = 3;

    public function saveWithRetry(PostInterface $post): PostInterface
    {
        $attempt = 0;
        $lastException = null;

        while ($attempt < self::MAX_RETRIES) {
            try {
                return $this->postRepository->save($post);
            } catch (\Magento\Framework\Exception\CouldNotSaveException $e) {
                $lastException = $e;

                // Detectar si es un deadlock
                if ($this->isDeadlock($e)) {
                    $attempt++;
                    $this->logger->warning(
                        sprintf('Deadlock detected, retry %d/%d', $attempt, self::MAX_RETRIES)
                    );
                    // Espera exponencial: 100ms, 200ms, 400ms
                    usleep(100000 * (2 ** ($attempt - 1)));
                    continue;
                }

                // No es deadlock — no reintentar
                throw $e;
            }
        }

        throw new \Magento\Framework\Exception\CouldNotSaveException(
            __('Could not save post after %1 attempts due to deadlock.', self::MAX_RETRIES),
            $lastException
        );
    }

    private function isDeadlock(\Exception $e): bool
    {
        // MySQL error 1213: Deadlock found when trying to get lock
        return strpos($e->getMessage(), '1213') !== false
            || strpos($e->getMessage(), 'Deadlock') !== false;
    }
}
```

## Integridad referencial: manejar FK violations

```php
public function deleteCategory(int $categoryId): bool
{
    $connection = $this->resourceConnection->getConnection();

    $connection->beginTransaction();
    try {
        // Verificar si hay posts asociados ANTES de eliminar
        $postCount = (int) $connection->fetchOne(
            $connection->select()
                ->from($connection->getTableName('mivendor_blog_post_category'), ['COUNT(*)'])
                ->where('category_id = ?', $categoryId)
        );

        if ($postCount > 0) {
            $connection->rollBack();
            throw new \Magento\Framework\Exception\LocalizedException(
                __('Cannot delete category: it has %1 associated post(s).', $postCount)
            );
        }

        $this->categoryRepository->deleteById($categoryId);
        $connection->commit();
        return true;

    } catch (\Magento\Framework\Exception\LocalizedException $e) {
        $connection->rollBack();
        throw $e;
    } catch (\Exception $e) {
        $connection->rollBack();
        throw new \Magento\Framework\Exception\CouldNotDeleteException(
            __('Could not delete category: %1', $e->getMessage()),
            $e
        );
    }
}
```

## Operaciones masivas con chunking

Para procesar miles de registros, nunca cargues todo en memoria:

```php
public function deactivateOldPosts(\DateTime $before): int
{
    $connection = $this->resourceConnection->getConnection();
    $table = $connection->getTableName('mivendor_blog_post');
    $chunkSize = 500;
    $totalUpdated = 0;

    do {
        $connection->beginTransaction();
        try {
            // Actualizar en chunks — evita timeouts y locks prolongados
            $updated = $connection->update(
                $table,
                ['is_active' => 0],
                [
                    'is_active = ?'    => 1,
                    'created_at < ?'   => $before->format('Y-m-d H:i:s'),
                    'post_id IN (?)'   => $connection->select()
                        ->from($table, ['post_id'])
                        ->where('is_active = ?', 1)
                        ->where('created_at < ?', $before->format('Y-m-d H:i:s'))
                        ->limit($chunkSize),
                ]
            );

            $connection->commit();
            $totalUpdated += $updated;

        } catch (\Exception $e) {
            $connection->rollBack();
            throw $e;
        }

    } while ($updated === $chunkSize); // Si actualizó el chunk completo, puede haber más

    return $totalUpdated;
}
```

## Logging de errores de DB

```php
use Psr\Log\LoggerInterface;

class PostRepository implements PostRepositoryInterface
{
    public function __construct(
        // ...
        private readonly LoggerInterface $logger
    ) {}

    public function save(PostInterface $post): PostInterface
    {
        try {
            $this->postResource->save($post);
        } catch (\Exception $e) {
            // Loguear el contexto completo para debugging
            $this->logger->critical('Failed to save post', [
                'post_id'   => $post->getPostId(),
                'post_title'=> $post->getTitle(),
                'error'     => $e->getMessage(),
                'trace'     => $e->getTraceAsString(),
            ]);

            throw new CouldNotSaveException(
                __('Could not save the post.'),
                $e
            );
        }

        return $post;
    }
}
```

## Resumen

```
Transacción básica:
  beginTransaction() → operaciones → commit()
  En catch: rollBack() → re-throw

Reglas:
  Siempre hacer rollBack() en el catch antes de re-throw
  Siempre pasar $e como segundo argumento al construir excepciones (preserva stack trace)
  Nunca catch(\Exception) sin re-throw — pierdes el error original

Deadlocks:
  Son normales en sistemas concurrentes
  Solución: reintentar con backoff exponencial
  Detectar por el código MySQL 1213 en el mensaje

Chunking:
  Procesar en lotes de 500-1000 para operaciones masivas
  Evita timeouts de DB y memory exhaustion

Integridad referencial:
  Verificar constraints ANTES de ejecutar
  Preferir mensajes claros (LocalizedException) sobre errores de FK crípticos
```

## Ejercicios

### Ejercicio 1 — Transacción multi-tabla

Escribe un servicio `PublishPost` que, en una sola transacción:
1. Cambie `is_active = 1` en el post
2. Cree un registro en `mivendor_blog_activity` con `{type: 'publish', post_id, created_at}`
3. Haga rollback si cualquiera de los dos falla

<details>
<summary>Ver solución</summary>

```php
<?php
namespace MiVendor\Blog\Model;

use Magento\Framework\App\ResourceConnection;
use MiVendor\Blog\Api\PostRepositoryInterface;
use Magento\Framework\Exception\CouldNotSaveException;

class PublishPost
{
    public function __construct(
        private readonly PostRepositoryInterface $postRepository,
        private readonly ResourceConnection $resourceConnection
    ) {}

    public function execute(int $postId): void
    {
        $connection = $this->resourceConnection->getConnection();

        $connection->beginTransaction();
        try {
            // Paso 1: activar el post
            $post = $this->postRepository->getById($postId);
            $post->setIsActive(true);
            $this->postRepository->save($post);

            // Paso 2: registrar en activity log
            $activityTable = $connection->getTableName('mivendor_blog_activity');
            $connection->insert($activityTable, [
                'type'       => 'publish',
                'post_id'    => $postId,
                'created_at' => date('Y-m-d H:i:s'),
            ]);

            $connection->commit();

        } catch (\Exception $e) {
            $connection->rollBack();
            throw new CouldNotSaveException(
                __('Could not publish post ID %1: %2', $postId, $e->getMessage()),
                $e
            );
        }
    }
}
```

**Nota sobre transacciones anidadas**: `$this->postRepository->save()` internamente llama a `AbstractDb::save()` que también hace `beginTransaction()/commit()`. Magento maneja esto con savepoints automáticamente — no se cancela el commit externo.

</details>

### Ejercicio 2 — Transferir posts entre autores

Escribe `transferPosts(int $fromAuthorId, int $toAuthorId, array $postIds)` que:
1. Verifique que todos los post IDs pertenecen al `fromAuthor`
2. Los transfiera al `toAuthor` en una sola transacción
3. Loguee cuántos se transfirieron

<details>
<summary>Ver solución</summary>

```php
public function transferPosts(int $fromAuthorId, int $toAuthorId, array $postIds): int
{
    if (empty($postIds)) {
        return 0;
    }

    $connection = $this->resourceConnection->getConnection();
    $table = $connection->getTableName('mivendor_blog_post');

    $connection->beginTransaction();
    try {
        // Verificar que todos los IDs pertenecen al fromAuthor
        $validIds = $connection->fetchCol(
            $connection->select()
                ->from($table, ['post_id'])
                ->where('post_id IN (?)', $postIds)
                ->where('author_id = ?', $fromAuthorId)
        );

        $invalidIds = array_diff($postIds, $validIds);
        if (!empty($invalidIds)) {
            throw new \Magento\Framework\Exception\LocalizedException(
                __('Posts [%1] do not belong to author %2.',
                   implode(', ', $invalidIds), $fromAuthorId)
            );
        }

        // Transferir
        $transferred = $connection->update(
            $table,
            ['author_id' => $toAuthorId],
            [
                'post_id IN (?)' => $validIds,
                'author_id = ?'  => $fromAuthorId,
            ]
        );

        $connection->commit();

        $this->logger->info(sprintf(
            'Transferred %d post(s) from author %d to author %d.',
            $transferred, $fromAuthorId, $toAuthorId
        ));

        return $transferred;

    } catch (\Magento\Framework\Exception\LocalizedException $e) {
        $connection->rollBack();
        throw $e;
    } catch (\Exception $e) {
        $connection->rollBack();
        throw new \Magento\Framework\Exception\CouldNotSaveException(
            __('Transfer failed: %1', $e->getMessage()),
            $e
        );
    }
}
```

**Por qué validar antes del UPDATE**: Si pasas IDs de posts de otro autor, el `WHERE author_id = ?` los ignora silenciosamente — no hay error. Verificar antes da un mensaje claro al caller.

</details>
