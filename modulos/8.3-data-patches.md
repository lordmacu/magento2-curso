## Patches vs Migrations de Laravel

🔄 **Laravel**: Los seeders insertan datos, las migrations modifican el schema. Las migrations tienen `up()` y `down()`.

En Magento hay dos tipos de patch:

```
DataPatch    →  Inserta o modifica DATOS (filas en tablas)
SchemaPatch  →  Modifica el SCHEMA cuando db_schema.xml no alcanza (raro)

Ambos:
  - Se ejecutan UNA SOLA VEZ — Magento los registra en patch_list
  - No tienen "rollback" explícito (no hay down())
  - Pueden declarar dependencias entre sí
```

## Data Patch básico

```php
<?php
// app/code/MiVendor/Blog/Setup/Patch/Data/InsertDefaultCategory.php
namespace MiVendor\Blog\Setup\Patch\Data;

use Magento\Framework\Setup\Patch\DataPatchInterface;
use MiVendor\Blog\Model\CategoryFactory;
use MiVendor\Blog\Model\ResourceModel\Category;

class InsertDefaultCategory implements DataPatchInterface
{
    public function __construct(
        private readonly CategoryFactory $categoryFactory,
        private readonly Category $categoryResource
    ) {}

    /**
     * Qué hace este patch — se ejecuta UNA SOLA VEZ
     */
    public function apply(): void
    {
        $category = $this->categoryFactory->create();
        $category->setName('General');
        $category->setUrlKey('general');
        $category->setIsActive(true);
        $category->setSortOrder(0);
        $this->categoryResource->save($category);
    }

    /**
     * Dependencias — otros patches que deben ejecutarse ANTES
     */
    public static function getDependencies(): array
    {
        return [];
    }

    /**
     * Aliases — nombres anteriores de este patch (para migraciones de nombre)
     */
    public function getAliases(): array
    {
        return [];
    }
}
```

## Cómo Magento registra los patches

```sql
-- Magento guarda en la tabla patch_list:
SELECT * FROM patch_list;
-- | patch_name                                              | applied |
-- | MiVendor\Blog\Setup\Patch\Data\InsertDefaultCategory   | 1       |

-- Si el patch ya está ahí, NO se vuelve a ejecutar
-- aunque modifiques el código del patch
```

```bash
# Ejecutar todos los patches pendientes
php bin/magento setup:upgrade

# Ver qué patches se aplicarán sin ejecutarlos
php bin/magento setup:upgrade --dry-run
```

## Dependencias entre patches

```php
<?php
// InsertDefaultPosts.php — depende de InsertDefaultCategory
namespace MiVendor\Blog\Setup\Patch\Data;

class InsertDefaultPosts implements DataPatchInterface
{
    public function apply(): void
    {
        // Aquí puedes asumir que la categoría "General" ya existe
        $this->postFactory->create()
            ->setTitle('Bienvenido a MiVendor Blog')
            ->setCategoryId(1)
            ->setIsActive(true);
        // ...
    }

    public static function getDependencies(): array
    {
        // Magento garantiza que InsertDefaultCategory se ejecutó antes
        return [InsertDefaultCategory::class];
    }

    public function getAliases(): array
    {
        return [];
    }
}
```

## Usar el ResourceModel directo (más eficiente)

Para insertar muchos registros, mejor usar el connection directo que Models individuales:

```php
<?php
namespace MiVendor\Blog\Setup\Patch\Data;

use Magento\Framework\Setup\Patch\DataPatchInterface;
use Magento\Framework\App\ResourceConnection;

class InsertCountries implements DataPatchInterface
{
    public function __construct(
        private readonly ResourceConnection $resourceConnection
    ) {}

    public function apply(): void
    {
        $connection = $this->resourceConnection->getConnection();
        $tableName  = $connection->getTableName('mivendor_blog_country');

        // INSERT múltiple en un solo query — mucho más rápido que Models
        $connection->insertMultiple($tableName, [
            ['code' => 'MX', 'name' => 'México',         'is_active' => 1],
            ['code' => 'CO', 'name' => 'Colombia',       'is_active' => 1],
            ['code' => 'AR', 'name' => 'Argentina',      'is_active' => 1],
            ['code' => 'ES', 'name' => 'España',         'is_active' => 1],
            ['code' => 'US', 'name' => 'United States',  'is_active' => 1],
        ]);
    }

    public static function getDependencies(): array { return []; }
    public function getAliases(): array { return []; }
}
```

## Modificar configuración del sistema

Un uso frecuente es configurar valores del panel de admin durante la instalación:

```php
<?php
namespace MiVendor\Blog\Setup\Patch\Data;

use Magento\Framework\Setup\Patch\DataPatchInterface;
use Magento\Framework\App\Config\Storage\WriterInterface;
use Magento\Framework\App\Cache\Manager as CacheManager;

class ConfigureDefaultSettings implements DataPatchInterface
{
    public function __construct(
        private readonly WriterInterface $configWriter,
        private readonly CacheManager $cacheManager
    ) {}

    public function apply(): void
    {
        // Configurar valores por defecto del módulo
        $this->configWriter->save('mivendor_blog/general/enabled', '1');
        $this->configWriter->save('mivendor_blog/general/posts_per_page', '10');
        $this->configWriter->save('mivendor_blog/seo/use_rich_snippets', '1');
        $this->configWriter->save('mivendor_blog/comments/enabled', '0');

        // Limpiar caché de configuración para que los valores estén disponibles
        $this->cacheManager->clean(['config']);
    }

    public static function getDependencies(): array { return []; }
    public function getAliases(): array { return []; }
}
```

## Migración de datos existentes

El caso más común en proyectos reales — migrar datos de una estructura antigua a la nueva:

```php
<?php
namespace MiVendor\Blog\Setup\Patch\Data;

use Magento\Framework\Setup\Patch\DataPatchInterface;
use Magento\Framework\App\ResourceConnection;
use Psr\Log\LoggerInterface;

class MigratePostsToNewSchema implements DataPatchInterface
{
    public function __construct(
        private readonly ResourceConnection $resourceConnection,
        private readonly LoggerInterface $logger
    ) {}

    public function apply(): void
    {
        $connection = $this->resourceConnection->getConnection();

        // Leer de la tabla vieja
        $oldTable = $connection->getTableName('mivendor_blog_post_old');
        $newTable = $connection->getTableName('mivendor_blog_post');

        $select = $connection->select()
            ->from($oldTable, ['id', 'post_title', 'post_content', 'active'])
            ->where('post_content IS NOT NULL');

        $rows = $connection->fetchAll($select);
        $this->logger->info(sprintf('Migrating %d posts...', count($rows)));

        foreach ($rows as $row) {
            try {
                $connection->insert($newTable, [
                    'title'      => $row['post_title'],
                    'content'    => $row['post_content'],
                    'is_active'  => (int) $row['active'],
                    'url_key'    => $this->generateUrlKey($row['post_title']),
                    'created_at' => date('Y-m-d H:i:s'),
                ]);
            } catch (\Exception $e) {
                $this->logger->error(
                    'Failed to migrate post ID ' . $row['id'] . ': ' . $e->getMessage()
                );
            }
        }
    }

    private function generateUrlKey(string $title): string
    {
        return strtolower(preg_replace('/[^a-zA-Z0-9]+/', '-', $title));
    }

    public static function getDependencies(): array { return []; }
    public function getAliases(): array { return []; }
}
```

## Patch que puede "revertirse": `PatchRevertableInterface`

```php
<?php
use Magento\Framework\Setup\Patch\DataPatchInterface;
use Magento\Framework\Setup\Patch\PatchRevertableInterface;

class AddFeaturedAttribute implements DataPatchInterface, PatchRevertableInterface
{
    public function apply(): void
    {
        // Agregar atributo EAV al producto
        $this->eavSetup->addAttribute(\Magento\Catalog\Model\Product::ENTITY, 'is_featured', [
            'type'    => 'int',
            'label'   => 'Is Featured',
            'input'   => 'boolean',
            'default' => 0,
        ]);
    }

    public function revert(): void
    {
        // Revertir — eliminar el atributo
        $this->eavSetup->removeAttribute(\Magento\Catalog\Model\Product::ENTITY, 'is_featured');
    }

    public static function getDependencies(): array { return []; }
    public function getAliases(): array { return []; }
}
```

```bash
# Revertir un patch específico (raro en producción, útil en desarrollo)
php bin/magento setup:rollback --data-restore-file=path/to/db_backup.sql
```

## Schema Patch: cuándo usarlo

Los Schema Patches son para modificaciones de schema que `db_schema.xml` no puede expresar:

```php
<?php
use Magento\Framework\Setup\Patch\SchemaPatchInterface;
use Magento\Framework\App\ResourceConnection;

class AddFulltextIndex implements SchemaPatchInterface
{
    public function __construct(
        private readonly ResourceConnection $resourceConnection
    ) {}

    public function apply(): void
    {
        $connection = $this->resourceConnection->getConnection();
        $table = $connection->getTableName('mivendor_blog_post');

        // FULLTEXT index — no soportado en db_schema.xml
        $connection->query(
            "ALTER TABLE `{$table}` ADD FULLTEXT INDEX `FTX_TITLE_CONTENT` (`title`, `content`)"
        );
    }

    public static function getDependencies(): array { return []; }
    public function getAliases(): array { return []; }
}
```


## Resumen

```
DataPatch      →  Insertar/migrar datos
SchemaPatch    →  Modificar schema (cuando db_schema.xml no alcanza)

Cada patch:
  apply()             →  lógica del patch
  getDependencies()   →  patches que deben ejecutarse antes
  getAliases()        →  nombres anteriores (migraciones de nombre)

Se ejecutan con:
  php bin/magento setup:upgrade

Solo se ejecutan UNA VEZ — Magento los registra en patch_list.
Para re-ejecutar en desarrollo:
  DELETE FROM patch_list WHERE patch_name = 'MiVendor\\Blog\\Setup\\Patch\\Data\\MiPatch';
  php bin/magento setup:upgrade
```

### Ejercicio 1 — Data Patch con configuración inicial

Crea un Data Patch `InitialConfiguration` para el módulo `MiVendor_Blog` que:
1. Configure `mivendor_blog/general/posts_per_page` = `10`
2. Configure `mivendor_blog/seo/canonical_enabled` = `1`
3. Limpie la caché de configuración al final

<details>
<summary>Ver solución</summary>

```php
<?php
namespace MiVendor\Blog\Setup\Patch\Data;

use Magento\Framework\Setup\Patch\DataPatchInterface;
use Magento\Framework\App\Config\Storage\WriterInterface;
use Magento\Framework\App\Cache\Manager as CacheManager;

class InitialConfiguration implements DataPatchInterface
{
    public function __construct(
        private readonly WriterInterface $configWriter,
        private readonly CacheManager $cacheManager
    ) {}

    public function apply(): void
    {
        $this->configWriter->save('mivendor_blog/general/posts_per_page', '10');
        $this->configWriter->save('mivendor_blog/seo/canonical_enabled', '1');

        // Limpiar solo la caché de configuración — no toda la caché
        $this->cacheManager->clean(['config']);
    }

    public static function getDependencies(): array
    {
        return [];
    }

    public function getAliases(): array
    {
        return [];
    }
}
```

```bash
php bin/magento setup:upgrade

# Verificar que se aplicó:
SELECT * FROM patch_list WHERE patch_name LIKE '%InitialConfiguration%';
# → MiVendor\Blog\Setup\Patch\Data\InitialConfiguration

# Verificar los valores:
php bin/magento config:show mivendor_blog/general/posts_per_page
# → 10
```

</details>

### Ejercicio 2 — Migración de datos con dependencia

Tienes estos dos patches pendientes:
1. `CreateDefaultCategory` — crea una categoría "Sin categoría" con ID 1
2. `AssignPostsToDefaultCategory` — asigna posts sin categoría a la categoría con ID 1

Escribe ambos patches con la dependencia correcta.

<details>
<summary>Ver solución</summary>

```php
<?php
// Setup/Patch/Data/CreateDefaultCategory.php
namespace MiVendor\Blog\Setup\Patch\Data;

use Magento\Framework\Setup\Patch\DataPatchInterface;
use Magento\Framework\App\ResourceConnection;

class CreateDefaultCategory implements DataPatchInterface
{
    public function __construct(
        private readonly ResourceConnection $resourceConnection
    ) {}

    public function apply(): void
    {
        $connection = $this->resourceConnection->getConnection();
        $table = $connection->getTableName('mivendor_blog_category');

        // Insertar solo si no existe ya (idempotente)
        $exists = $connection->fetchOne(
            "SELECT category_id FROM `{$table}` WHERE url_key = 'uncategorized' LIMIT 1"
        );

        if (!$exists) {
            $connection->insert($table, [
                'name'       => 'Sin categoría',
                'url_key'    => 'uncategorized',
                'is_active'  => 1,
                'sort_order' => 999,
            ]);
        }
    }

    public static function getDependencies(): array
    {
        return [];
    }

    public function getAliases(): array
    {
        return [];
    }
}
```

```php
<?php
// Setup/Patch/Data/AssignPostsToDefaultCategory.php
namespace MiVendor\Blog\Setup\Patch\Data;

use Magento\Framework\Setup\Patch\DataPatchInterface;
use Magento\Framework\App\ResourceConnection;

class AssignPostsToDefaultCategory implements DataPatchInterface
{
    public function __construct(
        private readonly ResourceConnection $resourceConnection
    ) {}

    public function apply(): void
    {
        $connection = $this->resourceConnection->getConnection();
        $catTable   = $connection->getTableName('mivendor_blog_category');
        $pivotTable = $connection->getTableName('mivendor_blog_post_category');
        $postTable  = $connection->getTableName('mivendor_blog_post');

        // Obtener el ID de la categoría por defecto
        $defaultCategoryId = (int) $connection->fetchOne(
            "SELECT category_id FROM `{$catTable}` WHERE url_key = 'uncategorized' LIMIT 1"
        );

        if (!$defaultCategoryId) {
            return; // La categoría no existe — no debería pasar gracias a la dependencia
        }

        // Posts que no tienen ninguna categoría asignada
        $postsWithoutCategory = $connection->fetchCol(
            "SELECT p.post_id FROM `{$postTable}` p
             LEFT JOIN `{$pivotTable}` pc ON p.post_id = pc.post_id
             WHERE pc.post_id IS NULL"
        );

        if (empty($postsWithoutCategory)) {
            return;
        }

        $rows = array_map(
            fn($postId) => ['post_id' => $postId, 'category_id' => $defaultCategoryId],
            $postsWithoutCategory
        );

        $connection->insertMultiple($pivotTable, $rows);
    }

    public static function getDependencies(): array
    {
        // Garantiza que CreateDefaultCategory se ejecutó primero
        return [CreateDefaultCategory::class];
    }

    public function getAliases(): array
    {
        return [];
    }
}
```

```bash
php bin/magento setup:upgrade
# Magento ejecuta CreateDefaultCategory primero, luego AssignPostsToDefaultCategory
```

**Por qué la dependencia es crítica**: Sin `getDependencies()`, Magento podría ejecutar `AssignPostsToDefaultCategory` antes de `CreateDefaultCategory`, y el `fetchOne` de la categoría devolvería `null`.

</details>
