## Por qué Magento no usa `.env`

🔄 **Laravel**: Todo va en `.env` → `config/app.php` lee esas variables → `config('app.key')` en tu código.

Magento tiene dos archivos en `app/etc/` que cumplen roles distintos:

```
app/etc/
├── env.php       ← Configuración de entorno (secrets, DB, Redis, Elasticsearch)
│                    NO se sube a git — como tu .env
├── config.php    ← Lista de módulos habilitados + configuración exportada
│                    SÍ se sube a git — como tu config/app.php
└── di.xml        ← DI global (pocas veces se toca manualmente)
```

## env.php — El equivalente al .env

```php
// app/etc/env.php
<?php
return [
    // ── Base de datos ──────────────────────────────────────────
    'db' => [
        'table_prefix' => '',
        'connection' => [
            'default' => [
                'host'     => 'db',
                'dbname'   => 'magento',
                'username' => 'magento',
                'password' => 'magento',
                'model'    => 'mysql4',
                'engine'   => 'innodb',
                'initStatements' => 'SET NAMES utf8;',
                'active'   => '1',
                'driver_options' => [
                    1014 => false
                ]
            ]
        ]
    ],

    // ── Redis — caché ──────────────────────────────────────────
    'cache' => [
        'frontend' => [
            'default' => [
                'backend' => 'Magento\\Framework\\Cache\\Backend\\Redis',
                'backend_options' => [
                    'server'   => 'redis',
                    'port'     => '6379',
                    'database' => '0',
                ]
            ],
            'page_cache' => [
                'backend' => 'Magento\\Framework\\Cache\\Backend\\Redis',
                'backend_options' => [
                    'server'   => 'redis',
                    'port'     => '6379',
                    'database' => '1',
                ]
            ]
        ]
    ],

    // ── Redis — sesiones ───────────────────────────────────────
    'session' => [
        'save' => 'redis',
        'redis' => [
            'host'     => 'redis',
            'port'     => '6379',
            'database' => '2',
        ]
    ],

    // ── Elasticsearch ──────────────────────────────────────────
    'system' => [
        'default' => [
            'catalog' => [
                'search' => [
                    'engine'              => 'elasticsearch7',
                    'elasticsearch7_server_hostname' => 'elasticsearch',
                    'elasticsearch7_server_port'     => '9200',
                ]
            ]
        ]
    ],

    // ── Claves y URLs ──────────────────────────────────────────
    'crypt' => [
        'key' => 'tu-clave-de-encriptacion-aqui'
    ],

    'backend' => [
        'frontName' => 'admin'   // La URL del panel admin: /admin
    ],

    // ── Modo de la aplicación ──────────────────────────────────
    'MAGE_MODE' => 'developer',   // developer | production | default

    // ── Caché de configuración (genera generated/) ─────────────
    'cache_types' => [
        'config'             => 1,
        'layout'             => 1,
        'block_html'         => 1,
        'collections'        => 1,
        'reflection'         => 1,
        'db_ddl'             => 1,
        'compiled_config'    => 1,
        'eav'                => 1,
        'customer_notification' => 1,
        'config_integration' => 1,
        'config_integration_api' => 1,
        'full_page'          => 1,
        'config_webservice'  => 1,
        'translate'          => 1,
    ],

    // ── Instalación ────────────────────────────────────────────
    'install' => [
        'date' => 'Sun, 06 Apr 2024 00:00:00 +0000'
    ],
];
```

### Lo que NO debes tocar manualmente en env.php

- `crypt.key` — si lo cambias, pierdes todos los datos encriptados (contraseñas de pago, API keys guardadas)
- `install.date` — Magento lo usa para detectar si está instalado
- `cache_types` — usa `bin/magento cache:enable/disable`

## config.php — La configuración versionada

```php
// app/etc/config.php
<?php
return [
    'modules' => [
        'Magento_Store'           => 1,
        'Magento_Catalog'         => 1,
        'Magento_Checkout'        => 1,
        // ... todos los módulos habilitados (1) o deshabilitados (0)
        'MiVendor_MiModulo'       => 1,
    ]
];
```

Este archivo se genera con `php bin/magento module:enable` y `setup:upgrade`. **Sí se versiona en git** — es la fuente de verdad de qué módulos están activos en el proyecto.

### Exportar configuración del admin a config.php

Magento permite exportar la configuración del panel de admin (Settings → Configuration) a `config.php` para que sea versionada y reproducible:

```bash
# Exportar toda la configuración del admin a config.php
php bin/magento app:config:dump

# Solo exportar módulos (lo más común)
php bin/magento app:config:dump scopes themes

# Importar en otro entorno (ej: al hacer deploy)
php bin/magento app:config:import
```

Esto es poderoso para entornos múltiples: configuras en staging, haces dump, el deploy lo importa automáticamente en producción.

## Leer configuración en código

La configuración del panel de admin (guardada en `core_config_data`) se accede vía `ScopeConfigInterface`:

```php
namespace MiVendor\MiModulo\Model;

use Magento\Framework\App\Config\ScopeConfigInterface;
use Magento\Store\Model\ScopeInterface;

class MiServicio
{
    // Paths de configuración — los defines en system.xml (módulo 10.6)
    private const CONFIG_ENABLED  = 'mimodulo/general/enabled';
    private const CONFIG_API_KEY  = 'mimodulo/api/key';
    private const CONFIG_MAX_ITEMS = 'mimodulo/performance/max_items';

    public function __construct(
        private readonly ScopeConfigInterface $scopeConfig
    ) {}

    public function isEnabled(?int $storeId = null): bool
    {
        return $this->scopeConfig->isSetFlag(
            self::CONFIG_ENABLED,
            ScopeInterface::SCOPE_STORE,
            $storeId
        );
    }

    public function getApiKey(?int $storeId = null): string
    {
        return (string) $this->scopeConfig->getValue(
            self::CONFIG_API_KEY,
            ScopeInterface::SCOPE_STORE,
            $storeId
        );
    }

    public function getMaxItems(): int
    {
        return (int) $this->scopeConfig->getValue(
            self::CONFIG_MAX_ITEMS,
            ScopeInterface::SCOPE_STORE
        );
    }
}
```

### Los scopes de configuración

```php
// Leer a nivel global (default)
$this->scopeConfig->getValue('path/to/config');
$this->scopeConfig->getValue('path/to/config', ScopeConfigInterface::SCOPE_TYPE_DEFAULT);

// Leer para un website específico
$this->scopeConfig->getValue('path/to/config', ScopeInterface::SCOPE_WEBSITE, 'base');

// Leer para una store view específica (el más común)
$this->scopeConfig->getValue('path/to/config', ScopeInterface::SCOPE_STORE, 1);
$this->scopeConfig->getValue('path/to/config', ScopeInterface::SCOPE_STORE, 'default');

// isSetFlag — para valores booleanos (0/1)
$this->scopeConfig->isSetFlag('catalog/frontend/flat_catalog_product', ScopeInterface::SCOPE_STORE);
```

## Escribir configuración por código

```php
use Magento\Framework\App\Config\Storage\WriterInterface;

class Instalador
{
    public function __construct(
        private readonly WriterInterface $configWriter
    ) {}

    public function configurarDefaults(): void
    {
        // Escribir a nivel global
        $this->configWriter->save(
            'mimodulo/general/enabled',
            '1'
        );

        // Escribir para un scope específico
        $this->configWriter->save(
            'mimodulo/api/endpoint',
            'https://api.ejemplo.com',
            \Magento\Store\Model\ScopeInterface::SCOPE_WEBSITE,
            1   // website_id
        );

        // Después de escribir, limpiar caché de config
        // (normalmente lo haces en un Data Patch — módulo 8.3)
    }
}
```

## Valores de configuración bloqueados (lock)

Puedes bloquear valores para que no se puedan cambiar desde el admin:

```bash
# Bloquear en env.php (más prioritario, no editable desde el admin)
php bin/magento config:set --lock-env web/unsecure/base_url "https://mitienda.com/"

# Bloquear en config.php (editable con app:config:import)
php bin/magento config:set --lock-config web/secure/use_in_frontend 1
```

En `env.php` queda como:
```php
'system' => [
    'default' => [
        'web' => [
            'unsecure' => [
                'base_url' => 'https://mitienda.com/'
            ]
        ]
    ]
]
```

Los valores bloqueados aparecen en gris en el admin con el mensaje "locked by system configuration".

## Prioridad de configuración

Cuando Magento lee un valor de configuración, sigue esta jerarquía (mayor número = mayor prioridad):

```
1. Valor por defecto en config.xml del módulo  (menor prioridad)
2. Valor en core_config_data con scope=default
3. Valor en core_config_data con scope=website
4. Valor en core_config_data con scope=store    (mayor scope)
5. Valor en config.php (--lock-config)
6. Valor en env.php    (--lock-env)              (mayor prioridad)
```

🔄 **Laravel**: Es similar a tener valores default en `config/`, que se sobreescriben por `.env`, que se sobreescriben por variables de entorno del sistema.

## config.xml — Valores por defecto de tu módulo

Para que tu módulo tenga valores default sin necesidad de que el admin los configure:

```xml
<!-- app/code/MiVendor/MiModulo/etc/config.xml -->
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:module:Magento_Store:etc/config.xsd">
    <default>
        <mimodulo>
            <general>
                <enabled>1</enabled>
            </general>
            <performance>
                <max_items>100</max_items>
                <cache_lifetime>3600</cache_lifetime>
            </performance>
            <api>
                <timeout>30</timeout>
                <retries>3</retries>
            </api>
        </mimodulo>
    </default>
</config>
```

Estos valores se leen con `ScopeConfigInterface` exactamente igual que los del admin. Son el nivel más bajo de la jerarquía.

## Resumen

```
archivo         versionado    propósito
──────────────────────────────────────────────────────────────
env.php         NO (gitignore) DB, Redis, keys, modo MAGE_MODE
config.php      SÍ            Lista de módulos, config exportada del admin
config.xml      SÍ            Valores default de tu módulo
core_config_data (DB)         Valores configurados desde el admin panel
```

### Leer configuración — cheat sheet

```php
// Leer valor (string/int)
$this->scopeConfig->getValue('section/group/field', ScopeInterface::SCOPE_STORE);

// Leer booleano
$this->scopeConfig->isSetFlag('section/group/field', ScopeInterface::SCOPE_STORE);

// Escribir
$this->configWriter->save('section/group/field', 'value');

// CLI — leer
php bin/magento config:show section/group/field

// CLI — escribir
php bin/magento config:set section/group/field value
```

## Ejercicios

### Ejercicio 1 — Leer configuración por scope

Tienes un módulo con estas rutas de configuración:

```
mimodulo/general/enabled     → boolean
mimodulo/api/key             → string
mimodulo/performance/limit   → int
```

Escribe un servicio PHP que lea los tres valores correctamente, manejando el scope de store view.

<details>
<summary>Ver solución</summary>

```php
// Model/ConfigProvider.php
namespace MiVendor\MiModulo\Model;

use Magento\Framework\App\Config\ScopeConfigInterface;
use Magento\Store\Model\ScopeInterface;

class ConfigProvider
{
    private const PATH_ENABLED = 'mimodulo/general/enabled';
    private const PATH_API_KEY = 'mimodulo/api/key';
    private const PATH_LIMIT   = 'mimodulo/performance/limit';

    public function __construct(
        private readonly ScopeConfigInterface $scopeConfig
    ) {}

    public function isEnabled(?int $storeId = null): bool
    {
        // isSetFlag para booleans — retorna true si el valor es 1/true/yes
        return $this->scopeConfig->isSetFlag(
            self::PATH_ENABLED,
            ScopeInterface::SCOPE_STORE,
            $storeId
        );
    }

    public function getApiKey(?int $storeId = null): string
    {
        return (string) $this->scopeConfig->getValue(
            self::PATH_API_KEY,
            ScopeInterface::SCOPE_STORE,
            $storeId
        );
    }

    public function getLimit(?int $storeId = null): int
    {
        return (int) $this->scopeConfig->getValue(
            self::PATH_LIMIT,
            ScopeInterface::SCOPE_STORE,
            $storeId
        );
    }
}
```

```bash
# Verificar desde CLI:
php bin/magento config:show mimodulo/general/enabled
php bin/magento config:show mimodulo/api/key

# Establecer un valor para probar:
php bin/magento config:set mimodulo/general/enabled 1
php bin/magento config:set mimodulo/performance/limit 50
php bin/magento cache:flush
```

</details>

### Ejercicio 2 — Valores por defecto con config.xml

Sin configurar nada desde el panel de admin, haz que `mimodulo/general/enabled` sea `1` y `mimodulo/performance/limit` sea `100` por defecto.

<details>
<summary>Ver solución</summary>

```xml
<!-- app/code/MiVendor/MiModulo/etc/config.xml -->
<?xml version="1.0"?>
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:module:Magento_Store:etc/config.xsd">
    <default>
        <mimodulo>
            <general>
                <enabled>1</enabled>
            </general>
            <performance>
                <limit>100</limit>
            </performance>
        </mimodulo>
    </default>
</config>
```

```bash
php bin/magento cache:flush

# Verificar — aunque nunca hayas guardado nada en el admin:
php bin/magento config:show mimodulo/general/enabled
# → 1

php bin/magento config:show mimodulo/performance/limit
# → 100
```

**Cómo funciona**: `config.xml` es el nivel más bajo de la jerarquía de configuración. Si no hay nada en `core_config_data` ni en `env.php`, Magento usa estos valores. Es el equivalente a los valores por defecto en `config/` de Laravel.

</details>
