# 7.7 — Router Personalizado: interceptar URLs con lógica custom

> **Objetivo**: Crear routers propios para manejar URLs dinámicas que no siguen el patrón estándar `/{frontName}/{controller}/{action}` — por ejemplo, URLs SEO-friendly de posts de blog o páginas de categorías custom.

## Por qué necesitas un router custom

El router estándar de Magento resuelve URLs del tipo:
```
/blog/post/view/id/42
```

Pero en proyectos reales necesitas URLs como:
```
/mi-primer-post-en-magento    ← URL de un post de blog (slug dinámico)
/ofertas/verano-2024          ← Categoría custom con subcategoría
/brand/nike                   ← Página de marca
```

Ninguna de estas sigue el patrón `{frontName}/{controller}/{action}`, así que el router estándar no puede resolverlas. Para eso existe el router personalizado.

🔄 **Laravel**: En Laravel usarías `Route::get('/{slug}', ...)` con un patrón regex. En Magento declaras una clase que implementa `RouterInterface` y decides si procesas la URL o la pasas al siguiente router.

---

## Cómo funciona el sistema de routing

Magento tiene varios routers que se ejecutan en orden de prioridad:

```
1. routerList (priority):
   ├── 10  → robots.txt router
   ├── 20  → Admin router (adminhtml)
   ├── 30  → Standard router (frontName → controller → action)
   ├── 40  → CMS router (páginas y bloques de CMS)
   └── 100 → Default router (404)

Tu router custom va entre el 30 y el 100 (o antes si necesitas).
```

Cada router recibe el `Request` y puede:
- Devolver un `ActionInterface` → el request está resuelto, se ejecuta el action
- Devolver `null` → pasar al siguiente router

## Crear un router custom: paso a paso

### Paso 1 — La clase Router

```php
<?php
// app/code/MiVendor/Blog/Controller/Router.php
namespace MiVendor\Blog\Controller;

use Magento\Framework\App\ActionFactory;
use Magento\Framework\App\ActionInterface;
use Magento\Framework\App\RequestInterface;
use Magento\Framework\App\RouterInterface;
use MiVendor\Blog\Api\PostRepositoryInterface;
use Magento\Framework\Api\SearchCriteriaBuilder;

class Router implements RouterInterface
{
    public function __construct(
        private readonly ActionFactory $actionFactory,
        private readonly PostRepositoryInterface $postRepository,
        private readonly SearchCriteriaBuilder $searchCriteriaBuilder
    ) {}

    public function match(RequestInterface $request): ?ActionInterface
    {
        $identifier = trim($request->getPathInfo(), '/');

        // Solo interceptamos rutas que parecen slugs de blog
        // Ejemplo: "blog/mi-primer-post" o solo "mi-primer-post"
        if (!$this->isBlogPath($identifier)) {
            return null; // Pasar al siguiente router
        }

        $slug = $this->extractSlug($identifier);
        $post = $this->findPostBySlug($slug);

        if (!$post) {
            return null; // Post no encontrado, dejar que llegue al 404
        }

        // Reescribir el request para que apunte al controller correcto
        $request->setModuleName('blog');
        $request->setControllerName('post');
        $request->setActionName('view');
        $request->setParam('id', $post->getId());

        // Devolver el action que procesará la request
        return $this->actionFactory->create(
            \Magento\Framework\App\Action\Forward::class,
            ['request' => $request]
        );
    }

    private function isBlogPath(string $identifier): bool
    {
        // Solo procesar rutas que empiezan con "blog/"
        return str_starts_with($identifier, 'blog/');
    }

    private function extractSlug(string $identifier): string
    {
        // "blog/mi-primer-post" → "mi-primer-post"
        return substr($identifier, strlen('blog/'));
    }

    private function findPostBySlug(string $slug): ?PostInterface
    {
        $searchCriteria = $this->searchCriteriaBuilder
            ->addFilter('url_key', $slug)
            ->addFilter('is_active', 1)
            ->setPageSize(1)
            ->create();

        $result = $this->postRepository->getList($searchCriteria);
        $items = $result->getItems();

        return !empty($items) ? reset($items) : null;
    }
}
```

### Paso 2 — Registrar el router en di.xml

```xml
<!-- app/code/MiVendor/Blog/etc/frontend/di.xml -->
<?xml version="1.0"?>
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:framework:ObjectManager/etc/config.xsd">

    <type name="Magento\Framework\App\RouterList">
        <arguments>
            <argument name="routerList" xsi:type="array">
                <item name="blog" xsi:type="array">
                    <item name="class" xsi:type="string">MiVendor\Blog\Controller\Router</item>
                    <item name="disable" xsi:type="boolean">false</item>
                    <item name="sortOrder" xsi:type="string">50</item>
                </item>
            </argument>
        </arguments>
    </type>

</config>
```

**sortOrder 50**: Se ejecuta después del router estándar (30) pero antes del CMS (40) y del 404 (100). Ajusta según tus necesidades.

## Caso práctico: URL rewriting desde base de datos

Un patrón más robusto — guardar las URL rewrites en una tabla y consultarla:

```php
<?php
namespace MiVendor\Blog\Controller;

use Magento\Framework\App\RouterInterface;
use Magento\Framework\App\RequestInterface;
use Magento\Framework\App\ActionInterface;
use Magento\Framework\App\ActionFactory;
use MiVendor\Blog\Model\ResourceModel\UrlRewrite as UrlRewriteResource;

class Router implements RouterInterface
{
    public function __construct(
        private readonly ActionFactory $actionFactory,
        private readonly UrlRewriteResource $urlRewriteResource
    ) {}

    public function match(RequestInterface $request): ?ActionInterface
    {
        $pathInfo = trim($request->getPathInfo(), '/');

        // Buscar en la tabla de rewrites
        $rewrite = $this->urlRewriteResource->getByRequestPath($pathInfo);

        if (!$rewrite) {
            return null;
        }

        // Parsear la URL target: "blog/post/view/id/42"
        $targetPath = $rewrite['target_path'];
        $parts = explode('/', $targetPath);

        $request->setModuleName($parts[0] ?? '');
        $request->setControllerName($parts[1] ?? '');
        $request->setActionName($parts[2] ?? 'index');

        // Parsear parámetros adicionales: "key/value/key2/value2"
        $params = array_slice($parts, 3);
        for ($i = 0; $i < count($params) - 1; $i += 2) {
            $request->setParam($params[$i], $params[$i + 1]);
        }

        return $this->actionFactory->create(
            \Magento\Framework\App\Action\Forward::class,
            ['request' => $request]
        );
    }
}
```

```php
// Model/ResourceModel/UrlRewrite.php
namespace MiVendor\Blog\Model\ResourceModel;

use Magento\Framework\Model\ResourceModel\Db\AbstractDb;

class UrlRewrite extends AbstractDb
{
    protected function _construct(): void
    {
        $this->_init('mivendor_blog_url_rewrite', 'rewrite_id');
    }

    public function getByRequestPath(string $requestPath): ?array
    {
        $connection = $this->getConnection();
        $select = $connection->select()
            ->from($this->getMainTable())
            ->where('request_path = ?', $requestPath)
            ->limit(1);

        $row = $connection->fetchRow($select);
        return $row ?: null;
    }
}
```

## Router con redirección 301

Para manejar URLs antiguas y redirigir a las nuevas (SEO):

```php
public function match(RequestInterface $request): ?ActionInterface
{
    $pathInfo = trim($request->getPathInfo(), '/');

    $rewrite = $this->urlRewriteResource->getByRequestPath($pathInfo);

    if (!$rewrite) {
        return null;
    }

    // Si es una redirección permanente
    if ((int) $rewrite['redirect_type'] === 301) {
        // Necesitamos enviar el redirect directamente desde el router
        // Magento no tiene un mecanismo nativo aquí — usamos Response
        $response = $request->getResponse(); // No disponible directamente en RequestInterface

        // Alternativa: dispatch a un controller de redirect
        $request->setModuleName('blog');
        $request->setControllerName('redirect');
        $request->setActionName('permanent');
        $request->setParam('target', $rewrite['target_path']);

        return $this->actionFactory->create(
            \Magento\Framework\App\Action\Forward::class,
            ['request' => $request]
        );
    }

    // URL normal
    // ... mismo código anterior
}
```

## Router para múltiples entidades

Si tu módulo maneja tanto posts como categorías con URLs SEO:

```php
public function match(RequestInterface $request): ?ActionInterface
{
    $pathInfo = trim($request->getPathInfo(), '/');

    // Intentar como categoría primero
    $category = $this->categoryRepository->getByUrlKey($pathInfo);
    if ($category) {
        $request->setModuleName('blog');
        $request->setControllerName('category');
        $request->setActionName('view');
        $request->setParam('id', $category->getId());
        return $this->actionFactory->create(\Magento\Framework\App\Action\Forward::class, ['request' => $request]);
    }

    // Intentar como post
    // Formato: "categoria/slug-del-post" o solo "slug-del-post"
    $slug = $this->extractPostSlug($pathInfo);
    $post = $this->postRepository->getByUrlKey($slug);
    if ($post) {
        $request->setModuleName('blog');
        $request->setControllerName('post');
        $request->setActionName('view');
        $request->setParam('id', $post->getId());
        return $this->actionFactory->create(\Magento\Framework\App\Action\Forward::class, ['request' => $request]);
    }

    return null; // No es nuestro — siguiente router
}
```

## Consideraciones de rendimiento

El router se ejecuta en **cada request** del frontend. Evita queries pesadas:

```php
// ❌ Mal — query compleja en cada request
public function match(RequestInterface $request): ?ActionInterface
{
    // Esto consulta todas las entidades en cada pageview
    $allPosts = $this->postRepository->getAll();
    foreach ($allPosts as $post) {
        if ($post->getUrlKey() === $pathInfo) { ... }
    }
}

// ✅ Bien — query directa con filtro específico
public function match(RequestInterface $request): ?ActionInterface
{
    // Query indexada por url_key — rápida
    $post = $this->postRepository->getByUrlKey($pathInfo);
    ...
}

// ✅ Mejor aún — verificación rápida antes de hacer la query
public function match(RequestInterface $request): ?ActionInterface
{
    // Si el path tiene extensión (.html, .css, .js), no es nuestro
    if (preg_match('/\.\w{2,4}$/', $pathInfo)) {
        return null;
    }

    // Si empieza con prefijos del sistema, no es nuestro
    if (preg_match('/^(catalog|checkout|customer|cms)/', $pathInfo)) {
        return null;
    }

    // Ahora sí la query
    $post = $this->postRepository->getByUrlKey($pathInfo);
    ...
}
```

---

## Resumen

```
RouterInterface::match(Request) → ActionInterface | null

Si match() devuelve null  → el siguiente router toma el control
Si devuelve un Action     → se ejecuta ese action

Registro en di.xml (frontend):
  RouterList → tu clase → sortOrder (entre 30 y 100 normalmente)

Dentro de match():
  $request->setModuleName()      → módulo
  $request->setControllerName()  → directorio en Controller/
  $request->setActionName()      → clase PHP
  $request->setParam()           → parámetros
  return ActionFactory::create(Forward::class)
```

## Ejercicios

### Ejercicio 1 — Router para URLs de marca

Crea un router que intercepte URLs del tipo `/brand/{slug}` y las despache al controller `MiVendor\Catalog\Controller\Brand\View` pasando el slug como parámetro `slug`.

<details>
<summary>Ver solución</summary>

```php
<?php
// app/code/MiVendor/Catalog/Controller/Router.php
namespace MiVendor\Catalog\Controller;

use Magento\Framework\App\RouterInterface;
use Magento\Framework\App\RequestInterface;
use Magento\Framework\App\ActionInterface;
use Magento\Framework\App\ActionFactory;

class Router implements RouterInterface
{
    public function __construct(
        private readonly ActionFactory $actionFactory
    ) {}

    public function match(RequestInterface $request): ?ActionInterface
    {
        $pathInfo = trim($request->getPathInfo(), '/');

        // Solo procesar rutas /brand/{slug}
        if (!preg_match('/^brand\/([a-z0-9\-]+)$/', $pathInfo, $matches)) {
            return null;
        }

        $slug = $matches[1];

        $request->setModuleName('catalog');       // MiVendor_Catalog
        $request->setControllerName('brand');     // Controller/Brand/
        $request->setActionName('view');          // View.php
        $request->setParam('slug', $slug);

        return $this->actionFactory->create(
            \Magento\Framework\App\Action\Forward::class,
            ['request' => $request]
        );
    }
}
```

```xml
<!-- etc/frontend/di.xml -->
<type name="Magento\Framework\App\RouterList">
    <arguments>
        <argument name="routerList" xsi:type="array">
            <item name="mivendor_catalog" xsi:type="array">
                <item name="class" xsi:type="string">MiVendor\Catalog\Controller\Router</item>
                <item name="disable" xsi:type="boolean">false</item>
                <item name="sortOrder" xsi:type="string">45</item>
            </item>
        </argument>
    </arguments>
</type>
```

```php
// Controller/Brand/View.php — el controller que recibe el dispatch
class View extends \Magento\Framework\App\Action\Action
    implements \Magento\Framework\App\Action\HttpGetActionInterface
{
    public function execute(): \Magento\Framework\View\Result\Page
    {
        $slug = $this->getRequest()->getParam('slug');
        // ... cargar brand por slug, renderizar página
        return $this->resultPageFactory->create();
    }
}
```

**Por qué regex**: El regex `^brand\/([a-z0-9\-]+)$` garantiza que:
1. La URL empieza exactamente con `brand/`
2. El slug solo contiene caracteres válidos para SEO (sin espacios, sin caracteres especiales)
3. No interceptamos cosas como `brand/` vacío o `brand/../../etc`

### Ejercicio 2 — Router que consulta la base de datos con caché

El router del ejercicio anterior no consulta la DB (solo valida el formato), pero el controller sí lo hace. Reescríbelo para que el router consulte la DB y solo haga el dispatch si la marca existe — evitando que el controller haga un 404 tardío.

Además, añade una capa de caché para no hacer la query en cada request.

<details>
<summary>Ver solución</summary>

```php
<?php
namespace MiVendor\Catalog\Controller;

use Magento\Framework\App\RouterInterface;
use Magento\Framework\App\RequestInterface;
use Magento\Framework\App\ActionInterface;
use Magento\Framework\App\ActionFactory;
use Magento\Framework\App\CacheInterface;
use MiVendor\Catalog\Api\BrandRepositoryInterface;

class Router implements RouterInterface
{
    private const CACHE_TAG = 'mivendor_brand_router';
    private const CACHE_LIFETIME = 3600; // 1 hora

    public function __construct(
        private readonly ActionFactory $actionFactory,
        private readonly BrandRepositoryInterface $brandRepository,
        private readonly CacheInterface $cache
    ) {}

    public function match(RequestInterface $request): ?ActionInterface
    {
        $pathInfo = trim($request->getPathInfo(), '/');

        if (!preg_match('/^brand\/([a-z0-9\-]+)$/', $pathInfo, $matches)) {
            return null;
        }

        $slug = $matches[1];

        // Intentar leer desde caché
        $cacheKey = self::CACHE_TAG . '_' . md5($slug);
        $cachedId = $this->cache->load($cacheKey);

        if ($cachedId === false) {
            // No está en caché — consultar la DB
            try {
                $brand = $this->brandRepository->getBySlug($slug);
                $brandId = $brand->getId();
            } catch (\Magento\Framework\Exception\NoSuchEntityException $e) {
                // Guardar en caché que este slug no existe (evitar query repetida)
                $this->cache->save('0', $cacheKey, [self::CACHE_TAG], self::CACHE_LIFETIME);
                return null;
            }

            // Guardar el ID en caché
            $this->cache->save((string) $brandId, $cacheKey, [self::CACHE_TAG], self::CACHE_LIFETIME);
        } else {
            $brandId = (int) $cachedId;
        }

        // Si el valor cacheado es 0, la marca no existe
        if (!$brandId) {
            return null;
        }

        $request->setModuleName('catalog');
        $request->setControllerName('brand');
        $request->setActionName('view');
        $request->setParam('id', $brandId);     // ID en vez de slug
        $request->setParam('slug', $slug);       // Slug para canonical URL

        return $this->actionFactory->create(
            \Magento\Framework\App\Action\Forward::class,
            ['request' => $request]
        );
    }
}
```

```php
// Invalidar la caché del router cuando se guarda/elimina una marca:
// Observer/Brand/ClearRouterCache.php
class ClearRouterCache implements ObserverInterface
{
    public function __construct(private readonly CacheInterface $cache) {}

    public function execute(\Magento\Framework\Event\Observer $observer): void
    {
        // Limpiar toda la caché del router cuando cambia cualquier marca
        $this->cache->clean([\MiVendor\Catalog\Controller\Router::CACHE_TAG]);
    }
}
```

**Dos formas de cachear "no existe"**:
- Guardar `'0'` en caché → evita queries repetidas para slugs inválidos (ej: bots escaneando)
- No cachear nada → cada request con slug inválido hace una query (más simple pero más carga)

Para producción, la primera opción es mejor.

</details>
