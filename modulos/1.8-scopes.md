## El problema que resuelven los Scopes

Imagina que tienes una instalación de Magento con 3 tiendas:

```
Tienda México  → precios en MXN, idioma español, IVA 16%
Tienda USA     → precios en USD, idioma inglés, sin IVA
Tienda España  → precios en EUR, idioma español, IVA 21%
```

Cada tienda necesita configuraciones diferentes para el mismo ajuste (por ejemplo, "moneda por defecto"). Los Scopes son el mecanismo que permite esto.

🔄 **Laravel**: No existe nada equivalente en Laravel. Es un concepto único de Magento. Si vienes de Laravel, piensa en los Scopes como una configuración multinivel donde la más específica sobreescribe a la más general.

## La jerarquía de 3 niveles

```
┌─────────────────────────────────────────────────┐
│                   GLOBAL                        │
│   Configuración base para toda la instalación   │
│   Aplica cuando no hay override en niveles inf. │
└───────────────┬─────────────────────────────────┘
                │ puede sobrescribirse en →
┌───────────────▼─────────────────────────────────┐
│                  WEBSITE                        │
│   Un grupo de tiendas bajo la misma marca       │
│   Comparten catálogo y precios                  │
└───────────────┬─────────────────────────────────┘
                │ puede sobrescribirse en →
┌───────────────▼─────────────────────────────────┐
│                 STORE VIEW                      │
│   El nivel más específico                       │
│   Define idioma, formato de fecha, etc.         │
└─────────────────────────────────────────────────┘
```

### Ejemplo concreto de herencia

```
Configuración: "Moneda por defecto"

GLOBAL:     USD
  │
  ├── Website: Latinoamerica
  │     │  → hereda USD del global
  │     ├── Store View: México  → override: MXN
  │     ├── Store View: Colombia → override: COP
  │     └── Store View: Argentina → override: ARS
  │
  └── Website: Europa
        │  → override: EUR
        ├── Store View: España  → hereda EUR del website
        └── Store View: Francia → hereda EUR del website
```

En este ejemplo:
- Store View México → usa **MXN** (override explícito)
- Store View España → usa **EUR** (heredado del Website Europa)
- Store View Colombia → usa **COP** (override explícito)

## La estructura completa en Magento

```
Instalación de Magento
│
├── Website A (ID: 1, code: "base")         ← Stores > All Stores
│   ├── Store A1 (ID: 1)                    ← Agrupa los Store Views
│   │   ├── Store View A1a (ID: 1, "es")    ← Lo que el usuario ve
│   │   └── Store View A1b (ID: 2, "en")
│   └── Store A2 (ID: 2)
│       └── Store View A2a (ID: 3, "pt")
│
└── Website B (ID: 2, code: "b2b")
    └── Store B1 (ID: 3)
        └── Store View B1a (ID: 4, "es")
```

> **Confusión frecuente**: Hay 3 entidades — **Website**, **Store** (también llamado "Store Group") y **Store View**. En el día a día, cuando decimos "tienda" nos referimos al **Store View**. El "Store" (Group) es solo un agrupador intermedio.

## Cómo leer configuración por scope en código

### Leyendo config del scope actual

```php
namespace MiVendor\MiModulo\Model;

use Magento\Framework\App\Config\ScopeConfigInterface;
use Magento\Store\Model\ScopeInterface;

class ConfigProvider
{
    // Rutas de configuración — definidas en etc/config.xml y system.xml
    const XML_PATH_ENABLED   = 'mimodulo/general/enabled';
    const XML_PATH_API_KEY   = 'mimodulo/api/key';
    const XML_PATH_MAX_ITEMS = 'mimodulo/catalog/max_items';

    public function __construct(
        private readonly ScopeConfigInterface $scopeConfig
    ) {}

    // Leer para el Store View actual (el más común)
    public function isEnabled(?int $storeId = null): bool
    {
        return $this->scopeConfig->isSetFlag(
            self::XML_PATH_ENABLED,
            ScopeInterface::SCOPE_STORE,  // nivel: store view
            $storeId                       // null = store view actual
        );
    }

    // Leer para un Store View específico
    public function getApiKey(int $storeId): string
    {
        return (string) $this->scopeConfig->getValue(
            self::XML_PATH_API_KEY,
            ScopeInterface::SCOPE_STORE,
            $storeId
        );
    }

    // Leer a nivel Website
    public function getMaxItemsForWebsite(int $websiteId): int
    {
        return (int) $this->scopeConfig->getValue(
            self::XML_PATH_MAX_ITEMS,
            ScopeInterface::SCOPE_WEBSITE,
            $websiteId
        );
    }

    // Leer el valor global (sin scope)
    public function getGlobalApiKey(): string
    {
        return (string) $this->scopeConfig->getValue(
            self::XML_PATH_API_KEY,
            ScopeConfigInterface::SCOPE_TYPE_DEFAULT  // scope global
        );
    }
}
```

### Los constantes de scope

```php
use Magento\Store\Model\ScopeInterface;

ScopeInterface::SCOPE_STORE    // = 'store'   → Store View
ScopeInterface::SCOPE_STORES   // = 'stores'  → Store View (plural, mismo efecto)
ScopeInterface::SCOPE_WEBSITE  // = 'website' → Website
ScopeInterface::SCOPE_WEBSITES // = 'websites'→ Website (plural)

use Magento\Framework\App\Config\ScopeConfigInterface;
ScopeConfigInterface::SCOPE_TYPE_DEFAULT  // = 'default' → Global
```

💡 **TIP**: Casi siempre usarás `SCOPE_STORE`. El sistema de herencia se encarga automáticamente de subir a Website y luego a Global si no hay override en el nivel actual.

## Definir configuración con valores por scope

### config.xml — Valores default globales

```xml
<!-- etc/config.xml — Valores DEFAULT del módulo (nivel global) -->
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:module:Magento_Store:etc/config.xsd">
    <default>
        <mimodulo>
            <general>
                <enabled>1</enabled>
            </general>
            <api>
                <key></key>
                <timeout>30</timeout>
            </api>
            <catalog>
                <max_items>100</max_items>
            </catalog>
        </mimodulo>
    </default>
</config>
```

### system.xml — El formulario en Admin > Stores > Configuration

```xml
<!-- etc/adminhtml/system.xml -->
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:module:Magento_Config:etc/system_file.xsd">
    <system>
        <tab id="mivendor" translate="label" sortOrder="200">
            <label>Mi Vendor</label>
        </tab>

        <section id="mimodulo" translate="label" sortOrder="100"
                 showInDefault="1" showInWebsite="1" showInStore="1">
            <!--                  ↑ global      ↑ website    ↑ store view -->
            <tab>mivendor</tab>
            <label>Mi Módulo</label>
            <resource>MiVendor_MiModulo::config</resource>

            <group id="general" translate="label" sortOrder="10"
                   showInDefault="1" showInWebsite="1" showInStore="1">
                <label>General</label>

                <field id="enabled" translate="label" type="select" sortOrder="10"
                       showInDefault="1" showInWebsite="1" showInStore="1">
                    <label>Habilitado</label>
                    <source_model>Magento\Config\Model\Config\Source\Yesno</source_model>
                </field>
            </group>

            <group id="api" translate="label" sortOrder="20"
                   showInDefault="1" showInWebsite="1" showInStore="0">
                <!--                                          ↑ no configurable por store view -->
                <label>API</label>

                <field id="key" translate="label" type="text" sortOrder="10"
                       showInDefault="1" showInWebsite="1" showInStore="0">
                    <label>API Key</label>
                    <!-- Valor encriptado en DB -->
                    <backend_model>Magento\Config\Model\Config\Backend\Encrypted</backend_model>
                </field>

                <field id="timeout" translate="label" type="text" sortOrder="20"
                       showInDefault="1" showInWebsite="0" showInStore="0">
                    <label>Timeout (segundos)</label>
                    <!-- Solo configurable a nivel global -->
                </field>
            </group>
        </section>
    </system>
</config>
```

Los atributos `showInDefault`, `showInWebsite`, `showInStore` controlan en qué niveles aparece el campo en el panel de administración.

## Obtener el Store View actual

En muchos contextos necesitas saber en qué Store View estás:

```php
use Magento\Store\Model\StoreManagerInterface;

class MiClase
{
    public function __construct(
        private readonly StoreManagerInterface $storeManager
    ) {}

    public function getInfo(): array
    {
        $store   = $this->storeManager->getStore();
        $website = $this->storeManager->getWebsite();

        return [
            'store_id'     => $store->getId(),        // int
            'store_code'   => $store->getCode(),      // 'default', 'es', etc.
            'store_name'   => $store->getName(),
            'website_id'   => $website->getId(),
            'website_code' => $website->getCode(),
            'base_url'     => $store->getBaseUrl(),
            'locale'       => $store->getLocaleCode(), // 'es_MX', 'en_US'
            'currency'     => $store->getCurrentCurrencyCode(),
        ];
    }

    // Iterar todos los stores (útil en crons que procesan todas las tiendas)
    public function procesarTodasLasTiendas(): void
    {
        foreach ($this->storeManager->getStores() as $store) {
            $storeId = (int) $store->getId();
            // Procesar lógica para este store
            $apiKey = $this->configProvider->getApiKey($storeId);
            // ...
        }
    }
}
```

## Cómo la herencia funciona en la DB

Los valores de configuración se guardan en la tabla `core_config_data`:

```sql
SELECT scope, scope_id, path, value
FROM core_config_data
WHERE path = 'mimodulo/general/enabled'
ORDER BY scope, scope_id;

-- Resultado:
-- scope      | scope_id | path                       | value
-- default    | 0        | mimodulo/general/enabled   | 1    ← Global
-- website    | 2        | mimodulo/general/enabled   | 0    ← Override en Website 2
-- store      | 5        | mimodulo/general/enabled   | 1    ← Override en Store View 5
```

Cuando llamas a `$scopeConfig->getValue('mimodulo/general/enabled', SCOPE_STORE, 3)`, Magento busca en este orden:

```
1. ¿Hay un override para store_id=3?   → Si existe, devuelve ese valor
2. ¿Hay un override para el website del store 3? → Si existe, devuelve ese valor
3. ¿Hay un valor global (default)?     → Devuelve el valor global
4. No hay nada → null
```

## Usar scope en Observers y Plugins

Cuando tu código corre en un contexto con Store View activo, el `StoreManager` te da el scope automáticamente:

```php
// Observer que reacciona al guardar un producto
class ProductSaveObserver implements ObserverInterface
{
    public function __construct(
        private readonly StoreManagerInterface $storeManager,
        private readonly ScopeConfigInterface  $scopeConfig
    ) {}

    public function execute(\Magento\Framework\Event\Observer $observer): void
    {
        $product = $observer->getEvent()->getProduct();
        $storeId = $product->getStoreId(); // Store View donde se guardó

        // Leer configuración específica de ese Store View
        $isEnabled = $this->scopeConfig->isSetFlag(
            'mimodulo/general/enabled',
            ScopeInterface::SCOPE_STORE,
            $storeId
        );

        if (!$isEnabled) {
            return;
        }

        // lógica...
    }
}
```

## Scope en cron jobs — el patrón más común

Los crons corren sin un Store View activo. Si necesitas procesar datos por tienda, itera los stores:

```php
class SincronizarInventarioCron
{
    public function __construct(
        private readonly StoreManagerInterface $storeManager,
        private readonly ScopeConfigInterface  $scopeConfig,
        private readonly Emulation             $emulation
    ) {}

    public function execute(): void
    {
        foreach ($this->storeManager->getStores() as $store) {
            $storeId = (int) $store->getId();

            // ¿Está habilitado para esta tienda?
            $enabled = $this->scopeConfig->isSetFlag(
                'mimodulo/sync/enabled',
                ScopeInterface::SCOPE_STORE,
                $storeId
            );

            if (!$enabled) {
                continue;
            }

            // Emular contexto del store para servicios que lo requieren
            $this->emulation->startEnvironmentEmulation(
                $storeId,
                \Magento\Framework\App\Area::AREA_FRONTEND
            );

            try {
                $apiKey = $this->scopeConfig->getValue(
                    'mimodulo/api/key',
                    ScopeInterface::SCOPE_STORE,
                    $storeId
                );

                $this->sincronizar($storeId, $apiKey);

            } finally {
                $this->emulation->stopEnvironmentEmulation();
            }
        }
    }
}
```

## Dónde se configura en el Admin

Los scopes se configuran en **Stores > Configuration**:

```
Admin → Stores → Configuration

El selector en la esquina superior izquierda:
┌─────────────────────────────────────────┐
│  Scope: [Default Config        ▼]       │  ← Global
│         [Main Website           ]       │  ← Website
│           ├── [Default Store View]      │  ← Store View
│           └── [Spanish Store View]      │
└─────────────────────────────────────────┘
```

Cuando seleccionas un scope en ese selector y cambias un valor, el campo muestra un checkbox **"Use Default"** / **"Use Website"** que permite volver a heredar del nivel superior.

## Anti-pattern: hardcodear el store_id

```php
// ❌ MAL — hardcodear store ID rompe proyectos multitienda
$value = $this->scopeConfig->getValue('path/to/config', SCOPE_STORE, 1);

// ✅ BIEN — usar el store actual o iterar todos
$value = $this->scopeConfig->getValue('path/to/config', SCOPE_STORE);

// ✅ BIEN — cuando necesitas un store específico, pásalo como parámetro
public function getValue(int $storeId): string
{
    return $this->scopeConfig->getValue('path/to/config', SCOPE_STORE, $storeId);
}
```

💡 **TIP**: Aunque tu proyecto solo tenga una tienda hoy, programa siempre con scope correcto. Los clientes de Magento eventualmente piden multitienda, y refactorizar código hardcodeado es doloroso.

## Resumen

```
Global (default)
    └── herencia hacia abajo
        Website
            └── herencia hacia abajo
                Store View  ← nivel más específico, el que más usas
```

| Scope | Constante | Cuándo usarlo |
|---|---|---|
| Global | `SCOPE_TYPE_DEFAULT` | Configuración que aplica a toda la instalación |
| Website | `SCOPE_WEBSITE` | Config que varía por marca/región |
| Store View | `SCOPE_STORE` | Config que varía por idioma/moneda/locale |

### Reglas prácticas

```
¿Lees config en un Controller/Block/ViewModel? → SCOPE_STORE sin store_id (actual)
¿Lees config en un Cron?                       → itera storeManager->getStores()
¿Lees config en un Observer?                   → usa el store_id del evento
¿Defines config en system.xml?                 → showInDefault=1 siempre,
                                                  showInStore/Website según necesidad
```
