## El problema que resuelve Layout XML

🔄 **Laravel**: Las vistas son archivos Blade. Cada controller devuelve `view('posts.index', $data)`. El layout es un template que otros extienden con `@extends`.

En Magento una página es el resultado de **fusionar decenas de archivos XML** de múltiples módulos. No hay un solo "template principal" — hay una estructura en árbol que se construye dinámicamente:

```
Página de producto en Magento:
  default.xml                           (base de todas las páginas)
+ catalog_product_view.xml              (del módulo Catalog)
+ catalog_product_view_type_simple.xml  (para productos simples)
+ mivendor_blog_*.xml                   (si tu módulo agrega algo)
= Una página HTML completa
```

Nadie toca directamente el HTML. Todo pasa por XML.

---

## La arquitectura: tres niveles

```
1. HANDLES     →  Qué XMLs se cargan (basado en URL/contexto)
2. ESTRUCTURA  →  Containers y Blocks (el árbol de la página)
3. RENDERIZADO →  Blocks ejecutan PHP, templates generan HTML
```

---

## Cómo se construye una página

```
Request HTTP → Router → Controller → ResultPage
     ↓
Layout Manager lee los HANDLES activos
     ↓
Carga y fusiona todos los XMLs que coincidan
     ↓
Árbol único de Containers y Blocks
     ↓
Cada Block ejecuta PHP → renderiza .phtml
     ↓
HTML final ensamblado
```

## Estructura de un archivo de layout

```xml
<!-- app/code/MiVendor/Blog/view/frontend/layout/blog_post_view.xml -->
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">

    <head>
        <title>Mi Blog Post</title>
        <css src="MiVendor_Blog::css/blog.css"/>
        <script src="MiVendor_Blog::js/blog.js"/>
    </head>

    <body>
        <referenceContainer name="content">
            <block class="MiVendor\Blog\Block\Post\View"
                   name="blog.post.view"
                   template="MiVendor_Blog::post/view.phtml"/>
        </referenceContainer>
    </body>

</page>
```

---

## Los cuatro elementos clave

### `<block>` — unidad de renderizado

```xml
<block class="MiVendor\Blog\Block\Post\View"
       name="blog.post.view"
       template="MiVendor_Blog::post/view.phtml"
       as="post_view"
       before="-">
    <arguments>
        <argument name="cache_lifetime" xsi:type="number">86400</argument>
        <argument name="show_author" xsi:type="boolean">true</argument>
    </arguments>
    <block class="MiVendor\Blog\Block\Post\Author"
           name="blog.post.author"
           template="MiVendor_Blog::post/author.phtml"/>
</block>
```

### `<container>` — estructura sin PHP

```xml
<container name="blog.sidebar"
           htmlTag="aside"
           htmlClass="blog-sidebar"
           htmlId="blog-sidebar"
           label="Blog Sidebar"/>
```

### `<referenceBlock>` y `<referenceContainer>` — modificar lo existente

```xml
<!-- Agregar al container de otro módulo -->
<referenceContainer name="content">
    <block class="..." name="mi.block" template="..."/>
</referenceContainer>

<!-- Modificar argumentos de un block existente -->
<referenceBlock name="product.info.main">
    <arguments>
        <argument name="show_qty" xsi:type="boolean">false</argument>
    </arguments>
</referenceBlock>

<!-- Eliminar un block -->
<referenceBlock name="catalog.compare.sidebar" remove="true"/>
```

## Dónde van los archivos

```
view/frontend/layout/
  default.xml              ← todas las páginas frontend
  blog_index_index.xml     ← solo /blog/index/index
  blog_post_view.xml       ← solo /blog/post/view

Nomenclatura: {frontName}_{controllerDir}_{action}.xml
```

---

## El árbol base de la página

```
root
└── page.wrapper
    ├── header.container
    ├── main.content
    │   └── columns
    │       ├── main              ← contenido principal
    │       ├── sidebar.main
    │       └── sidebar.additional
    └── footer-container
```

Tu módulo agrega en `content`, `sidebar.main`, etc. usando `<referenceContainer>`.

---

## Posicionamiento

```xml
<block ... before="-"/>           <!-- al inicio -->
<block ... after="-"/>            <!-- al final (default) -->
<block ... before="otro.block"/>  <!-- antes de un block específico -->
<block ... after="otro.block"/>   <!-- después de un block específico -->
```

---

## Agregar CSS/JS

```xml
<head>
    <css src="MiVendor_Blog::css/blog.css"/>
    <script src="MiVendor_Blog::js/blog.js"/>
    <remove src="Magento_Catalog::css/catalog.css"/>
</head>
```

---

## Prioridad de fusión

```
1. Magento core
2. Módulos de terceros
3. Tu módulo (app/code/)
4. Tema activo (app/design/)  ← mayor prioridad, gana sobre todo
```

---

## Caché

```bash
php bin/magento cache:clean layout
```

En modo `developer` se regenera automáticamente en cada request.

---

## Resumen

```
<container>          →  estructura (sin PHP, sin template)
<block>              →  renderizado (clase PHP + .phtml)
<referenceBlock>     →  modificar block existente
<referenceContainer> →  agregar al container de otro módulo
remove="true"        →  eliminar block del árbol

Ubicación: view/frontend/layout/{handle}.xml
```

## Ejercicios

### Ejercicio 1 — Banner en homepage

Sin modificar el core, agrega `MiVendor\Blog\Block\Promo\Banner` con template `MiVendor_Blog::promo/banner.phtml` en el container `content` de `cms_index_index`, antes del contenido principal.

<details>
<summary>Ver solución</summary>

```xml
<!-- view/frontend/layout/cms_index_index.xml -->
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">
    <body>
        <referenceContainer name="content">
            <block class="MiVendor\Blog\Block\Promo\Banner"
                   name="mivendor.promo.banner"
                   template="MiVendor_Blog::promo/banner.phtml"
                   before="-"/>
        </referenceContainer>
    </body>
</page>
```

```bash
php bin/magento cache:clean layout
```

</details>

---

### Ejercicio 2 — Eliminar bloque de comparación

Elimina `catalog.compare.sidebar` de páginas de categoría sin tocar el core.

<details>
<summary>Ver solución</summary>

```xml
<!-- view/frontend/layout/catalog_category_view.xml -->
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">
    <body>
        <referenceBlock name="catalog.compare.sidebar" remove="true"/>
    </body>
</page>
```

**`remove="true"` vs `display="false"`**: `remove` elimina el block del árbol (no se instancia). `display="false"` lo instancia pero no genera HTML — reversible desde PHP.

</details>
