# 1.4 — Magento Layers: Las 4 Capas en Profundidad

> **Objetivo**: Entender qué código va en cada capa, por qué existe esta separación y cómo aplicarla al escribir tu propio módulo. Después de este módulo sabrás exactamente dónde poner cada clase.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [1.3 — Magento Areas](1.3-areas.md)

---

## Por qué existe la separación en capas

En el 1.2 vimos las 4 capas de manera conceptual. Aquí vamos al detalle con código real.

El problema que las capas resuelven es el **acoplamiento**:

```php
// ❌ Código sin capas — todo en un solo lugar (estilo "script" o Eloquent al extremo)
class ProductController
{
    public function view($id)
    {
        // Lógica de presentación
        $product = DB::table('catalog_product_entity')->where('entity_id', $id)->first();

        // Lógica de negocio mezclada con acceso a DB
        if ($product->status == 1 && $product->stock > 0) {
            $price = $product->price * 1.16; // IVA hardcodeado
        }

        // Presentación mezclada con lógica
        return view('product', compact('product', 'price'));
    }
}
```

**Problemas**:
- ¿Qué pasa si necesitas el mismo precio en la API REST?
- ¿Y si la lógica del IVA cambia?
- ¿Cómo testeas el cálculo del precio sin levantar HTTP?

Con capas, cada responsabilidad tiene su lugar y se puede cambiar o testear de forma independiente.

## Mapa visual de las capas con archivos reales

```
app/code/MiVendor/Blog/
│
├── Controller/                    ← PRESENTATION
│   ├── Post/View.php
│   └── Post/Save.php
│
├── Block/                         ← PRESENTATION
│   └── Post/View.php
│
├── ViewModel/                     ← PRESENTATION
│   └── PostData.php
│
├── view/                          ← PRESENTATION
│   └── frontend/
│       ├── layout/
│       │   └── blog_post_view.xml
│       └── templates/
│           └── post/view.phtml
│
├── Api/                           ← SERVICE
│   ├── PostRepositoryInterface.php
│   └── Data/
│       └── PostInterface.php
│
├── Model/                         ← DOMAIN + SERVICE + PERSISTENCE (mezclado)
│   ├── Post.php                   ← DOMAIN (lógica de negocio)
│   ├── PostRepository.php         ← SERVICE (implementa PostRepositoryInterface)
│   └── ResourceModel/
│       ├── Post.php               ← PERSISTENCE (acceso a DB)
│       └── Post/
│           └── Collection.php     ← PERSISTENCE (queries múltiples)
│
└── Setup/                         ← PERSISTENCE
    ├── db_schema.xml
    └── Patch/
        └── Data/
            └── AddInitialPosts.php
```

💡 **TIP**: El directorio `Model/` en Magento contiene código de las capas Domain, Service y Persistence mezclados. Es confuso al principio. La clave es el subdirectorio: `Model/` = Domain, `Model/ResourceModel/` = Persistence, `Api/` = Service contracts.

## CAPA 1: Presentation Layer

### Responsabilidad

- Recibir la petición HTTP
- Delegar a la capa de servicio
- Renderizar la respuesta (HTML, JSON, redirect)
- **NO** contener lógica de negocio
- **NO** acceder directamente a la base de datos

### Controllers — una clase por acción

🔄 **Laravel**: En Laravel un Controller tiene múltiples métodos (`index`, `show`, `store`...). En Magento, **cada método es una clase separada**.

```php
// app/code/MiVendor/Blog/Controller/Post/View.php
namespace MiVendor\Blog\Controller\Post;

use Magento\Framework\App\Action\HttpGetActionInterface;
use Magento\Framework\View\Result\PageFactory;
use Magento\Framework\App\RequestInterface;

class View implements HttpGetActionInterface
{
    public function __construct(
        private readonly PageFactory    $resultPageFactory,
        private readonly RequestInterface $request
    ) {}

    public function execute(): \Magento\Framework\Controller\ResultInterface
    {
        $postId = (int) $this->request->getParam('id');

        if (!$postId) {
            // Redirect a 404
            $resultRedirect = $this->resultRedirectFactory->create();
            return $resultRedirect->setPath('noroute');
        }

        // ✅ Solo crea la página — el Block/ViewModel carga los datos
        $resultPage = $this->resultPageFactory->create();
        $resultPage->getConfig()->getTitle()->set(__('Ver Post'));

        return $resultPage;
    }
}
```

💡 **TIP**: Los Controllers implementan interfaces como `HttpGetActionInterface` o `HttpPostActionInterface` en lugar de extender clases base (patrón moderno de Magento 2.3+). Esto dice explícitamente qué verbo HTTP acepta la acción.

### Blocks — lógica de presentación

El Block es la capa entre el Layout XML y el template `.phtml`. Prepara los datos que el template necesita.

```php
// app/code/MiVendor/Blog/Block/Post/View.php
namespace MiVendor\Blog\Block\Post;

use Magento\Framework\View\Element\Template;
use MiVendor\Blog\Api\PostRepositoryInterface;
use MiVendor\Blog\Api\Data\PostInterface;

class View extends Template
{
    public function __construct(
        Template\Context                  $context,
        private readonly PostRepositoryInterface $postRepository,
        private readonly \Magento\Framework\App\RequestInterface $request,
        array $data = []
    ) {
        parent::__construct($context, $data);
    }

    public function getPost(): ?PostInterface
    {
        $postId = (int) $this->getRequest()->getParam('id');

        try {
            return $this->postRepository->getById($postId);
        } catch (\Magento\Framework\Exception\NoSuchEntityException $e) {
            return null;
        }
    }
}
```

### ViewModels — la forma moderna (Magento 2.2+)

Los ViewModels desacoplaron la lógica del Block. Un ViewModel no extiende `Template` — es un POJO (Plain Old PHP Object) con una sola dependencia: lo que necesita para hacer su trabajo.

🔄 **Laravel**: Equivalente a un View Composer, pero más liviano y testeable.

```php
// app/code/MiVendor/Blog/ViewModel/PostData.php
namespace MiVendor\Blog\ViewModel;

use Magento\Framework\View\Element\Block\ArgumentInterface;
use MiVendor\Blog\Api\PostRepositoryInterface;
use MiVendor\Blog\Api\Data\PostInterface;

// ArgumentInterface es el marcador — le dice a Magento que es un ViewModel
class PostData implements ArgumentInterface
{
    public function __construct(
        private readonly PostRepositoryInterface $postRepository,
        private readonly \Magento\Framework\App\RequestInterface $request
    ) {}

    public function getPost(): ?PostInterface
    {
        try {
            return $this->postRepository->getById(
                (int) $this->request->getParam('id')
            );
        } catch (\Magento\Framework\Exception\NoSuchEntityException $e) {
            return null;
        }
    }

    public function formatDate(\DateTime $date): string
    {
        return $date->format('d/m/Y');
    }
}
```

Se inyecta en el Layout XML así:

```xml
<!-- view/frontend/layout/blog_post_view.xml -->
<block class="Magento\Framework\View\Element\Template"
       name="blog.post.view"
       template="MiVendor_Blog::post/view.phtml">
    <arguments>
        <argument name="view_model"
                  xsi:type="object">MiVendor\Blog\ViewModel\PostData</argument>
    </arguments>
</block>
```

Y en el template:

```php
<!-- view/frontend/templates/post/view.phtml -->
<?php
/** @var \Magento\Framework\View\Element\Template $block */
/** @var \MiVendor\Blog\ViewModel\PostData $viewModel */
$viewModel = $block->getData('view_model');
$post = $viewModel->getPost();
?>

<?php if ($post): ?>
    <article>
        <h1><?= $block->escapeHtml($post->getTitle()) ?></h1>
        <div class="content">
            <?= $block->escapeHtml($post->getContent()) ?>
        </div>
    </article>
<?php else: ?>
    <p><?= __('Post no encontrado') ?></p>
<?php endif; ?>
```

💡 **TIP**: Siempre usa `$block->escapeHtml()` para renderizar contenido del usuario. Previene XSS. Es el equivalente de `{{ $variable }}` en Blade (que escapa automáticamente). En `.phtml` tienes que hacerlo explícito.

## CAPA 2: Service Layer

### Responsabilidad

- Definir los **contratos públicos** del módulo (interfaces en `Api/`)
- Ser la única forma que los externos interactúan con tu módulo
- Coordinar operaciones entre Domain y Persistence
- **NO** contener lógica de presentación

### Data Interfaces — los DTOs de Magento

```php
// Api/Data/PostInterface.php
namespace MiVendor\Blog\Api\Data;

interface PostInterface
{
    // Constantes de los campos — evita strings mágicos
    const POST_ID   = 'post_id';
    const TITLE     = 'title';
    const CONTENT   = 'content';
    const STATUS    = 'status';
    const AUTHOR_ID = 'author_id';
    const CREATED_AT = 'created_at';

    public function getId(): ?int;

    public function getTitle(): string;
    public function setTitle(string $title): self;

    public function getContent(): string;
    public function setContent(string $content): self;

    public function getStatus(): string;
    public function setStatus(string $status): self;

    public function getAuthorId(): int;
    public function setAuthorId(int $authorId): self;

    public function getCreatedAt(): string;
}
```

### Repository Interface — el contrato de acceso a datos

```php
// Api/PostRepositoryInterface.php
namespace MiVendor\Blog\Api;

use MiVendor\Blog\Api\Data\PostInterface;
use MiVendor\Blog\Api\Data\PostSearchResultsInterface;
use Magento\Framework\Api\SearchCriteriaInterface;

interface PostRepositoryInterface
{
    /**
     * @throws \Magento\Framework\Exception\NoSuchEntityException
     */
    public function getById(int $id): PostInterface;

    /**
     * @throws \Magento\Framework\Exception\CouldNotSaveException
     */
    public function save(PostInterface $post): PostInterface;

    /**
     * @throws \Magento\Framework\Exception\CouldNotDeleteException
     */
    public function delete(PostInterface $post): bool;

    /**
     * @throws \Magento\Framework\Exception\NoSuchEntityException
     * @throws \Magento\Framework\Exception\CouldNotDeleteException
     */
    public function deleteById(int $id): bool;

    public function getList(SearchCriteriaInterface $searchCriteria): PostSearchResultsInterface;
}
```

💡 **TIP**: Los doctypes `@throws` son importantes en Magento. Los endpoints REST los usan para generar respuestas de error HTTP correctas automáticamente (404, 422, etc.).

## CAPA 3: Domain Layer

### Responsabilidad

- Representar las **entidades del negocio** (Post, Producto, Pedido)
- Contener las **reglas de negocio puras**
- **NO** conocer cómo se persisten los datos
- **NO** conocer cómo se presentan
- Ser testeable sin base de datos ni HTTP

```php
// Model/Post.php
namespace MiVendor\Blog\Model;

use Magento\Framework\Model\AbstractModel;
use MiVendor\Blog\Api\Data\PostInterface;

class Post extends AbstractModel implements PostInterface
{
    // Estados del dominio
    const STATUS_PUBLISHED = 'published';
    const STATUS_DRAFT     = 'draft';
    const STATUS_ARCHIVED  = 'archived';

    protected function _construct(): void
    {
        $this->_init(\MiVendor\Blog\Model\ResourceModel\Post::class);
    }

    // ── Implementación de PostInterface ──────────────────────────────

    public function getId(): ?int
    {
        return $this->getData(self::POST_ID) ? (int)$this->getData(self::POST_ID) : null;
    }

    public function getTitle(): string
    {
        return (string) $this->getData(self::TITLE);
    }

    public function setTitle(string $title): self
    {
        return $this->setData(self::TITLE, $title);
    }

    public function getContent(): string
    {
        return (string) $this->getData(self::CONTENT);
    }

    public function setContent(string $content): self
    {
        return $this->setData(self::CONTENT, $content);
    }

    public function getStatus(): string
    {
        return (string) $this->getData(self::STATUS);
    }

    public function setStatus(string $status): self
    {
        return $this->setData(self::STATUS, $status);
    }

    public function getAuthorId(): int
    {
        return (int) $this->getData(self::AUTHOR_ID);
    }

    public function setAuthorId(int $authorId): self
    {
        return $this->setData(self::AUTHOR_ID, $authorId);
    }

    public function getCreatedAt(): string
    {
        return (string) $this->getData(self::CREATED_AT);
    }

    // ── Lógica de negocio pura ───────────────────────────────────────

    public function isPublished(): bool
    {
        return $this->getStatus() === self::STATUS_PUBLISHED;
    }

    public function isDraft(): bool
    {
        return $this->getStatus() === self::STATUS_DRAFT;
    }

    public function publish(): self
    {
        return $this->setStatus(self::STATUS_PUBLISHED);
    }

    public function archive(): self
    {
        if (!$this->isPublished()) {
            throw new \LogicException('Solo se pueden archivar posts publicados.');
        }
        return $this->setStatus(self::STATUS_ARCHIVED);
    }

    public function getExcerpt(int $length = 150): string
    {
        return substr(strip_tags($this->getContent()), 0, $length) . '...';
    }

    public function getReadingTimeMinutes(): int
    {
        $wordCount = str_word_count(strip_tags($this->getContent()));
        return (int) ceil($wordCount / 200); // 200 palabras por minuto promedio
    }
}
```

🔄 **Laravel/Eloquent vs Magento Model**:

```php
// Laravel — el Model hace todo:
$post = Post::find(5);           // query a DB (en el Model)
$post->isPublished();            // lógica de negocio (en el Model)
$post->save();                   // persistencia (en el Model)

// Magento — separación estricta:
$post = $this->postRepository->getById(5);  // query (en Repository/ResourceModel)
$post->isPublished();                        // lógica (en el Model)
$this->postRepository->save($post);          // persistencia (en Repository)
```

## CAPA 4: Persistence Layer

### Responsabilidad

- Mapear entidades a tablas de base de datos
- Ejecutar queries SQL
- Definir el schema de las tablas
- **NO** contener lógica de negocio
- **NO** saber nada de presentación

### ResourceModel — CRUD de una entidad

```php
// Model/ResourceModel/Post.php
namespace MiVendor\Blog\Model\ResourceModel;

use Magento\Framework\Model\ResourceModel\Db\AbstractDb;

class Post extends AbstractDb
{
    protected function _construct(): void
    {
        // tabla, primary key
        $this->_init('mivendor_blog_post', 'post_id');
    }

    // Puedes sobreescribir _beforeSave / _afterSave para lógica de DB
    protected function _beforeSave(\Magento\Framework\Model\AbstractModel $object): self
    {
        if (!$object->getCreatedAt()) {
            $object->setCreatedAt((new \DateTime())->format('Y-m-d H:i:s'));
        }
        return parent::_beforeSave($object);
    }
}
```

### Collection — queries de múltiples registros

🔄 **Laravel**: Equivalente a los Scopes de Eloquent + el Query Builder, pero como clase separada.

```php
// Model/ResourceModel/Post/Collection.php
namespace MiVendor\Blog\Model\ResourceModel\Post;

use Magento\Framework\Model\ResourceModel\Db\Collection\AbstractCollection;

class Collection extends AbstractCollection
{
    protected $_idFieldName = 'post_id';

    protected function _construct(): void
    {
        $this->_init(
            \MiVendor\Blog\Model\Post::class,
            \MiVendor\Blog\Model\ResourceModel\Post::class
        );
    }

    // "Scopes" reutilizables — como los scopes de Eloquent
    public function addPublishedFilter(): self
    {
        return $this->addFieldToFilter('status', \MiVendor\Blog\Model\Post::STATUS_PUBLISHED);
    }

    public function addAuthorFilter(int $authorId): self
    {
        return $this->addFieldToFilter('author_id', $authorId);
    }

    public function addRecentFirst(): self
    {
        return $this->setOrder('created_at', self::SORT_ORDER_DESC);
    }

    public function addSearchFilter(string $term): self
    {
        return $this->addFieldToFilter(
            ['title', 'content'],
            [
                ['like' => "%{$term}%"],
                ['like' => "%{$term}%"],
            ]
        );
    }
}
```

Uso de la Collection:

```php
// Equivalente en Laravel: Post::published()->byAuthor(5)->recent()->get()

$collection = $this->collectionFactory->create();
$collection
    ->addPublishedFilter()
    ->addAuthorFilter(5)
    ->addRecentFirst()
    ->setPageSize(10)
    ->setCurPage(1);

foreach ($collection as $post) {
    echo $post->getTitle();
}
```

### Repository — la implementación del Service Contract

El Repository es donde Service Layer y Persistence Layer se juntan:

```php
// Model/PostRepository.php
namespace MiVendor\Blog\Model;

use MiVendor\Blog\Api\PostRepositoryInterface;
use MiVendor\Blog\Api\Data\PostInterface;
use MiVendor\Blog\Model\PostFactory;
use MiVendor\Blog\Model\ResourceModel\Post as PostResource;
use MiVendor\Blog\Model\ResourceModel\Post\CollectionFactory;
use Magento\Framework\Exception\CouldNotSaveException;
use Magento\Framework\Exception\CouldNotDeleteException;
use Magento\Framework\Exception\NoSuchEntityException;

class PostRepository implements PostRepositoryInterface
{
    public function __construct(
        private readonly PostResource      $resource,
        private readonly PostFactory       $postFactory,
        private readonly CollectionFactory $collectionFactory
    ) {}

    public function getById(int $id): PostInterface
    {
        $post = $this->postFactory->create();
        $this->resource->load($post, $id);

        if (!$post->getId()) {
            throw new NoSuchEntityException(
                __('El post con ID "%1" no existe.', $id)
            );
        }

        return $post;
    }

    public function save(PostInterface $post): PostInterface
    {
        try {
            $this->resource->save($post);
        } catch (\Exception $e) {
            throw new CouldNotSaveException(
                __('No se pudo guardar el post: %1', $e->getMessage())
            );
        }

        return $post;
    }

    public function delete(PostInterface $post): bool
    {
        try {
            $this->resource->delete($post);
        } catch (\Exception $e) {
            throw new CouldNotDeleteException(
                __('No se pudo eliminar el post: %1', $e->getMessage())
            );
        }

        return true;
    }

    public function deleteById(int $id): bool
    {
        return $this->delete($this->getById($id));
    }

    public function getList(\Magento\Framework\Api\SearchCriteriaInterface $searchCriteria): \MiVendor\Blog\Api\Data\PostSearchResultsInterface
    {
        $collection = $this->collectionFactory->create();
        // Aplicar filtros del SearchCriteria a la collection
        // (lo veremos en detalle en el módulo 8.6)
        $collection->load();

        $searchResults = $this->searchResultsFactory->create();
        $searchResults->setSearchCriteria($searchCriteria);
        $searchResults->setItems($collection->getItems());
        $searchResults->setTotalCount($collection->getSize());

        return $searchResults;
    }
}
```

## Conectar todo: el di.xml que une las capas

Para que Magento sepa que `PostRepositoryInterface` debe instanciar `PostRepository`, necesitas declararlo:

```xml
<!-- etc/di.xml -->
<config>
    <!-- Service Contract: interface → implementación -->
    <preference for="MiVendor\Blog\Api\PostRepositoryInterface"
                type="MiVendor\Blog\Model\PostRepository"/>

    <!-- Data interface → implementación (para el Model) -->
    <preference for="MiVendor\Blog\Api\Data\PostInterface"
                type="MiVendor\Blog\Model\Post"/>
</config>
```

Ahora cuando cualquier clase pida `PostRepositoryInterface` en su constructor, el DI container instancia `PostRepository`.

## El flujo completo entre capas con código

```

        │
        ▼
[PRESENTATION] Controller/Post/View::execute()
    $resultPage = $this->resultPageFactory->create();
    // El controller solo crea la página, no carga datos
        │
        ▼
[PRESENTATION] Layout XML: blog_post_view.xml
    Inyecta ViewModel\PostData en el block
        │
        ▼
[PRESENTATION] ViewModel/PostData::getPost()

        │
        ▼

    $post = $this->postFactory->create()

        │
        ▼

        │
        ▼

        │
        ▼ (sube de vuelta)

        │
        ▼
```

## Resumen: ¿Dónde pongo cada clase?

| Tengo que crear... | Va en... | Capa |
|---|---|---|
| Un Controller | `Controller/Accion/Nombre.php` | Presentation |
| Un Block | `Block/Nombre.php` | Presentation |
| Un ViewModel | `ViewModel/Nombre.php` | Presentation |
| Un template | `view/frontend/templates/*.phtml` | Presentation |
| Una interfaz de servicio | `Api/NombreInterface.php` | Service |
| Una interfaz de datos (DTO) | `Api/Data/NombreInterface.php` | Service |
| Un Repository | `Model/NombreRepository.php` | Service |
| Un Model (entidad) | `Model/Nombre.php` | Domain |
| Un ResourceModel | `Model/ResourceModel/Nombre.php` | Persistence |
| Una Collection | `Model/ResourceModel/Nombre/Collection.php` | Persistence |
| El schema de tablas | `Setup/db_schema.xml` | Persistence |
| Datos iniciales | `Setup/Patch/Data/NombrePatch.php` | Persistence |

### La regla de oro para no equivocarse

```
¿La clase necesita HTTP o sesión?       → Presentation
¿La clase define un contrato público?   → Service (Api/)
¿La clase tiene reglas de negocio?      → Domain (Model/)
¿La clase habla con la DB?              → Persistence (ResourceModel/)
```

## Anti-patterns frecuentes

```php
// ❌ Lógica de negocio en el Controller
class View extends Action
{
    public function execute()
    {
        // NO hagas queries o lógica de negocio aquí
        $product = $this->objectManager->get(Product::class);
        $product->load($this->getRequest()->getParam('id'));
        $price = $product->getPrice() * 1.16; // IVA en el controller = ❌
    }
}

// ❌ Query directa en el Model
class Post extends AbstractModel
{
    public function getRelatedPosts(): array
    {
        // NO hagas queries dentro del Model
        $connection = $this->getResource()->getConnection();
        return $connection->fetchAll("SELECT * FROM...");
    }
}

// ❌ Instanciar con ObjectManager directamente
class MiClase
{
    public function __construct()
    {
        // NUNCA uses ObjectManager directamente (excepto en Factory y tests)
        $this->repo = \Magento\Framework\App\ObjectManager::getInstance()
            ->get(PostRepositoryInterface::class);
    }
}
```

```php
// ✅ Correcto: DI en el constructor
class MiClase
{
    public function __construct(
        private readonly PostRepositoryInterface $postRepository
    ) {}
}
```
