## Diferencias clave con controllers de storefront

🔄 **Laravel**: Un controller de admin y uno de frontend son prácticamente iguales — solo cambia el middleware.

En Magento el área `adminhtml` tiene su propio stack:

```
Frontend Controller                 Admin Controller
──────────────────────────────────────────────────────
App\Action\Action                   Magento\Backend\App\Action\Context
HttpGetActionInterface              _isAllowed() para ACL
FormKeyValidator (manual)           FormKey verificado automáticamente
Session de customer                 Session de admin (AuthSession)
ResultFactory::TYPE_PAGE            Layout adminhtml diferente
Sin redirección automática          Redirect a getUrl('*/*/') pattern
```

---

## Estructura base de un Admin Controller

```php
<?php
// app/code/MiVendor/Blog/Controller/Adminhtml/Post/Index.php
namespace MiVendor\Blog\Controller\Adminhtml\Post;

use Magento\Backend\App\Action;
use Magento\Backend\App\Action\Context;
use Magento\Framework\View\Result\PageFactory;

class Index extends Action
{
    // ACL resource — definido en acl.xml
    public const ADMIN_RESOURCE = 'MiVendor_Blog::post_manage';

    public function __construct(
        Context $context,
        private readonly PageFactory $resultPageFactory
    ) {
        parent::__construct($context);
    }

    public function execute(): \Magento\Framework\View\Result\Page
    {
        $resultPage = $this->resultPageFactory->create();

        // Configurar el título de la página de admin
        $resultPage->getConfig()->getTitle()->prepend(__('Blog Posts'));

        return $resultPage;
    }
}
```

**Diferencias inmediatas**:
1. Extiende `Magento\Backend\App\Action` (no `Magento\Framework\App\Action\Action`)
2. `const ADMIN_RESOURCE` — Magento lo usa automáticamente para verificar ACL
3. `Context` es `Magento\Backend\App\Action\Context` (tiene más servicios inyectados)

## ACL: Control de Acceso

### 1. Definir recursos en acl.xml

```xml
<!-- app/code/MiVendor/Blog/etc/acl.xml -->
<?xml version="1.0"?>
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:framework:Acl/etc/acl.xsd">
    <acl>
        <resources>
            <resource id="Magento_Backend::admin">
                <resource id="MiVendor_Blog::blog" title="Blog" sortOrder="100">
                    <!-- Recurso padre: acceso al módulo Blog -->
                    <resource id="MiVendor_Blog::post_manage" title="Manage Posts" sortOrder="10"/>
                    <resource id="MiVendor_Blog::category_manage" title="Manage Categories" sortOrder="20"/>
                    <resource id="MiVendor_Blog::settings" title="Settings" sortOrder="30"/>
                </resource>
            </resource>
        </resources>
    </acl>
</config>
```

### 2. Verificación automática con `ADMIN_RESOURCE`

```php
// Magento llama automáticamente _isAllowed() antes de execute()
// _isAllowed() por defecto verifica ADMIN_RESOURCE:

class Delete extends Action
{
    public const ADMIN_RESOURCE = 'MiVendor_Blog::post_manage';

    public function execute(): \Magento\Framework\Controller\Result\Redirect
    {
        // Si el admin no tiene permiso, Magento redirige al dashboard
        // con "Access Denied" antes de llegar aquí
        $postId = (int) $this->getRequest()->getParam('id');
        // ... eliminar post
    }
}
```

### 3. `_isAllowed()` personalizado

```php
// Cuando necesitas lógica más compleja:
protected function _isAllowed(): bool
{
    // Editar: puede editar posts O ser superadmin
    return $this->_authorization->isAllowed('MiVendor_Blog::post_manage')
        || $this->_authorization->isAllowed('Magento_Backend::all');
}
```

### 4. Verificar ACL en código (sin controller)

```php
use Magento\Framework\AuthorizationInterface;

class SomeService
{
    public function __construct(
        private readonly AuthorizationInterface $authorization
    ) {}

    public function canDeletePost(): bool
    {
        return $this->authorization->isAllowed('MiVendor_Blog::post_manage');
    }
}
```

## Routes del admin

```xml
<!-- app/code/MiVendor/Blog/etc/adminhtml/routes.xml -->
<?xml version="1.0"?>
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:framework:App/etc/routes.xsd">
    <router id="admin">
        <route id="blog" frontName="blog">
            <module name="MiVendor_Blog"/>
        </route>
    </router>
</config>
```

**URL resultante**: `/admin/blog/post/index`

Anatomía: `/{adminPath}/{frontName}/{controllerDir}/{action}`
- `/admin` — el path del admin (configurable en env.php)
- `/blog` — tu frontName
- `/post` — directorio Controller/Adminhtml/Post/
- `/index` — clase Index.php

### NewAction — Mostrar formulario de creación

```php
// Controller/Adminhtml/Post/NewAction.php
// (NewAction porque "new" es palabra reservada en PHP)
class NewAction extends Action
{
    public const ADMIN_RESOURCE = 'MiVendor_Blog::post_manage';

    public function execute(): \Magento\Framework\Controller\Result\Forward
```

### Edit — Formulario de edición

```php
// Controller/Adminhtml/Post/Edit.php
class Edit extends Action
{
    public const ADMIN_RESOURCE = 'MiVendor_Blog::post_manage';

    public function __construct(
        Context $context,
        private readonly PageFactory $resultPageFactory,
        private readonly PostRepositoryInterface $postRepository,
        private readonly \Magento\Framework\Registry $registry
    ) {
        parent::__construct($context);
    }

    public function execute(): \Magento\Framework\View\Result\Page|\Magento\Framework\Controller\Result\Redirect
    {
        $postId = (int) $this->getRequest()->getParam('id');

        if ($postId) {
            try {
                $post = $this->postRepository->getById($postId);
                $this->registry->register('current_post', $post);
            } catch (\Magento\Framework\Exception\NoSuchEntityException $e) {
                $this->messageManager->addErrorMessage(__('This post no longer exists.'));
                return $this->resultRedirectFactory->create()->setPath('*/*/');
            }
        }

        $resultPage = $this->resultPageFactory->create();
        $title = $postId ? __('Edit Post') : __('New Post');
        $resultPage->getConfig()->getTitle()->prepend($title);
        return $resultPage;
    }
}
```

### Save — Procesar el formulario

```php
// Controller/Adminhtml/Post/Save.php
class Save extends Action implements HttpPostActionInterface
{
    public const ADMIN_RESOURCE = 'MiVendor_Blog::post_manage';

    public function __construct(
        Context $context,
        private readonly PostRepositoryInterface $postRepository,
        private readonly PostInterfaceFactory $postFactory,
        private readonly \Magento\Framework\Api\DataObjectHelper $dataObjectHelper
    ) {
        parent::__construct($context);
    }

    public function execute(): \Magento\Framework\Controller\Result\Redirect
    {
        $resultRedirect = $this->resultRedirectFactory->create();
        $data = $this->getRequest()->getPostValue();

        if (!$data) {
            return $resultRedirect->setPath('*/*/');
        }

        $postId = (int) ($data['id'] ?? 0);

        try {
            // Cargar existente o crear nuevo
            $post = $postId
                ? $this->postRepository->getById($postId)
                : $this->postFactory->create();

            // Popular con los datos del formulario
            $this->dataObjectHelper->populateWithArray(
                $post,
                $data,
                PostInterface::class
            );

            $this->postRepository->save($post);
            $this->messageManager->addSuccessMessage(__('Post saved successfully.'));

            // "Save and Continue Edit" vs "Save"
            if ($this->getRequest()->getParam('back') === 'edit') {
                return $resultRedirect->setPath('*/*/edit', ['id' => $post->getId()]);
            }

            return $resultRedirect->setPath('*/*/');

        } catch (\Magento\Framework\Exception\LocalizedException $e) {
            $this->messageManager->addErrorMessage($e->getMessage());
        } catch (\Exception $e) {
            $this->messageManager->addExceptionMessage(
                $e,
                __('Something went wrong while saving the post.')
            );
        }

        // Si hay error, volver al formulario con los datos
        $this->_session->setFormData($data);
        $redirect = $postId
            ? $resultRedirect->setPath('*/*/edit', ['id' => $postId])
            : $resultRedirect->setPath('*/*/new');

        return $redirect;
    }
}
```

### Delete — Eliminar un registro

```php
// Controller/Adminhtml/Post/Delete.php
class Delete extends Action implements HttpPostActionInterface
{
    public const ADMIN_RESOURCE = 'MiVendor_Blog::post_manage';

    public function execute(): \Magento\Framework\Controller\Result\Redirect
    {
        $resultRedirect = $this->resultRedirectFactory->create();
        $postId = (int) $this->getRequest()->getParam('id');

        if (!$postId) {
            $this->messageManager->addErrorMessage(__('We can\'t find a post to delete.'));
            return $resultRedirect->setPath('*/*/');
        }

        try {
            $this->postRepository->deleteById($postId);
            $this->messageManager->addSuccessMessage(__('Post deleted successfully.'));
        } catch (\Magento\Framework\Exception\NoSuchEntityException $e) {
            $this->messageManager->addErrorMessage(__('This post no longer exists.'));
        } catch (\Exception $e) {
            $this->messageManager->addExceptionMessage(
                $e,
                __('Something went wrong while deleting the post.')
            );
            return $resultRedirect->setPath('*/*/edit', ['id' => $postId]);
        }

        return $resultRedirect->setPath('*/*/');
    }
}
```

## El patrón `*/*/` en redirects

`*/*/` es un shorthand de Magento para el área admin:

```php
// */*/       → {module}/{controller}/index
// */*/index  → {module}/{controller}/index
// */*/edit   → {module}/{controller}/edit

// Equivalente al wildcard expandido:
$resultRedirect->setPath('blog/post/index');
$resultRedirect->setPath('*/*/');  // ← mismo resultado desde Post/Delete
```

El sistema resuelve `*` con el módulo y controlador actuales. Solo funciona dentro del mismo módulo/controller.

## MessageManager: tipos de mensajes

```php
// En cualquier admin controller:

// ✅ Éxito (verde)
$this->messageManager->addSuccessMessage(__('Post saved.'));

// ❌ Error (rojo)
$this->messageManager->addErrorMessage(__('Could not save post.'));

// ⚠️ Advertencia (amarillo)
$this->messageManager->addWarningMessage(__('Post saved, but images failed to upload.'));

// ℹ️ Información (azul)
$this->messageManager->addNoticeMessage(__('Remember to flush cache after this change.'));

// Desde una excepción (incluye el mensaje de la excepción en el log)
$this->messageManager->addExceptionMessage($e, __('An error occurred.'));
```

Los mensajes se almacenan en sesión y se renderizan en el siguiente request (patrón PRG).

## MassAction Controller

```php
// Controller/Adminhtml/Post/MassDelete.php
use Magento\Ui\Component\MassAction\Filter;
use MiVendor\Blog\Model\ResourceModel\Post\CollectionFactory;

class MassDelete extends Action implements HttpPostActionInterface
{
    public const ADMIN_RESOURCE = 'MiVendor_Blog::post_manage';

    public function __construct(
        Context $context,
        private readonly Filter $filter,
        private readonly CollectionFactory $collectionFactory,
        private readonly PostRepositoryInterface $postRepository
    ) {
        parent::__construct($context);
    }

    public function execute(): \Magento\Framework\Controller\Result\Redirect
    {
        // El Filter extrae los IDs seleccionados del UI Grid
        $collection = $this->filter->getCollection(
            $this->collectionFactory->create()
        );

        $deleted = 0;
        foreach ($collection as $post) {
            try {
                $this->postRepository->delete($post);
                $deleted++;
            } catch (\Exception $e) {
                $this->messageManager->addErrorMessage(
                    __('Could not delete post ID %1: %2', $post->getId(), $e->getMessage())
                );
            }
        }

        if ($deleted) {
            $this->messageManager->addSuccessMessage(
                __('A total of %1 post(s) have been deleted.', $deleted)
            );
        }

        return $this->resultRedirectFactory->create()->setPath('*/*/');
    }
}
```

## Resumen: estructura de un módulo admin completo

```
Controller/Adminhtml/Post/
├── Index.php         ← Listado (GET)
├── NewAction.php     ← Forward a Edit (GET)
├── Edit.php          ← Formulario (GET)
├── Save.php          ← Guardar (POST)
├── Delete.php        ← Eliminar (POST)
└── MassDelete.php    ← Eliminar varios (POST, desde UI Grid)

etc/
├── adminhtml/
│   ├── routes.xml    ← frontName del admin
│   └── menu.xml      ← Entrada en el menú
└── acl.xml           ← Recursos de permiso
```

```
ADMIN_RESOURCE   →  ACL automático en cada controller
_isAllowed()     →  Override cuando necesitas lógica custom
*/*/             →  Redirect al index del controller actual
MessageManager   →  Mensajes flash (éxito/error/aviso)
_session         →  Flash data entre requests (ej: repoblar formulario)
```

## Ejercicios

### Ejercicio 1 — Controller de categorías con ACL separado

Tienes `MiVendor_Blog::post_manage` para posts y `MiVendor_Blog::category_manage` para categorías. Escribe el `Delete` controller para categorías que:
1. Solo permita acceso con `category_manage`
2. Maneje el caso de que la categoría tenga posts (lanzar `LocalizedException`)
3. Redirija al listado con mensaje apropiado en cada caso

<details>
<summary>Ver solución</summary>

```php
<?php
// Controller/Adminhtml/Category/Delete.php
namespace MiVendor\Blog\Controller\Adminhtml\Category;

use Magento\Backend\App\Action;
use Magento\Backend\App\Action\Context;
use Magento\Framework\App\Action\HttpPostActionInterface;
use MiVendor\Blog\Api\CategoryRepositoryInterface;

class Delete extends Action implements HttpPostActionInterface
{
    public const ADMIN_RESOURCE = 'MiVendor_Blog::category_manage';

    public function __construct(
        Context $context,
        private readonly CategoryRepositoryInterface $categoryRepository
    ) {
        parent::__construct($context);
    }

    public function execute(): \Magento\Framework\Controller\Result\Redirect
    {
        $resultRedirect = $this->resultRedirectFactory->create();
        $categoryId = (int) $this->getRequest()->getParam('id');

        if (!$categoryId) {
            $this->messageManager->addErrorMessage(__('Invalid category ID.'));
            return $resultRedirect->setPath('*/*/');
        }

        try {
            $this->categoryRepository->deleteById($categoryId);
            $this->messageManager->addSuccessMessage(__('Category has been deleted.'));
            return $resultRedirect->setPath('*/*/');

        } catch (\Magento\Framework\Exception\LocalizedException $e) {
            // Captura específica — por ejemplo "Category has associated posts"
            $this->messageManager->addErrorMessage($e->getMessage());
            return $resultRedirect->setPath('*/*/edit', ['id' => $categoryId]);

        } catch (\Exception $e) {
            $this->messageManager->addExceptionMessage(
                $e,
                __('Something went wrong while deleting the category.')
            );
            return $resultRedirect->setPath('*/*/edit', ['id' => $categoryId]);
        }
    }
}
```

```php
// En CategoryRepository::deleteById() lanzas la excepción si hay posts:
public function deleteById(int $categoryId): bool
{
    $category = $this->getById($categoryId);

    $postCount = $this->postCollectionFactory->create()
        ->addFieldToFilter('category_id', $categoryId)
        ->getSize();

    if ($postCount > 0) {
        throw new \Magento\Framework\Exception\LocalizedException(
            __('Cannot delete category with %1 associated post(s). Remove the posts first.', $postCount)
        );
    }

    return $this->categoryResource->delete($category);
}
```

**Por qué `LocalizedException` y no `\Exception`**: `LocalizedException` en Magento significa "error esperado con mensaje para el usuario". El controller la captura y muestra el mensaje directamente. `\Exception` es para errores inesperados — se loguea con `addExceptionMessage`.

</details>

### Ejercicio 2 — Save con "Save and Continue Edit"

Escribe `MiVendor\Faq\Controller\Adminhtml\Question\Save` que:
1. Guarde la pregunta via `QuestionRepositoryInterface`
2. Si el formulario tiene `back=edit`, redirija de vuelta al edit con el ID guardado
3. Si hay error de validación (`LocalizedException`), vuelva al formulario con los datos del POST

<details>
<summary>Ver solución</summary>

```php
<?php
namespace MiVendor\Faq\Controller\Adminhtml\Question;

use Magento\Backend\App\Action;
use Magento\Backend\App\Action\Context;
use Magento\Framework\App\Action\HttpPostActionInterface;
use MiVendor\Faq\Api\QuestionRepositoryInterface;
use MiVendor\Faq\Api\Data\QuestionInterfaceFactory;

class Save extends Action implements HttpPostActionInterface
{
    public const ADMIN_RESOURCE = 'MiVendor_Faq::question_manage';

    public function __construct(
        Context $context,
        private readonly QuestionRepositoryInterface $questionRepository,
        private readonly QuestionInterfaceFactory $questionFactory
    ) {
        parent::__construct($context);
    }

    public function execute(): \Magento\Framework\Controller\Result\Redirect
    {
        $resultRedirect = $this->resultRedirectFactory->create();
        $data = $this->getRequest()->getPostValue();

        if (empty($data)) {
            return $resultRedirect->setPath('*/*/');
        }

        $questionId = (int) ($data['question_id'] ?? 0);

        try {
            $question = $questionId
                ? $this->questionRepository->getById($questionId)
                : $this->questionFactory->create();

            $question->setTitle($data['title'] ?? '');
            $question->setContent($data['content'] ?? '');
            $question->setIsActive((bool) ($data['is_active'] ?? false));

            $saved = $this->questionRepository->save($question);
            $this->messageManager->addSuccessMessage(__('Question saved successfully.'));

            if ($this->getRequest()->getParam('back') === 'edit') {
                return $resultRedirect->setPath(
                    '*/*/edit',
                    ['question_id' => $saved->getId()]
                );
            }

            return $resultRedirect->setPath('*/*/');

        } catch (\Magento\Framework\Exception\LocalizedException $e) {
            $this->messageManager->addErrorMessage($e->getMessage());
        } catch (\Exception $e) {
            $this->messageManager->addExceptionMessage($e, __('Something went wrong while saving.'));
        }

        // Guardar datos en sesión para repoblar el formulario
        $this->_session->setFormData($data);

        return $questionId
            ? $resultRedirect->setPath('*/*/edit', ['question_id' => $questionId])
            : $resultRedirect->setPath('*/*/new');
    }
}
```

```php
// En el DataProvider del formulario — recuperar datos guardados en sesión:
public function getData(): array
{
    $data = $this->backendSession->getFormData(true); // true = limpiar sesión
    if ($data) {
        return [$data['question_id'] ?? null => $data];
    }
    // ... cargar desde repositorio si no hay datos en sesión
}
```

**El patrón completo**:
- Save exitoso → `addSuccessMessage` → redirect a index (o edit si `back=edit`)
- `LocalizedException` → `addErrorMessage` → guardar POST en `_session` → redirect al formulario
- `\Exception` inesperada → `addExceptionMessage` (loguea) → mismo comportamiento

</details>
