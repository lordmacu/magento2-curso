# 3.3 — Sequence y Dependencias entre Módulos

> **Objetivo**: Entender cómo declarar que tu módulo depende de otro, qué implica esa dependencia, el orden de carga y cómo evitar los errores más comunes de módulos que se cargan en el orden incorrecto.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [3.2 — Crear tu Primer Módulo](3.2-primer-modulo.md)

---

## Por qué existe el sistema de sequence

Magento carga más de 200 módulos. Algunos dependen de otros — si el módulo de Checkout se carga antes que el de Catálogo, va a fallar porque necesita clases que aún no existen.

🔄 **Laravel**: En Laravel los Service Providers tienen `$defer` y el sistema de bootstrapping resuelve el orden. En Magento el orden se declara explícitamente en `module.xml` con `<sequence>`.

---

## Tipos de dependencia

Hay dos conceptos que se confunden frecuentemente:

### 1. `<sequence>` — Orden de carga

```xml
<!-- etc/module.xml -->
<module name="MiVendor_Blog">
    <sequence>
        <module name="Magento_Cms"/>
    </sequence>
</module>
```

`<sequence>` garantiza que `Magento_Cms` se carga **antes** que `MiVendor_Blog`. Pero **no** declara una dependencia dura — si `Magento_Cms` está deshabilitado, `MiVendor_Blog` puede seguir funcionando (potencialmente).

**Cuándo usar `<sequence>`**:
- Tu módulo extiende layout XML de otro módulo (`default.xml`, handles específicos)
- Tu módulo usa observers que deben ejecutarse después de los del otro módulo
- Tu módulo usa configuración que otro módulo registra en `config.xml`
- Tu módulo sobrescribe templates de otro módulo

### 2. `require` en composer.json — Dependencia dura

```json
{
    "require": {
        "magento/module-catalog": "*",
        "magento/module-customer": "*"
    }
}
```

Esta es la dependencia real — si el paquete no está instalado, Composer falla. Úsala cuando tu código **no puede funcionar** sin el otro módulo (herencias de clases, uso de interfaces, etc.).

## Casos prácticos de `<sequence>`

### Caso 1 — Tu módulo extiende el layout de otro

```xml
<!-- MiVendor_Blog/etc/module.xml -->
<module name="MiVendor_Blog">
    <sequence>
        <module name="Magento_Theme"/>
        <module name="Magento_Cms"/>
    </sequence>
</module>
```

```xml
<!-- MiVendor_Blog/view/frontend/layout/default.xml -->
<!-- Modifica el layout default de Magento — necesita que Theme se cargue primero -->
<page>
    <body>
        <referenceBlock name="header.links">
            <block class="..." name="blog.header.link" .../>
        </referenceBlock>
    </body>
</page>
```

Sin el `<sequence>`, el `referenceBlock` podría aplicarse antes de que `Magento_Theme` haya registrado el bloque `header.links` — resultado: el bloque no existe y el layout falla silenciosamente.

### Caso 2 — Tu módulo extiende una clase del core

```xml
<!-- MiVendor_CheckoutExtra/etc/module.xml -->
<module name="MiVendor_CheckoutExtra">
    <sequence>
        <module name="Magento_Checkout"/>
        <module name="Magento_Quote"/>
        <module name="Magento_Payment"/>
    </sequence>
</module>
```

### Caso 3 — Módulo que depende de otro módulo tuyo

```xml
<!-- MiVendor_BlogAdmin/etc/module.xml -->
<!-- BlogAdmin extiende Blog — necesita que Blog se cargue primero -->
<module name="MiVendor_BlogAdmin">
    <sequence>
        <module name="MiVendor_Blog"/>
        <module name="Magento_Backend"/>
    </sequence>
</module>
```

## Ver el orden de carga actual

```bash
# Ver todos los módulos en su orden de carga
php bin/magento module:status

# Ver la secuencia resuelta para un módulo específico
php bin/magento dev:di:info "MiVendor\Blog\Model\AlgunaClase"

# El orden real está en:
cat app/etc/config.php
# Los módulos aparecen en el orden en que Magento los procesa
```

## Dependencias en `composer.json` del módulo

Si distribuyes tu módulo como paquete Composer, las dependencias van en su `composer.json`:

```json
{
    "name": "mivendor/magento2-blog",
    "type": "magento2-module",
    "require": {
        "php": "^8.1",
        "magento/framework": "*",
        "magento/module-cms": "*",
        "magento/module-catalog": "*",
        "magento/module-store": "*"
    },
    "suggest": {
        "magento/module-elasticsearch": "Para búsqueda avanzada de posts"
    }
}
```

- `require` — dependencias obligatorias (Composer falla si no están)
- `suggest` — dependencias opcionales (solo informativo, no bloquea)

## El grafo de dependencias

Magento construye internamente un grafo dirigido acíclico (DAG) con todos los módulos y sus sequences. Si hay un ciclo, falla:

```
MiModuloA → MiModuloB → MiModuloA   ← ERROR: dependencia circular
```

```bash
# Si ves este error:
# "Circular dependency: MiVendor_A depends on MiVendor_B,
#  MiVendor_B depends on MiVendor_A"

# Solución: extraer la lógica compartida a un tercer módulo:
MiVendor_ACore  ←  MiVendor_A
                ←  MiVendor_B
```

## Deshabilitar un módulo con dependientes

```bash
# Si intentas deshabilitar un módulo del que otros dependen:
php bin/magento module:disable Magento_Catalog

# Error:
# "The following modules depend on Magento_Catalog and must be
#  disabled before it: Magento_CatalogSearch, Magento_ConfigurableProduct..."

# Debes deshabilitar primero todos los dependientes:
php bin/magento module:disable MiVendor_Blog
php bin/magento module:disable Magento_Catalog  # ahora sí
```

## Verificar dependencias de un módulo

```bash
# Ver de qué módulos depende el tuyo (sequence)
grep -r "MiVendor_Blog" app/code/MiVendor/Blog/etc/module.xml

# Ver qué módulos dependen del tuyo
grep -r "MiVendor_Blog" app/code/ vendor/magento/ --include="module.xml"

# Lista completa de dependencias resueltas
php bin/magento module:status --enabled
```

## Reglas prácticas

```
¿Usas clases PHP de otro módulo?
    → require en composer.json + sequence en module.xml

¿Modificas layout XML de otro módulo?
    → sequence en module.xml

¿Tu módulo puede funcionar sin el otro pero lo mejora?
    → Solo suggest en composer.json, sin sequence obligatorio

¿Tus observers deben ejecutarse después de los del otro módulo?
    → sequence en module.xml

¿Dos módulos tuyos y uno extiende al otro?
    → sequence en el módulo que extiende, apuntando al base
```

## Resumen

```xml
<!-- Patrón completo de module.xml con dependencias -->
<config>
    <module name="MiVendor_MiModulo" setup_version="1.0.0">
        <sequence>
            <!-- Módulos que deben cargarse ANTES -->
            <module name="Magento_Catalog"/>
            <module name="Magento_Customer"/>
            <module name="MiVendor_Base"/>
        </sequence>
    </module>
</config>
```

```
sequence      →  orden de carga (module.xml)
require       →  dependencia dura (composer.json)
suggest       →  dependencia opcional (composer.json)
```
