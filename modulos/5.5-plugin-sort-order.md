# 5.5 — Plugin Sort Order: Orden de Ejecución con Múltiples Plugins

> **Objetivo**: Entender cómo Magento ordena y ejecuta múltiples plugins sobre el mismo método, cómo controlar ese orden con `sortOrder`, y cómo deshabilitar plugins de otros módulos.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [5.4 — Around Plugin](5.4-around-plugin.md)

---

## El problema: múltiples módulos sobre el mismo método

En un proyecto real, varios módulos pueden tener plugins sobre el mismo método. Magento los encadena todos — el orden importa.

```xml
<!-- Módulo A -->
<type name="Magento\Catalog\Api\ProductRepositoryInterface">
    <plugin name="modulo_a_plugin" type="ModuloA\Plugin\ProductPlugin" sortOrder="10"/>
</type>

<!-- Módulo B -->
<type name="Magento\Catalog\Api\ProductRepositoryInterface">
    <plugin name="modulo_b_plugin" type="ModuloB\Plugin\ProductPlugin" sortOrder="20"/>
</type>

<!-- Módulo C -->
<type name="Magento\Catalog\Api\ProductRepositoryInterface">
    <plugin name="modulo_c_plugin" type="ModuloC\Plugin\ProductPlugin" sortOrder="30"/>
</type>
```

---

## Orden de ejecución

### Before plugins — sortOrder ASC (menor primero)

```
sortOrder=10  → before plugin A
sortOrder=20  → before plugin B
sortOrder=30  → before plugin C
              → método original ejecuta
```

### After plugins — sortOrder DESC (mayor primero)

Los after plugins se ejecutan en orden **inverso** al sortOrder — el último before es el primero en after:

```
              → método original ejecuta
sortOrder=30  → after plugin C
sortOrder=20  → after plugin B
sortOrder=10  → after plugin A
```

### Visualización completa

```
[before A (10)] → [before B (20)] → [before C (30)]
                                          ↓
                                   método original
                                          ↓
[after A (10)]  ← [after B (20)]  ← [after C (30)]
```

Es como una pila LIFO (Last In, First Out) para los after plugins.

---

## Around plugins en la cadena

Los around plugins se anidan según su sortOrder:

```
around A (10) {
    // antes
    around B (20) {
        // antes
        around C (30) {
            // antes
            método original
            // después
        }
        // después
    }
    // después
}
```

Cada `$proceed()` llama al siguiente around en la cadena.

## Ejemplo práctico con tres plugins

```php
// Plugin A (sortOrder=10)
class PluginA
{
    public function beforeGetById($subject, $id): ?array
    {
        echo "Before A\n";
        return null;
    }

    public function afterGetById($subject, $result): ProductInterface
    {
        echo "After A\n";
        return $result;
    }
}

// Plugin B (sortOrder=20)
class PluginB
{
    public function beforeGetById($subject, $id): ?array
    {
        echo "Before B\n";
        return null;
    }

    public function afterGetById($subject, $result): ProductInterface
    {
        echo "After B\n";
        return $result;
    }
}

// Plugin C (sortOrder=30)
class PluginC
{
    public function beforeGetById($subject, $id): ?array
    {
        echo "Before C\n";
        return null;
    }

    public function afterGetById($subject, $result): ProductInterface
    {
        echo "After C\n";
        return $result;
    }
}
```

**Output**:
```
Before A      ← sortOrder=10, primero
Before B      ← sortOrder=20
Before C      ← sortOrder=30
[método original ejecuta]
After C       ← sortOrder=30, primero en after (inverso)
After B       ← sortOrder=20
After A       ← sortOrder=10, último en after
```

## Definir el sortOrder correcto

```xml
<!-- Plugins del core de Magento usan valores bajos: 10, 20, 30... -->
<!-- Tus plugins deben usar valores que reflejen su posición deseada -->

<!-- Ejecutar ANTES que otros módulos -->
<plugin name="mi_plugin_prioritario" type="..." sortOrder="5"/>

<!-- Ejecutar DESPUÉS que otros módulos (valor alto) -->
<plugin name="mi_plugin_final" type="..." sortOrder="200"/>

<!-- Sin sortOrder definido — Magento asigna un orden no garantizado -->
<plugin name="mi_plugin_sin_orden" type="..."/>
```

**Regla práctica**:
- Plugins de validación temprana → `sortOrder` bajo (5-20)
- Plugins de logging/auditoría → `sortOrder` alto (100-200)
- Plugins de caché → `sortOrder` muy bajo (1-5) para evitar llamadas innecesarias

---

## Deshabilitar un plugin de otro módulo

```xml
<!-- Tu di.xml puede deshabilitar plugins de otros módulos -->
<type name="Magento\Catalog\Api\ProductRepositoryInterface">
    <plugin name="nombre_exacto_del_plugin_externo"
            disabled="true"/>
</type>
```

El `name` debe ser exactamente el mismo que usó el módulo original. Para encontrarlo:

```bash
# Buscar el nombre del plugin en el código del módulo
grep -r "plugin name=" vendor/magento/module-catalog/etc/ --include="di.xml"
```

## Casos donde el orden importa criticamente

### Validación antes de caché

```xml
<!-- La validación debe ir ANTES del plugin de caché -->
<!-- Si el caché va primero, retorna resultado sin validar -->

<plugin name="validation_plugin"  type="..." sortOrder="5"/>   <!-- va primero -->
<plugin name="cache_plugin"       type="..." sortOrder="10"/>  <!-- va después -->
```

### Transformación en cadena

```xml
<!-- Plugin que transforma el resultado de otro plugin -->
<plugin name="normalize_plugin"   type="..." sortOrder="10"/>  <!-- normaliza primero -->
<plugin name="format_plugin"      type="..." sortOrder="20"/>  <!-- formatea después -->
<!-- format_plugin recibe el resultado ya normalizado de normalize_plugin -->
```

### Logging al inicio y al final

```xml
<!-- Log de entrada — debe ser el primero -->
<plugin name="log_input"   type="..." sortOrder="1"/>

<!-- Log de salida — debe ser el último -->
<plugin name="log_output"  type="..." sortOrder="999"/>
```

---

## Plugins con mismo sortOrder

Si dos plugins tienen el mismo `sortOrder`, Magento los ordena por el `name` del plugin alfabéticamente. Evita esto — es un comportamiento implícito difícil de razonar.

```xml
<!-- ❌ Mismo sortOrder — orden impredecible -->
<plugin name="plugin_b" type="..." sortOrder="10"/>
<plugin name="plugin_a" type="..." sortOrder="10"/>
<!-- Resultado: plugin_a va primero (alfabético) — difícil de ver *)

<!-- ✅ sortOrders distintos — orden explícito -->
<plugin name="plugin_a" type="..." sortOrder="10"/>
<plugin name="plugin_b" type="..." sortOrder="20"/>
```

---

## Resumen

```
sortOrder define el orden de ejecución:
  Before: ASC (menor sortOrder = primero)
  After:  DESC (mayor sortOrder = primero — inverso al before)
  Around: ASC (igual que before, se anidan)

Estrategia:
  sortOrder bajo (1-20)   → validaciones, caché, control de acceso
  sortOrder medio (50-100) → lógica de negocio
  sortOrder alto (100-999) → logging, auditoría, notificaciones

Deshabilitar plugin externo:
  <plugin name="nombre_exacto" disabled="true"/>

Verificar orden:
  php bin/magento dev:di:info "Vendor\Clase"
```
