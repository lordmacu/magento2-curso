# 6.3 — Disparar tus Propios Eventos con dispatch()

> **Objetivo**: Aprender a crear y disparar eventos propios en tu módulo — hacerlo extensible por otros módulos sin que tengan que modificar tu código.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [6.2 — events.xml](6.2-events-xml.md)

---

## Por qué disparar tus propios eventos

Cuando creas un módulo que otros módulos o proyectos van a usar, los eventos son la forma de darles puntos de extensión sin modificar tu código.

```
Tu módulo dispara: 'mivendor_blog_post_published'
Otro módulo escucha y: envía notificación, actualiza sitemap, notifica al ERP...

Tu código no sabe nada de esos módulos — bajo acoplamiento.
```

---

## La forma correcta: inyectar EventManager

```php
namespace MiVendor\Blog\Model;

use Magento\Framework\Event\ManagerInterface as EventManager;

class PostService
{
    public function __construct(
        private readonly EventManager      $eventManager,
        private readonly PostFactory       $postFactory,
        private readonly ResourceModel\Post $postResource,
    ) {}

    public function publish(int $postId): Post
    {
        $post = $this->postFactory->create();
        $this->postResource->load($post, $postId);

        // Disparar evento ANTES de publicar (permite cancelar con around plugin)
        $this->eventManager->dispatch('mivendor_blog_post_publish_before', [
            'post'    => $post,
            'post_id' => $postId,
        ]);

        $post->setStatus(Post::STATUS_PUBLISHED);
        $post->setPublishedAt(date('Y-m-d H:i:s'));
        $this->postResource->save($post);

        // Disparar evento DESPUÉS de publicar
        $this->eventManager->dispatch('mivendor_blog_post_publish_after', [
            'post' => $post,
        ]);

        return $post;
    }
}
```

---

## Convención de nombres de eventos

```
{vendor}_{module}_{entity}_{action}_{timing}

Ejemplos:
  mivendor_blog_post_publish_before    ← antes de publicar
  mivendor_blog_post_publish_after     ← después de publicar
  mivendor_blog_post_delete_after      ← después de eliminar
  mivendor_blog_comment_save_before    ← antes de guardar comentario
  mivendor_blog_import_finish_after    ← después de importar

Magento usa:
  catalog_product_save_before
  catalog_product_save_after
  sales_order_place_after
  customer_login
```

**Regla**: siempre en `snake_case`, siempre con tu vendor como prefijo, siempre con `_before` o `_after` al final.

---

## Qué datos pasar en el evento

```php
// Pasa todos los datos que un Observer podría necesitar
$this->eventManager->dispatch('mivendor_blog_post_publish_after', [
    'post'         => $post,           // el objeto principal
    'post_id'      => $post->getId(),  // id por conveniencia
    'published_by' => $this->getCurrentUserId(), // contexto
    'store_id'     => $this->storeManager->getStore()->getId(),
]);
```

**Principio**: mejor pasar más datos que menos — los Observers solo usan lo que necesitan. Si alguien necesita datos que no pasaste, tendrá que hacer una query adicional.

---

## Pasar objetos mutables vs inmutables

Cuando pasas un objeto mutable (como un Model), los observers **pueden modificarlo**:

```php
// Dispatching con objeto mutable
$this->eventManager->dispatch('mivendor_blog_post_save_before', [
    'post' => $post,  // los observers PUEDEN modificar $post
]);

// Después del dispatch, $post puede haber sido modificado por un observer
$this->postResource->save($post); // guarda los cambios del observer también
```

Esto es poderoso pero peligroso — documenta claramente si tu evento permite mutación.

## DataObject para datos del evento

Para datos complejos o cuando quieres que los observers puedan modificar valores:

```php
use Magento\Framework\DataObject;

$transport = new DataObject([
    'post'         => $post,
    'should_send_email' => true,  // ← observer puede cambiar esto
    'recipients'   => [],
]);

$this->eventManager->dispatch('mivendor_blog_post_publish_after', [
    'transport' => $transport,
]);

// Leer el resultado modificado por observers
if ($transport->getShouldSendEmail()) {
    $this->emailService->send($transport->getPost(), $transport->getRecipients());
}
```

```php
// En el Observer — modifica el DataObject
class AddAdminToRecipients implements ObserverInterface
{
    public function execute(Observer $observer): void
    {
        $transport = $observer->getEvent()->getTransport();
        $recipients = $transport->getRecipients();
        $recipients[] = 'admin@tienda.com';
        $transport->setRecipients($recipients);
    }
}
```

## Par de eventos before/after — el patrón estándar

Siempre dispara eventos en pares — uno antes y uno después:

```php
public function deletePost(int $postId): void
{
    $post = $this->getById($postId);

    // Antes — permite que observers cancelen con una excepción
    $this->eventManager->dispatch('mivendor_blog_post_delete_before', [
        'post' => $post,
    ]);

    $this->postResource->delete($post);

    // Después — para logging, limpieza, notificaciones
    $this->eventManager->dispatch('mivendor_blog_post_delete_after', [
        'post'    => $post,
        'post_id' => $postId,
    ]);
}
```

**El evento `_before`**: permite validaciones, modificar datos, o lanzar excepción para cancelar.
**El evento `_after`**: para efectos secundarios seguros: logging, caché, notificaciones, sincronización.

## Ejemplo completo: módulo extensible

```php
namespace MiVendor\Blog\Model;

class ImportService
{
    public function __construct(
        private readonly EventManager   $eventManager,
        private readonly PostFactory    $postFactory,
        private readonly PostRepository $postRepository,
    ) {}

    public function importFromCsv(string $filePath): array
    {
        $results = ['imported' => 0, 'errors' => []];

        // Evento de inicio de importación
        $this->eventManager->dispatch('mivendor_blog_import_start', [
            'file_path' => $filePath,
        ]);

        $rows = $this->parseCsv($filePath);

        foreach ($rows as $row) {
            try {
                // Evento antes de importar cada fila
                $transport = new DataObject(['row' => $row, 'skip' => false]);
                $this->eventManager->dispatch('mivendor_blog_import_row_before', [
                    'transport' => $transport,
                ]);

                // Un observer puede marcar la fila para saltarse
                if ($transport->getSkip()) {
                    continue;
                }

                $post = $this->postFactory->create();
                $post->setData($transport->getRow());
                $this->postRepository->save($post);

                $results['imported']++;

                // Evento después de importar cada fila
                $this->eventManager->dispatch('mivendor_blog_import_row_after', [
                    'post' => $post,
                    'row'  => $row,
                ]);

            } catch (\Exception $e) {
                $results['errors'][] = $e->getMessage();
            }
        }

        // Evento de fin de importación
        $this->eventManager->dispatch('mivendor_blog_import_finish', [
            'results'   => $results,
            'file_path' => $filePath,
        ]);

        return $results;
    }
}
```

## Resumen

```php
// Inyectar
use Magento\Framework\Event\ManagerInterface as EventManager;

// Disparar
$this->eventManager->dispatch('vendor_module_entity_action_timing', [
    'key' => $value,
]);

// Convención de nombre:
// {vendor}_{module}_{entity}_{action}_{before|after}

// Patrón par:
// dispatch('..._before')  → antes de la operación
// operacion()
// dispatch('..._after')   → después de la operación

// Para datos mutables entre observers:
$transport = new DataObject(['key' => $value]);
$this->eventManager->dispatch('...', ['transport' => $transport]);
$result = $transport->getKey(); // puede haber sido modificado por observers
```

## Ejercicios

### Ejercicio 1 — Disparar evento en tu PostService

Agrega dos eventos a un método `delete()` en `PostService`:
- `mivendor_blog_post_delete_before` — antes de borrar, pasando el post
- `mivendor_blog_post_delete_after` — después de borrar, pasando el post y su ID

<details>
<summary>Ver solución</summary>

```php
// Model/PostService.php
namespace MiVendor\Blog\Model;

use Magento\Framework\Event\ManagerInterface as EventManager;

class PostService
{
    public function __construct(
        private readonly EventManager       $eventManager,
        private readonly PostFactory        $postFactory,
        private readonly ResourceModel\Post $postResource,
    ) {}

    public function delete(int $postId): void
    {
        $post = $this->postFactory->create();
        $this->postResource->load($post, $postId);

        if (!$post->getId()) {
            throw new \Magento\Framework\Exception\NoSuchEntityException(
                __('Post %1 no existe', $postId)
            );
        }

        // Evento before — permite que observers reaccionen antes del borrado
        $this->eventManager->dispatch('mivendor_blog_post_delete_before', [
            'post'    => $post,
            'post_id' => $postId,
        ]);

        $this->postResource->delete($post);

        // Evento after — para cleanup, notificaciones, etc.
        $this->eventManager->dispatch('mivendor_blog_post_delete_after', [
            'post'    => $post,
            'post_id' => $postId,
        ]);
    }
}
```

</details>

### Ejercicio 2 — Observer que reacciona al evento

Crea un Observer que escuche `mivendor_blog_post_delete_after` y loguee qué post fue eliminado y cuándo.

<details>
<summary>Ver solución</summary>

```php
// Observer/LogPostDeletion.php
namespace MiVendor\Blog\Observer;

use Magento\Framework\Event\ObserverInterface;
use Magento\Framework\Event\Observer;
use Psr\Log\LoggerInterface;

class LogPostDeletion implements ObserverInterface
{
    public function __construct(
        private readonly LoggerInterface $logger
    ) {}

    public function execute(Observer $observer): void
    {
        $event  = $observer->getEvent();
        $post   = $event->getPost();
        $postId = $event->getPostId();

        $this->logger->info('Post eliminado', [
            'post_id'    => $postId,
            'post_title' => $post->getTitle(),
            'deleted_at' => date('Y-m-d H:i:s'),
        ]);
    }
}
```

```xml
<!-- etc/events.xml -->
<event name="mivendor_blog_post_delete_after">
    <observer name="mivendor_blog_log_post_deletion"
              instance="MiVendor\Blog\Observer\LogPostDeletion"/>
</event>
```

```bash
php bin/magento cache:flush
tail -f var/log/system.log
# Al eliminar un post verás el log aparecer
```

</details>
