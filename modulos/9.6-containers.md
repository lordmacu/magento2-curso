# 9.6 — Containers vs Blocks: Estructura del Árbol de Layout

> **Objetivo**: Entender la diferencia entre Container y Block, cómo se combinan para construir la estructura de una página, y qué atributos controlan el HTML generado por los containers.

## Container vs Block

```
Container:
  - Solo estructura. Sin clase PHP. Sin template.
  - Genera un tag HTML wrapper (div, section, aside...) si se configura.
  - Contiene otros containers o blocks.
  - No puede tener caché propia.

Block:
  - Tiene clase PHP y/o template .phtml.
  - Genera HTML a través del template o de _toHtml().
  - Puede tener blocks hijos.
  - Puede tener caché configurable.
```

---

## Anatomía de un Container

```xml
<container name="blog.sidebar"
           label="Blog Sidebar"
           htmlTag="aside"
           htmlClass="sidebar blog-sidebar col-left"
           htmlId="blog-sidebar">
    <!-- Los blocks hijos van aquí -->
</container>
```

| Atributo | Descripción |
|---|---|
| `name` | Identificador único en el árbol — requerido |
| `label` | Etiqueta en el Page Builder / admin (no visible en frontend) |
| `htmlTag` | Tag HTML wrapper: `div`, `section`, `aside`, `main`, `header`... Si no se pone, no genera HTML propio |
| `htmlClass` | Clases CSS del wrapper |
| `htmlId` | ID del wrapper |

### Container sin htmlTag

```xml
<!-- Si no tiene htmlTag, no genera ningún HTML propio -->
<!-- Solo actúa como punto de inserción para sus hijos -->
<container name="content.top"/>
```

Los hijos se renderizan directamente sin wrapper.

---

## El árbol base de Magento (simplificado)

```xml
<container name="root" htmlTag="body" htmlClass="page-wrapper">
    <container name="page.wrapper" htmlTag="div" htmlClass="page-wrapper">

        <!-- Header -->
        <container name="header.container" htmlTag="header" htmlClass="page-header">
            <container name="header.panel" htmlTag="div" htmlClass="panel wrapper"/>
            <container name="header.content" htmlTag="div" htmlClass="header content"/>
        </container>

        <!-- Contenido principal -->
        <container name="main.content" htmlTag="main" htmlId="maincontent">
            <container name="page.messages"/>
            <container name="columns">
                <container name="main" htmlTag="div" htmlClass="column main" label="Main Content"/>
                <container name="sidebar.main" htmlTag="div" htmlClass="sidebar sidebar-main"/>
                <container name="sidebar.additional" htmlTag="div" htmlClass="sidebar sidebar-additional"/>
            </container>
        </container>

        <!-- Footer -->
        <container name="footer-container" htmlTag="footer" htmlClass="page-footer"/>
    </container>
</container>
```

---

## Puntos de inserción comunes

```
content             →  área de contenido principal de la página
main                →  column main (dentro de content)
sidebar.main        →  sidebar izquierdo (en páginas de catálogo)
sidebar.additional  →  sidebar derecho
header.panel        →  barra superior del header (links, switchers)
header.content      →  logo, búsqueda, carrito
before.body.end     →  justo antes de </body> (scripts, trackers)
after.body.start    →  justo después de <body> (polyfills, GTM noscript)
```

## Agregar tu container al árbol

```xml
<!-- Crear un container nuevo dentro de main -->
<referenceContainer name="main">
    <container name="blog.content.wrapper"
               htmlTag="section"
               htmlClass="blog-wrapper"
               before="-">
        <block class="MiVendor\Blog\Block\Post\List"
               name="blog.post.list"
               template="MiVendor_Blog::post/list.phtml"/>
    </container>
</referenceContainer>
```

---

## Mover un block a otro container

```xml
<!-- Mover el bloque de newsletter al footer -->
<move element="form.subscribe" destination="footer" before="-"/>
```

```xml
<!-- Mover el sidebar de la derecha a la izquierda -->
<move element="catalog.leftnav" destination="sidebar.main"/>
```

---

## `<move>` — reposicionar elementos

```xml
<!-- Sintaxis completa -->
<move element="nombre.del.elemento"
      destination="nombre.del.container.destino"
      before="otro.elemento"
      after="otro.elemento"/>
```

Útil para reorganizar la estructura sin modificar el XML del módulo que definió el elemento.

## Layouts de una, dos y tres columnas

Magento usa handles de página para controlar el número de columnas:

```xml
<!-- 1 columna (checkout, landing pages) -->
<update handle="page_one_column"/>

<!-- 2 columnas, sidebar izquierdo (default de catálogo) -->
<update handle="page_two_columns_left"/>

<!-- 2 columnas, sidebar derecho -->
<update handle="page_two_columns_right"/>

<!-- 3 columnas -->
<update handle="page_three_columns"/>
```

Desde el controller:
```php
$resultPage = $this->resultPageFactory->create();
$resultPage->getConfig()->setPageLayout('2columns-left');
```

## Ejemplo completo: página de blog con sidebar

```xml
<!-- view/frontend/layout/blog_index_index.xml -->
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd"
      layout="2columns-right">
    <body>
        <!-- Contenido principal -->
        <referenceContainer name="main">
            <container name="blog.main"
                       htmlTag="div"
                       htmlClass="blog-container">
                <block class="Magento\Framework\View\Element\Template"
                       name="blog.post.list"
                       template="MiVendor_Blog::post/list.phtml">
                    <arguments>
                        <argument name="view_model" xsi:type="object">
                            MiVendor\Blog\ViewModel\PostList
                        </argument>
                    </arguments>
                </block>
            </container>
        </referenceContainer>

        <!-- Sidebar derecho -->
        <referenceContainer name="sidebar.additional">
            <container name="blog.sidebar"
                       htmlTag="aside"
                       htmlClass="blog-sidebar">
                <block class="Magento\Framework\View\Element\Template"
                       name="blog.sidebar.recent"
                       template="MiVendor_Blog::sidebar/recent-posts.phtml"
                       before="-">
                    <arguments>
                        <argument name="view_model" xsi:type="object">
                            MiVendor\Blog\ViewModel\RecentPosts
                        </argument>
                    </arguments>
                </block>
                <block class="Magento\Framework\View\Element\Template"
                       name="blog.sidebar.categories"
                       template="MiVendor_Blog::sidebar/categories.phtml">
                    <arguments>
                        <argument name="view_model" xsi:type="object">
                            MiVendor\Blog\ViewModel\Categories
                        </argument>
                    </arguments>
                </block>
            </container>
        </referenceContainer>
    </body>
</page>
```

---

## Resumen

```
Container:
  htmlTag   →  tag HTML wrapper (div, section, aside...)
  htmlClass →  clases CSS
  htmlId    →  ID del elemento
  Sin htmlTag → sin HTML propio, solo punto de inserción

Block:
  class     →  clase PHP (Template o custom)
  template  →  archivo .phtml
  name      →  identificador único

<move element="X" destination="Y"/>  →  reubicar sin modificar XML original

Layouts:
  page_one_column
  page_two_columns_left / right
  page_three_columns
```

## Ejercicios

### Ejercicio 1 — Estructura de página con 3 zonas

Crea el layout XML para la página de listado de blog (`blog_index_index`) con:
- Layout 2 columnas izquierda
- Container `blog.posts` en `main` con clases `blog-posts col-md-8`
- Container `blog.sidebar` en `sidebar.main` con clases `blog-sidebar col-md-4`
- Block de listado en el primero, block de categorías en el segundo

<details>
<summary>Ver solución</summary>

```xml
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd"
      layout="2columns-left">
    <body>
        <referenceContainer name="main">
            <container name="blog.posts.wrapper"
                       htmlTag="div"
                       htmlClass="blog-posts col-md-8">
                <block class="Magento\Framework\View\Element\Template"
                       name="blog.post.list"
                       template="MiVendor_Blog::post/list.phtml">
                    <arguments>
                        <argument name="view_model" xsi:type="object">
                            MiVendor\Blog\ViewModel\PostList
                        </argument>
                    </arguments>
                </block>
            </container>
        </referenceContainer>

        <referenceContainer name="sidebar.main">
            <container name="blog.sidebar.wrapper"
                       htmlTag="div"
                       htmlClass="blog-sidebar col-md-4">
                <block class="Magento\Framework\View\Element\Template"
                       name="blog.sidebar.categories"
                       template="MiVendor_Blog::sidebar/categories.phtml">
                    <arguments>
                        <argument name="view_model" xsi:type="object">
                            MiVendor\Blog\ViewModel\Categories
                        </argument>
                    </arguments>
                </block>
            </container>
        </referenceContainer>
    </body>
</page>
```

### Ejercicio 2 — Mover el bloque de mensajes

En la página de checkout (`checkout_index_index`), mueve el container `page.messages` para que aparezca dentro del container `main`, antes de todo el contenido.

<details>
<summary>Ver solución</summary>

```xml
<!-- view/frontend/layout/checkout_index_index.xml -->
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">
    <body>
        <move element="page.messages" destination="main" before="-"/>
    </body>
</page>
```

**`<move>` vs `<referenceContainer>`**: `<move>` reubica un elemento ya existente en el árbol. `<referenceContainer>` agrega nuevos elementos a un container existente. Son operaciones complementarias.

</details>
