# 1.5 — Estructura de Directorios de Magento 2

> **Objetivo**: Navegar el proyecto sin perderte. Saber exactamente qué hay en cada carpeta, qué puedes tocar y qué no debes tocar nunca.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [1.4 — Magento Layers](1.4-layers.md)

---

## La regla más importante antes de empezar

```
vendor/   ← NUNCA toques esto
app/code/ ← Tu código va aquí
```

Todo lo que está en `vendor/` es código de Composer (el core de Magento + módulos de terceros). Se regenera con `composer install`. Si lo editas, pierdes tus cambios en el próximo `composer update`.

🔄 **Laravel**: Es lo mismo que `vendor/` en Laravel. Nunca editas `vendor/laravel/framework/`. En Magento la regla es aún más estricta porque el core entero vive ahí.

## Vista general del proyecto

```
magento/
│
├── app/                    ← Tu código y configuración
│   ├── code/               ← Módulos propios y de terceros (sin Composer)
│   ├── design/             ← Temas propios
│   ├── etc/                ← Configuración global (env.php, config.php)
│   └── i18n/               ← Traducciones globales
│
├── bin/
│   └── magento             ← El CLI (equivalente a php artisan)
│
├── dev/
│   └── tests/              ← Tests de integración y funcionales del core
│
├── generated/              ← Código auto-generado por el DI compiler (NO tocar)
│   ├── code/               ← Factories, Proxies, Interceptors generados
│   └── metadata/           ← Metadata del container DI
│
├── lib/
│   └── internal/           ← Librerías internas de Magento (no es Composer)
│
├── pub/                    ← Document root del servidor web
│   ├── index.php           ← Entry point de todas las peticiones
│   ├── static/             ← Assets estáticos desplegados (CSS, JS, imágenes de tema)
│   └── media/              ← Archivos subidos (imágenes de productos, etc.)
│
├── setup/                  ← Herramienta de instalación web (raramente usada)
│
├── var/                    ← Archivos temporales y de runtime
│   ├── cache/              ← Caché del filesystem
│   ├── log/                ← Logs (system.log, exception.log, debug.log)
│   ├── page_cache/         ← Full Page Cache built-in
│   ├── report/             ← Reportes de errores (más detallados que los logs)
│   ├── session/            ← Sesiones (si usas filesystem, no Redis)
│   └── tmp/                ← Archivos temporales de imports, exports, etc.
│
├── vendor/                 ← Dependencias de Composer (NO tocar)
│   ├── magento/            ← El core de Magento
│   └── [otros-vendors]/    ← Librerías PHP de terceros
│
├── composer.json           ← Dependencias del proyecto
├── composer.lock           ← Versiones exactas instaladas
└── app/etc/env.php         ← Configuración sensible (DB, Redis, etc.) NO commitear
```

## Las carpetas que más usarás como developer

### `app/code/` — Tu código

```
app/code/
└── VendorName/
    └── ModuleName/
        ├── Api/                    ← Service contracts (interfaces)
        │   └── Data/               ← Data Transfer Objects (interfaces)
        ├── Block/                  ← Presentation Layer: Blocks
        ├── Console/
        │   └── Command/            ← Comandos CLI propios
        ├── Controller/             ← Presentation Layer: Actions HTTP
        │   ├── Index.php           ← /modulo (action por defecto)
        │   └── Post/
        │       ├── View.php        ← /modulo/post/view
        │       └── Save.php        ← /modulo/post/save
        ├── Cron/                   ← Clases ejecutadas por cron jobs
        ├── etc/                    ← Configuración XML del módulo
        │   ├── module.xml          ← Declaración del módulo
        │   ├── di.xml              ← Inyección de dependencias (global)
        │   ├── events.xml          ← Observers (global)
        │   ├── crontab.xml         ← Definición de cron jobs
        │   ├── webapi.xml          ← Endpoints REST
        │   ├── schema.graphqls     ← Schema GraphQL
        │   ├── frontend/           ← Config específica del storefront
        │   │   ├── di.xml
        │   │   ├── routes.xml      ← Rutas de storefront
        │   │   └── events.xml
        │   └── adminhtml/          ← Config específica del admin
        │       ├── di.xml
        │       ├── routes.xml      ← Rutas del admin
        │       └── menu.xml        ← Entrada en el menú del admin
        ├── Helper/                 ← Helpers (usados cada vez menos)
        ├── Model/                  ← Domain + Service + Persistence
        │   ├── Post.php            ← Domain: la entidad
        │   ├── PostRepository.php  ← Service: implementa PostRepositoryInterface
        │   └── ResourceModel/
        │       ├── Post.php        ← Persistence: mapeo a tabla
        │       └── Post/
        │           └── Collection.php  ← Persistence: queries múltiples
        ├── Observer/               ← Event Observers
        │   ├── Frontend/
        │   └── Admin/
        ├── Plugin/                 ← Interceptors (Before/After/Around)
        ├── Setup/                  ← Schema y datos iniciales
        │   ├── db_schema.xml       ← Definición de tablas (declarative schema)
        │   └── Patch/
        │       └── Data/           ← Data patches (seeders)
        ├── ViewModel/              ← Presentation: ViewModels modernos
        ├── view/                   ← Assets, layouts y templates
        │   ├── frontend/
        │   │   ├── layout/         ← Layout XML del storefront
        │   │   ├── templates/      ← Templates .phtml del storefront
        │   │   └── web/            ← JS, CSS, imágenes del módulo
        │   │       ├── css/
        │   │       ├── js/
        │   │       └── images/
        │   └── adminhtml/
        │       ├── layout/         ← Layout XML del admin
        │       ├── templates/      ← Templates .phtml del admin
        │       └── ui_component/   ← UI Components XML (grids, forms)
        ├── registration.php        ← Registra el módulo en Magento
        └── composer.json           ← Info del módulo como paquete Composer
```

💡 **TIP**: No necesitas crear todos estos directorios. Solo crea los que tu módulo realmente usa. Un módulo mínimo solo necesita `etc/module.xml` y `registration.php`.

### `vendor/magento/` — El core (solo para leer)

```
vendor/magento/
├── framework/                  ← El framework base (DI, ORM, Events, etc.)
├── module-catalog/             ← Catálogo de productos y categorías
├── module-checkout/            ← Flujo de checkout
├── module-customer/            ← Gestión de clientes
├── module-sales/               ← Órdenes, facturas, envíos
├── module-quote/               ← Carrito de compras
├── module-cms/                 ← CMS pages y blocks
├── module-search/              ← Motor de búsqueda
├── module-elasticsearch/       ← Integración con Elasticsearch
├── module-inventory/           ← MSI (Multi Source Inventory)
├── module-store/               ← Multistore, Store Views
├── module-tax/                 ← Impuestos
├── module-payment/             ← Métodos de pago base
├── module-shipping/            ← Métodos de envío base
└── ... (170+ módulos más)
```

💡 **TIP**: Cuando quieras extender o modificar algo del core, primero busca el módulo correspondiente en `vendor/magento/`. Lee su código para entender cómo funciona — es la mejor documentación que tiene Magento.

### `generated/` — Código auto-generado

```
generated/
├── code/
│   └── Magento/
│       └── Catalog/
│           └── Model/
│               ├── ProductFactory.php      ← Factory auto-generada
│               ├── Product/Interceptor.php ← Proxy de plugins
│               └── ProductProxy.php       ← Lazy loading proxy
└── metadata/
    └── global.ser                          ← Metadata del DI container
```

Este directorio es generado por `php bin/magento setup:di:compile`. **Nunca lo edites manualmente**.

En modo `developer`, Magento genera estos archivos on-demand (al primer request). En modo `production`, debes compilar explícitamente.

---

### `var/log/` — Tus mejores amigos para debuggear

```
var/log/
├── system.log          ← Log general del sistema
├── exception.log       ← Excepciones PHP no capturadas
├── debug.log           ← Mensajes de debug (solo en modo developer)
├── magento.log         ← Log general de Magento
└── [modulo].log        ← Loggers específicos de módulos
```

Cómo leer logs en tiempo real mientras desarrollas:

```bash
# Desde tu Mac (fuera del container)
docker exec magento_app tail -f /var/www/html/var/log/system.log

# O si quieres ver excepciones
docker exec magento_app tail -f /var/www/html/var/log/exception.log
```

🔄 **Laravel**: Equivalente a `storage/logs/laravel.log`. La diferencia es que Magento tiene múltiples archivos separados por tipo.

---

### `pub/static/` — Assets desplegados

```
pub/static/
└── frontend/
    └── Magento/
        └── luma/
            └── es_MX/
                ├── css/
                │   └── styles-m.css    ← CSS compilado del tema
                ├── js/
                │   └── bundle/         ← JS bundleado
                └── images/
```

Este directorio se **genera automáticamente**. No lo commitees a git.

En modo `developer`: los archivos se generan al primer request (lento pero automático).
En modo `production`: debes correr `php bin/magento setup:static-content:deploy`.

---

### `pub/media/` — Archivos subidos por usuarios/admin

```
pub/media/
├── catalog/
│   └── product/
│       └── cache/        ← Imágenes de productos redimensionadas
├── import/               ← Archivos de importación temporal
└── wysiwyg/              ← Imágenes subidas desde el editor CMS
```

Este directorio debe estar en tu `.gitignore`. En producción va en un storage externo (S3, etc.).

## Dónde vive el código de Magento: `app/code/` vs `vendor/`

Hay **dos lugares** donde pueden vivir los módulos:

```
vendor/             ← Módulos instalados via Composer
    magento/        ← Core de Adobe/Magento
    vendor-name/    ← Módulos de terceros del Marketplace

app/code/           ← Módulos locales (tu código propio)
    MiVendor/
    └── MiModulo/
```

| | `vendor/` | `app/code/` |
|---|---|---|
| Instalado con | `composer require` | Manualmente o copiando |
| Se actualiza con | `composer update` | Nunca (es tu código) |
| ¿Commitear a git? | No (está en .gitignore) | Sí |
| Uso | Core + módulos de terceros | Tu código propio |

## Los archivos de configuración globales más importantes

### `app/etc/env.php` — Variables de entorno

🔄 **Laravel**: Equivalente al `.env`, pero en PHP puro en lugar de key=value.

```php
// app/etc/env.php — NUNCA commitear a git
return [
    'backend' => ['frontName' => 'admin'],    // URL del admin (ofuscar en producción)
    'db' => [
        'connection' => [
            'default' => [
                'host'     => 'db',           // hostname del Docker
                'dbname'   => 'magento',
                'username' => 'magento',
                'password' => 'magento',
                'active'   => '1',
            ],
        ],
        'table_prefix' => '',
    ],
    'cache' => [
        'frontend' => [
            'default' => ['id_prefix' => 'abc_'],
            'page_cache' => ['id_prefix' => 'abc_'],
        ],
    ],
    'session' => ['save' => 'redis', ...],
    'cache_types' => [
        'config'            => 1,  // 1=habilitado, 0=deshabilitado
        'layout'            => 1,
        'block_html'        => 1,
        'collections'       => 1,
        'full_page'         => 1,
        // ...
    ],
    'install' => ['date' => '...'],
    'crypt'   => ['key' => '...'],    // Clave de encriptación — CRÍTICO
];
```

### `app/etc/config.php` — Módulos habilitados

```php
// app/etc/config.php — SÍ se commitea a git
return [
    'modules' => [
        'Magento_Store'           => 1,
        'Magento_Directory'       => 1,
        'Magento_Catalog'         => 1,
        'MiVendor_MiModulo'       => 1,  // Tu módulo aparece aquí
        // ... 150+ módulos
    ],
];
```

Este archivo se genera/actualiza con `php bin/magento module:enable MiVendor_MiModulo`.

## Reglas de qué commitear y qué no

```
✅ Commitear:
app/code/           ← Tu código
app/design/         ← Tus temas
app/etc/config.php  ← Lista de módulos habilitados
composer.json
composer.lock

❌ NO commitear (agregar a .gitignore):
app/etc/env.php     ← Credenciales de DB, Redis, crypt key
generated/          ← Código auto-generado
var/                ← Caché, logs, sesiones
pub/static/         ← Assets generados
pub/media/          ← Archivos subidos
vendor/             ← Dependencias de Composer
```

Un `.gitignore` típico para Magento:

```gitignore
/vendor
/generated
/var
/pub/static
/pub/media
/app/etc/env.php
/.buildpath
/.cache
/.metadata
/.project
/.settings
/atlassian*
/nbproject
/sitemap
/sitemap.xml
/.idea
/.gitattributes
```

## Cómo encontrar código del core para extender

Este flujo lo vas a usar constantemente:

```bash
# 1. Quiero extender el precio de un producto.
#    Busco el archivo relevante:
find vendor/magento -name "Price.php" -path "*/Catalog/*" | head -10

# 2. Encontré: vendor/magento/module-catalog/Model/Product/Type/Price.php
#    Lo abro y leo el método que quiero interceptar

# 3. Creo un Plugin en mi módulo que intercepta ese método
#    app/code/MiVendor/MiModulo/Plugin/Catalog/ProductPricePlugin.php

# 4. Registro el plugin en etc/di.xml o etc/frontend/di.xml
```

💡 **TIP de búsqueda**: Magento tiene más de 170 módulos. Para encontrar lo que buscas usa:

```bash
# Buscar por clase
grep -r "class ProductRepository" vendor/magento --include="*.php" -l

# Buscar por interface
grep -r "interface ProductRepositoryInterface" vendor/magento --include="*.php" -l

# Buscar por evento
grep -r "catalog_product_save_after" vendor/magento --include="*.xml" -l
```
