## Qué es un handle

Un **handle** es un identificador de string que Magento activa durante el procesamiento de un request. Cuando un handle está activo, Magento carga todos los archivos de layout con ese nombre.

```
URL: /catalog/product/view/id/42
Handles activos:
  - default                          (siempre)
  - catalog_product_view             (por la URL)
  - catalog_product_view_id_42       (por el ID)
  - catalog_product_view_type_simple (por el tipo de producto)
  - customer_logged_in               (si el cliente está logueado)
```

Magento carga y fusiona los XML de **todos** los handles activos.

---

## Handles estándar

### `default` — todas las páginas

```xml
<!-- view/frontend/layout/default.xml -->
<!-- Se aplica a TODAS las páginas del frontend — úsalo con cuidado -->
<page ...>
    <body>
        <referenceContainer name="before.body.end">
            <block class="MiVendor\Blog\Block\Tracking"
                   name="mivendor.tracking"
                   template="MiVendor_Blog::tracking.phtml"/>
        </referenceContainer>
    </body>
</page>
```

### Handles por URL (los más comunes)

```
Handle                            URL / Contexto
─────────────────────────────────────────────────────────────
default                           Todas las páginas
cms_index_index                   Homepage (/)
cms_page_view                     Cualquier página CMS
catalog_category_view             Cualquier página de categoría
catalog_product_view              Cualquier página de producto
catalog_product_view_type_simple  Productos simples
catalog_product_view_type_configurable  Productos configurables
customer_account_index            Mi cuenta
customer_account_login            Login
checkout_cart_index               Carrito
checkout_index_index              Checkout
search_result_index               Resultados de búsqueda
```

### Handles por ID de entidad

```
catalog_product_view_id_{ID}      Producto específico (ID=42 → catalog_product_view_id_42)
catalog_category_view_id_{ID}     Categoría específica
cms_page_view_id_{ID}             Página CMS específica
```

## Handle de tu propio módulo

Para tu módulo `blog` con frontName `blog`:

```
blog_index_index    →  /blog/index/index (listado de posts)
blog_post_view      →  /blog/post/view   (ver un post)
blog_post_edit      →  /blog/post/edit
```

**Regla**: El nombre del handle es la ruta URL en minúsculas con `_` en vez de `/`.

## Agregar handles personalizados desde un controller

```php
// Controller/Post/View.php
public function execute(): \Magento\Framework\View\Result\Page
{
    $resultPage = $this->resultPageFactory->create();

    $postId = (int) $this->getRequest()->getParam('id');
    $post = $this->postRepository->getById($postId);

    // Agregar handle específico para este post
    $resultPage->addHandle('blog_post_view_id_' . $postId);

    // Agregar handle basado en categoría del post
    $resultPage->addHandle('blog_post_view_category_' . $post->getCategoryId());

    // Agregar handle si es post destacado
    if ($post->isFeatured()) {
        $resultPage->addHandle('blog_post_view_featured');
    }

    return $resultPage;
}
```

Luego en tu layout:

```xml
<!-- view/frontend/layout/blog_post_view_featured.xml -->
<!-- Solo se aplica a posts destacados -->
<page ...>
    <body>
        <referenceContainer name="content">
            <block class="MiVendor\Blog\Block\Post\FeaturedBadge"
                   name="blog.post.featured.badge"
                   template="MiVendor_Blog::post/featured-badge.phtml"
                   before="-"/>
        </referenceContainer>
    </body>
</page>
```

## Handles de estado del cliente


## Agregar handles desde un Observer

Para handles más complejos basados en lógica de negocio:

```php
// Observer/AddLayoutHandle.php
class AddLayoutHandle implements ObserverInterface
{
    public function execute(\Magento\Framework\Event\Observer $observer): void
    {
        $layout = $observer->getData('layout');
        $fullActionName = $observer->getData('full_action_name');

        // Solo en páginas de producto
        if ($fullActionName !== 'catalog_product_view') {
            return;
        }

        $product = $this->registry->registry('current_product');
        if (!$product) {
            return;
        }

        // Handle basado en atributo del producto
        $brand = $product->getData('brand');
        if ($brand) {
            $layout->getUpdate()->addHandle('catalog_product_view_brand_' . $brand);
        }
    }
}
```

```xml
<!-- etc/frontend/events.xml -->
<event name="layout_load_before">
    <observer name="mivendor_blog_add_handle"
              instance="MiVendor\Blog\Observer\AddLayoutHandle"/>
</event>
```

## `<update handle="..."/>` — incluir otro handle

Puedes forzar la carga de otro handle desde un XML:

```xml
<!-- En blog_post_view.xml — cargar el layout de sidebar también -->
<page ...>
    <update handle="mivendor_blog_sidebar"/>
    <body>
        <!-- ... -->
    </body>
</page>
```

```xml
<!-- view/frontend/layout/mivendor_blog_sidebar.xml -->
<!-- Este handle se puede incluir desde múltiples páginas -->
<layout ...>
    <body>
        <referenceContainer name="sidebar.main">
            <block class="MiVendor\Blog\Block\Sidebar\RecentPosts"
                   name="blog.sidebar.recent"
                   template="MiVendor_Blog::sidebar/recent-posts.phtml"/>
        </referenceContainer>
    </body>
</layout>
```

## Resumen

```
Handle = identificador que activa un archivo XML

Handles comunes:
  default                   →  todas las páginas
  cms_index_index           →  homepage
  catalog_product_view      →  cualquier producto
  catalog_product_view_id_N →  producto con ID específico
  customer_logged_in        →  clientes autenticados

Agregar handles desde controller:
  $resultPage->addHandle('mi_handle_custom')

Incluir handles desde XML:
  <update handle="nombre_del_handle"/>

Nombre del archivo = nombre del handle:
  blog_post_view.xml → handle "blog_post_view"
```

### Ejercicio 1 — Layout diferente según tipo de cliente

Crea los layouts necesarios para mostrar un bloque `MiVendor\Blog\Block\User\WelcomeBanner` con templates diferentes según si el visitante está logueado o no.

<details>
<summary>Ver solución</summary>

```xml
<!-- view/frontend/layout/customer_logged_in.xml -->
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">
    <body>
        <referenceContainer name="content">
            <block class="MiVendor\Blog\Block\User\WelcomeBanner"
                   name="mivendor.welcome.logged"
                   template="MiVendor_Blog::user/welcome-logged.phtml"
                   before="-"/>
        </referenceContainer>
    </body>
</page>
```

```xml
<!-- view/frontend/layout/customer_logged_out.xml -->
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">
    <body>
        <referenceContainer name="content">
            <block class="MiVendor\Blog\Block\User\WelcomeBanner"
                   name="mivendor.welcome.guest"
                   template="MiVendor_Blog::user/welcome-guest.phtml"
                   before="-"/>
        </referenceContainer>
    </body>
</page>
```

**Alternativa más simple**: usar un solo block con lógica PHP dentro que detecte `$this->httpContext->getValue(\Magento\Customer\Model\Context::CONTEXT_AUTH)`. Usa handles separados cuando el layout estructural es diferente (más o menos blocks), no solo el template.

</details>

### Ejercicio 2 — Handle custom desde controller para posts premium

El controller de vista de post (`Blog\Controller\Post\View`) debe agregar el handle `blog_post_view_premium` si el post tiene `is_premium = true`. Escribe el controller y el XML que agrega un bloque de paywall solo para ese handle.

<details>
<summary>Ver solución</summary>

```php
// Controller/Post/View.php
public function execute(): \Magento\Framework\View\Result\Page
{
    $resultPage = $this->resultPageFactory->create();
    $postId = (int) $this->getRequest()->getParam('id');

    try {
        $post = $this->postRepository->getById($postId);
    } catch (\Magento\Framework\Exception\NoSuchEntityException $e) {
        return $this->resultRedirectFactory->create()->setPath('noroute');
    }

    // Registrar el post para el Block
    $this->registry->register('current_post', $post);

    // Handle condicional
    if ($post->getData('is_premium')) {
        $resultPage->addHandle('blog_post_view_premium');
    }

    $resultPage->getConfig()->getTitle()->set($post->getTitle());
    return $resultPage;
}
```

```xml
<!-- view/frontend/layout/blog_post_view_premium.xml -->
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">
    <body>
        <!-- Ocultar el contenido principal -->
        <referenceBlock name="blog.post.content" display="false"/>

        <!-- Mostrar el paywall -->
        <referenceContainer name="content">
            <block class="MiVendor\Blog\Block\Post\Paywall"
                   name="blog.post.paywall"
                   template="MiVendor_Blog::post/paywall.phtml"
                   after="blog.post.view"/>
        </referenceContainer>
    </body>
</page>
```

**Por qué `display="false"` en vez de `remove="true"`**: Con `display="false"` el block sigue existiendo — puedes mostrarlo desde JS si el usuario paga, sin recargar la página.

</details>
