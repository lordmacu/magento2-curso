# 7.1 — Request Routing: routes.xml y Front Controllers

> **Objetivo**: Entender cómo Magento conecta una URL con código PHP — el sistema de routing es más explícito que Laravel pero sigue el mismo concepto de mapear rutas a acciones.
> **Estado**: ⬜ Pendiente
> **Prerequisito**: [6.5 — Plugin vs Observer vs Preference](6.5-plugin-vs-observer.md)

---

## Comparación con Laravel

🔄 **Laravel**: defines rutas en `routes/web.php` con closures o métodos de controller.

```php
// Laravel
Route::get('/blog/{id}', [PostController::class, 'show']);
```

**Magento**: las rutas se declaran en XML y cada acción es una clase PHP separada.

```xml
<!-- Magento: routes.xml declara el prefijo de la ruta -->
<!-- La URL /blog/post/view se mapea a Controller/Post/View.php -->
```

La diferencia conceptual: en Magento **no hay un archivo central de rutas**. Cada módulo declara su propio prefijo en `routes.xml` y el resto del path lo determinan las carpetas del Controller.

---

## Anatomía de una URL en Magento

```
http://localhost:8181 / blog / post / view / id / 5
                        │      │      │      └─ parámetros (key/value)
                        │      │      └─ action (nombre del archivo PHP)
                        │      └─ controller (nombre de la carpeta)
                        └─ frontName (declarado en routes.xml)
```

```
URL: /blog/post/view/id/5
→ frontName: blog
→ Controller folder: Post/
→ Action class: View.php  (Controller/Post/View.php)
→ Parámetros: id=5

URL: /blog/index/index  (= /blog/)
→ frontName: blog
→ Controller folder: Index/
→ Action class: Index.php (el default)
```

---

## routes.xml — declarar el frontName

```xml
<?xml version="1.0"?>
<!-- app/code/MiVendor/Blog/etc/frontend/routes.xml -->
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:framework:App/etc/routes.xsd">

    <router id="standard">
        <route id="mivendor_blog" frontName="blog">
            <module name="MiVendor_Blog"/>
        </route>
    </router>

</config>
```

- `router id="standard"` → el router del frontend. Para el admin es `admin`.
- `route id` → identificador único interno (nunca puede repetirse entre módulos)
- `frontName` → el primer segmento de la URL (`/blog/...`)
- `module name` → tu módulo que maneja estas rutas

---

## Estructura de Controllers

```
app/code/MiVendor/Blog/
└── Controller/
    ├── Index/
    │   └── Index.php     → /blog/index/index  (= /blog/)
    ├── Post/
    │   ├── View.php      → /blog/post/view
    │   ├── Create.php    → /blog/post/create
    │   └── Save.php      → /blog/post/save
    └── Category/
        └── List.php      → /blog/category/list
```

La URL se construye directamente desde la estructura de carpetas.

---

## El Front Controller — cómo funciona internamente

```
1. Request llega: GET /blog/post/view/id/5

2. FrontController pregunta a los Routers en orden:
   a. RoutesRouter (módulos) — busca en routes.xml
      → Encuentra: frontName="blog" → MiVendor_Blog

3. Construye el path del Controller:
   → Controller/Post/View.php

4. Instancia la clase vía DI y llama a execute()

5. El resultado (Page, JSON, Redirect...) se renderiza como respuesta HTTP
```

Los Routers se ejecutan en orden de prioridad:
```
1. CMS Router       → páginas y bloques CMS
2. Routes Router    → módulos con routes.xml
3. URL Rewrite      → URLs amigables del catálogo
4. Default Router   → 404
```

## El Controller mínimo

```php
<?php
// app/code/MiVendor/Blog/Controller/Post/View.php
namespace MiVendor\Blog\Controller\Post;

use Magento\Framework\App\Action\HttpGetActionInterface;
use Magento\Framework\View\Result\PageFactory;

class View implements HttpGetActionInterface
{
    public function __construct(
        private readonly PageFactory $pageFactory,
    ) {}

    public function execute(): \Magento\Framework\Controller\ResultInterface
    {
        return $this->pageFactory->create();
    }
}
```

**Puntos clave**:
- Implementa `HttpGetActionInterface` (o `HttpPostActionInterface` para POST)
- Un solo método `execute()`
- Devuelve un `ResultInterface` — nunca echo/print directamente

---

## Interfaces de método HTTP

```php
// Limitar el controller a un método HTTP específico:
use Magento\Framework\App\Action\HttpGetActionInterface;   // solo GET
use Magento\Framework\App\Action\HttpPostActionInterface;  // solo POST
use Magento\Framework\App\Action\HttpPutActionInterface;   // solo PUT
use Magento\Framework\App\Action\HttpDeleteActionInterface; // solo DELETE

// Si el método no coincide → Magento retorna 404 automáticamente
class Save implements HttpPostActionInterface { ... }
// GET /blog/post/save → 404 automático
// POST /blog/post/save → ejecuta
```

## Rutas del área Admin

Para el admin, el `router id` es diferente y la URL incluye el `frontName` del admin:

```xml
<?xml version="1.0"?>
<!-- app/code/MiVendor/Blog/etc/adminhtml/routes.xml -->
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:framework:App/etc/routes.xsd">

    <router id="admin">
        <route id="mivendor_blog_admin" frontName="blog">
            <module name="MiVendor_Blog"/>
        </route>
    </router>

</config>
```

```
URL del admin: /admin_r0hd7e1/blog/post/index
                │              │    │    └─ action
                │              │    └─ controller folder
                │              └─ frontName del módulo
                └─ frontName del admin (definido en env.php)
```

---

## Múltiples módulos con el mismo frontName

Puedes hacer que tu módulo "extienda" las rutas de otro:

```xml
<!-- MiVendor_BlogSeo también responde bajo /blog/ -->
<router id="standard">
    <route id="mivendor_blog" frontName="blog">
        <module name="MiVendor_BlogSeo" before="MiVendor_Blog"/>
    </route>
</router>
```

`before` / `after` controlan el orden de búsqueda de Controllers cuando dos módulos comparten el mismo `frontName`.

## Verificar rutas registradas

```bash
# Verificar que tu ruta existe y está activa
php bin/magento dev:router:match /blog/post/view

# Si el módulo está habilitado, verás:
# MiVendor\Blog\Controller\Post\View

# Buscar todos los routes.xml de tus módulos:
find app/code -name "routes.xml" | xargs grep -l "frontName"

# Ver el frontName del admin:
grep "frontName" app/etc/env.php
# → 'frontName' => 'admin_r0hd7e1'
```

## Resumen

```
URL: /{frontName}/{controller}/{action}/{params}
          │            │           │
          │            │           └─ Clase PHP en Controller/{Controller}/{Action}.php
          │            └─ Carpeta dentro de Controller/
          └─ Declarado en etc/frontend/routes.xml

routes.xml del frontend → router id="standard"
routes.xml del admin    → router id="admin"

Cada Controller:
  - Implementa HttpGetActionInterface o HttpPostActionInterface
  - Tiene un solo método execute()
  - Devuelve un ResultInterface (Page, JSON, Redirect, Raw...)
```

## Ejercicios

### Ejercicio 1 — Crear las rutas para un módulo Blog

Tienes el módulo `MiVendor_Blog`. Crea el `routes.xml` correcto para que las siguientes URLs funcionen:

```
GET  /blog/              → lista de posts
GET  /blog/post/view     → ver un post
POST /blog/post/save     → guardar un post
GET  /blog/category/list → lista de categorías
```

<details>
<summary>Ver solución</summary>

```xml
<?xml version="1.0"?>
<!-- app/code/MiVendor/Blog/etc/frontend/routes.xml -->
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:framework:App/etc/routes.xsd">
    <router id="standard">
        <route id="mivendor_blog" frontName="blog">
            <module name="MiVendor_Blog"/>
        </route>
    </router>
</config>
```

La estructura de Controllers resultante:

```
Controller/
├── Index/
│   └── Index.php        → GET /blog/ (y /blog/index/index)
├── Post/
│   ├── View.php         → GET /blog/post/view
│   └── Save.php         → POST /blog/post/save
└── Category/
    └── ListAction.php   → GET /blog/category/list
```

**Nota**: `List` es palabra reservada en PHP — usa `ListAction` como nombre de clase pero el archivo puede llamarse `ListAction.php`. La URL sigue siendo `/blog/category/list`.

```bash
php bin/magento cache:flush
# Verificar:
curl -o /dev/null -w "%{http_code}" http://localhost:8181/blog/
# → 200 (o 404 si no has creado el Controller aún)
```

</details>

### Ejercicio 2 — Interpretar una URL del admin

Dada esta URL de admin: `http://localhost:8181/admin_xyz123/catalog/product/index`

Determina: ¿qué `frontName` usa el módulo?, ¿en qué archivo PHP está el Controller?, ¿qué módulo lo maneja?

<details>
<summary>Ver solución</summary>

```
URL: /admin_xyz123/catalog/product/index
      │             │        │       └─ Action → Index.php
      │             │        └─ Controller folder → Product/
      │             └─ frontName del módulo → "catalog"
      └─ frontName del admin (en env.php: admin_xyz123)
```

```bash
# Encontrar el módulo que usa frontName="catalog" en el admin:
grep -r 'frontName="catalog"' vendor/magento/ --include="routes.xml"
# → vendor/magento/module-catalog/etc/adminhtml/routes.xml
#   <route id="catalog" frontName="catalog">
#       <module name="Magento_Catalog"/>

# El Controller está en:
# vendor/magento/module-catalog/Controller/Adminhtml/Product/Index.php
ls vendor/magento/module-catalog/Controller/Adminhtml/Product/Index.php
```

**Patrón importante**: en el admin, los Controllers van en `Controller/Adminhtml/` por convención — no es un requisito técnico pero es la estructura estándar de Magento.

</details>
