## Composer en Magento vs Laravel

🔄 **Laravel**: `composer.json` es simple — unas pocas dependencias, autoload PSR-4 hacia `app/`.

En Magento, Composer **es** el sistema de módulos. Cada módulo de terceros, cada tema, cada extensión del core llega vía Composer. Un proyecto real puede tener 200+ paquetes.

```bash
# Ver cuántos paquetes hay instalados
composer show | wc -l
# → 250+ en una instalación estándar
```

## Estructura del composer.json de Magento

```json
{
    "name": "magento/project-community-edition",
    "description": "eCommerce Platform for Growth",
    "type": "project",
    "require": {
        "php": "~8.1.0||~8.2.0",
        "magento/product-community-edition": "2.4.7",

        // Módulos de terceros que instalaste:
        "vendor/modulo-nombre": "^1.0",
        "amasty/module-special-promo": "^2.5"
    },
    "require-dev": {
        "phpunit/phpunit": "^9.5",
        "phpstan/phpstan": "^1.0"
    },
    "autoload": {
        "psr-4": {
            "Magento\\Framework\\": "lib/internal/Magento/Framework/",
            "Magento\\Setup\\":     "setup/src/Magento/Setup/",
            "Magento\\":           "app/code/Magento/"
        },
        "psr-0": {
            "": "app/code/"    // ← Carga TODOS los módulos en app/code/
        },
        "files": [
            "app/etc/NonComposerComponentRegistration.php"  // registra módulos locales
        ]
    },
    "repositories": [
        {
            "type": "composer",
            "url": "https://repo.magento.com/"   // El repo oficial de Adobe/Magento
        }
    ],
    "config": {
        "preferred-install": "dist",
        "sort-packages": true,
        "allow-plugins": {
            "magento/magento-composer-installer": true,
            "magento/inventory-composer-installer": true,
            "laminas/laminas-dependency-plugin": true
        }
    },
    "extra": {
        "magento-force-deploy": true
    }
}
```

## Tipos de paquetes Composer en Magento

Magento define sus propios tipos de paquete — Composer los trata diferente según el tipo:

```
magento2-module    → Módulo PHP (va a app/code/ o vendor/)
magento2-theme     → Tema (va a app/design/)
magento2-language  → Paquete de idioma (va a app/i18n/)
magento2-library   → Librería sin módulo (va a lib/)
magento2-component → Componente raíz (archivos en la raíz del proyecto)
project            → El proyecto en sí (el composer.json principal)
```

## Instalar módulos de terceros

### Desde el repositorio oficial de Magento (repo.magento.com)

```bash
# Autenticarse con tus keys de Magento Marketplace
composer config http-basic.repo.magento.com TU_PUBLIC_KEY TU_PRIVATE_KEY

# Instalar un módulo
composer require vendor/nombre-modulo

# Luego siempre:
php bin/magento module:enable Vendor_NombreModulo
php bin/magento setup:upgrade
php bin/magento cache:flush
```

### Desde Packagist (módulos open source)

```bash
composer require algolia/algoliasearch-magento-2
php bin/magento module:enable Algolia_AlgoliaSearch
php bin/magento setup:upgrade
php bin/magento cache:flush
```

### Desde GitHub (módulo sin publicar en Packagist)

```json
// composer.json — agregar el repo antes de instalarlo
{
    "repositories": [
        {
            "type": "vcs",
            "url": "https://github.com/usuario/magento2-mi-modulo"
        }
    ]
}
```

```bash
composer require usuario/magento2-mi-modulo:dev-main
```

## Módulos propios: ¿vendor/ o app/code/?

Esta es una decisión de arquitectura:

| | `app/code/` | `vendor/` (vía Composer) |
|---|---|---|
| **Cuándo usarlo** | Módulos del proyecto, customizaciones | Módulos reutilizables entre proyectos |
| **Versionado** | Se sube a git directamente | Se referencia en `composer.json` |
| **Registro** | `app/etc/NonComposerComponentRegistration.php` | `registration.php` del módulo |
| **Deploy** | Viene con el repo | `composer install` |

**Regla práctica**:
- Customizaciones del cliente → `app/code/`
- Módulos que reutilizas en varios proyectos → paquete Composer privado

## Crear un módulo como paquete Composer privado

### 1. El `composer.json` del módulo

```json
// Tu módulo: packages/mivendor-mimodulo/composer.json
{
    "name": "mivendor/magento2-mimodulo",
    "description": "Mi módulo reutilizable",
    "type": "magento2-module",
    "version": "1.0.0",
    "require": {
        "php": "^8.1",
        "magento/framework": "*"
    },
    "autoload": {
        "files": ["registration.php"],
        "psr-4": {
            "MiVendor\\MiModulo\\": ""
        }
    }
}
```

### 2. Repositorio privado con Satis o Packagist privado

```bash
# Opción 1: Satis (self-hosted)
composer global require composer/satis
satis build satis.json public/

# Opción 2: repo VCS en composer.json del proyecto
# (más simple para equipos pequeños)
```

### 3. Referenciarlo desde el proyecto

```json
{
    "repositories": [
        {
            "type": "path",
            "url": "./packages/mivendor-mimodulo"   // path local
        }
    ],
    "require": {
        "mivendor/magento2-mimodulo": "*"
    }
}
```

## Comandos Composer que más usarás

```bash
# Instalar todas las dependencias (en un proyecto nuevo o tras un git clone)
composer install

# Instalar sin dev dependencies (en producción)
composer install --no-dev --optimize-autoloader

# Agregar un módulo nuevo
composer require vendor/package

# Actualizar un módulo específico
composer update vendor/package --with-dependencies

# Ver si un módulo tiene actualizaciones disponibles
composer outdated vendor/package

# Ver de dónde viene una clase (qué paquete la define)
composer show --all | grep "nombre-busqueda"

# Ver la ruta instalada de un paquete
composer show vendor/package

# Regenerar el autoloader (necesario tras mover archivos manualmente)
composer dump-autoload

# Ver por qué está instalado un paquete (qué lo requiere)
composer why vendor/package

# Ver conflictos de versiones
composer why-not vendor/package 2.0.0
```

## El autoloading en Magento

Magento usa dos mecanismos simultáneos:

### PSR-4 (vendor/ y lib/)
```
vendor/magento/module-catalog/  →  Magento\Catalog\
vendor/magento/framework/       →  Magento\Framework\
```

### PSR-0 (app/code/)
```
app/code/MiVendor/MiModulo/Model/Producto.php
→ clase: MiVendor\MiModulo\Model\Producto
```

El PSR-0 en `app/code/` es automático — no necesitas declarar nada en `composer.json` para que tus clases sean encontradas. Esto es posible por la línea:
```json
"psr-0": { "": "app/code/" }
```

## Magento Marketplace y las keys

```bash
# Las keys van en auth.json (NO subir a git):
# ~/.composer/auth.json  o  {proyecto}/auth.json

{
    "http-basic": {
        "repo.magento.com": {
            "username": "TU_PUBLIC_KEY",
            "password": "TU_PRIVATE_KEY"
        }
    }
}
```

```bash
# Agregar las keys vía CLI:
composer config --global http-basic.repo.magento.com PUBLIC_KEY PRIVATE_KEY

# Verificar que están configuradas:
composer config --global --list | grep repo.magento.com
```

⚠️ `auth.json` debe estar en `.gitignore`. Si lo subes, cualquiera puede instalar módulos pagados con tus credenciales.

## composer.lock — el archivo más importante

```bash
# composer.lock fija las versiones exactas de TODOS los paquetes
# Es como el package-lock.json de npm

# Siempre commitear composer.lock — garantiza el mismo entorno en todos los developers
git add composer.lock

# NUNCA correr esto en producción sin revisar el lock:
composer update   # actualiza todo — puede romper cosas

# En producción, siempre:
composer install  # usa el lock file, no actualiza nada
```

## Desinstalar un módulo

```bash
# 1. Deshabilitar el módulo
php bin/magento module:disable Vendor_Modulo

# 2. Aplicar la desinstalación (si el módulo tiene uninstall script)
php bin/magento module:uninstall Vendor_Modulo

# 3. Quitar el paquete de Composer
composer remove vendor/package-name

# 4. Limpiar
php bin/magento setup:upgrade
php bin/magento cache:flush
```

## Resumen

```
composer install          → Siempre tras git clone / en producción
composer require          → Instalar módulo nuevo
composer dump-autoload    → Regenerar autoloader tras mover archivos
composer why              → Entender dependencias

app/code/    → Código del proyecto (va a git)
vendor/      → Dependencias (no va a git, se regenera con composer install)
auth.json    → Keys privadas (NUNCA a git)
composer.lock → Versiones fijas (SIEMPRE a git)
```
